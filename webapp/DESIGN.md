# human-count 控制台 · 界面设计方案（v2.0）

> 风格方向：**监控台 / Mission Control** · 深色为主 + 完整浅色主题 · 离线可用（无 Web Font / 无 CDN）
> 设计上下文见仓库根 `.impeccable.md`

---

## 一、设计目标与取舍

| 目标 | 做法 | 取舍 |
|---|---|---|
| **长时间盯屏不累** | 深色底不用纯黑（`oklch(12.5%)`），亮度对比控制在 10:1 内；浅色主题同步提供 | 放弃"极致黑"的视觉冲击 |
| **信息密度高但可扫读** | 4pt 间距体系 + 三级文字（正文/次要/标注）+ 等宽数字对齐；面板标题行固定 32px | 字号不做"大字报" |
| **状态一眼可辨** | 颜色**只**编码状态：强调青(行动) / 琥珀(选中·警告) / 品红(危险) / 青绿(正常) | 放弃装饰性用色 |
| **移动端真能用** | <768px 换交互模型：单机位 + 机位切换条 + 底部标签栏，而非压缩桌面版 | 放弃"手机上也能 6 宫格" |
| **离线确定可用** | 系统字体栈 + `color-mix()` / `oklch()`（现代浏览器原生支持） | 放弃品牌定制字体 |

## 二、色彩系统

使用 **OKLCH**（感知均匀）。中性色统一带 `hue 245` 冷调（chroma 0.006–0.022），
让界面与强调色同源，避免"死灰"。

### 语义 Token（双主题，只重定义语义层）

| Token | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg` | `oklch(12.5% .012 245)` | `oklch(97.2% .006 245)` | 应用底色 |
| `--surface-1` | `oklch(16% .014 245)` | `oklch(99.4% .003 245)` | 面板 |
| `--surface-2` | `oklch(20% .016 245)` | `oklch(95.6% .008 245)` | 面板内嵌 / 悬停 |
| `--surface-3` | `oklch(24.5% .018 245)` | `oklch(92.4% .01 245)` | 抬升 / 激活 |
| `--line` | `oklch(28.5% .018 245)` | `oklch(89.5% .012 245)` | 分隔线 / 边框 |
| `--line-2` | `oklch(37% .022 245)` | `oklch(80% .016 245)` | 强调边框 |
| `--fg` | `oklch(93.5% .008 245)` | `oklch(24% .018 245)` | 主文本 |
| `--fg-2` | `oklch(74% .013 245)` | `oklch(46% .016 245)` | 次要文本 |
| `--fg-3` | `oklch(58% .015 245)` | `oklch(60% .014 245)` | 标注 / 占位 |
| `--accent` | `oklch(79% .132 195)` | `oklch(52% .13 205)` | 主强调：行动、链接、进度 |
| `--accent-ink` | `oklch(18% .04 195)` | `oklch(99% .01 205)` | 强调色上的文字 |
| `--signal` | `oklch(83% .148 80)` | `oklch(60% .14 65)` | 选中 · 活动 · 聚焦数据 |
| `--ok` | `oklch(78% .15 155)` | `oklch(50% .13 155)` | 正常 / 保留 |
| `--warn` | `oklch(81% .145 80)` | `oklch(60% .14 68)` | 未决 / 掩膜 |
| `--danger` | `oklch(70% .19 12)` | `oklch(53% .19 20)` | 倒影 / 危险操作 |
| `--entity` | `oklch(73% .13 305)` | `oklch(52% .15 305)` | 同机实体编码 |

**深度表达**：深色主题用**更亮的表面**表达层级（不用阴影）；浅色主题用极轻阴影 + 边框。
阴影统一 `--shadow-1/2/3`，强度刻意压低（看不清才对）。

**60-30-10**：60% 中性底 / 30% 文本与边框 / 10% 强调色。强调色**只在**行动与选中出现。

## 三、字体与层级

**离线约束** → 系统字体栈：

```
--font-ui:   "Segoe UI Variable Text", "Segoe UI", -apple-system, "PingFang SC",
             "HarmonyOS Sans SC", "Microsoft YaHei UI", system-ui, sans-serif
--font-mono: ui-monospace, "JetBrains Mono", "Cascadia Mono", "SF Mono", Consolas, monospace
```

识别度来自**排版纪律**而非字体本身：

| Token | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `--text-2xs` | 10.5px | 1.25 | 600 | 微型大写标签（`letter-spacing:.08em`） |
| `--text-xs` | 11.5px | 1.35 | 500 | 元信息、字段名 |
| `--text-sm` | 12.5px | 1.45 | 400 | 表格、密集列表 |
| `--text-base` | 13.5px | 1.55 | 400 | 正文（**桌面**） |
| `--text-md` | 15px | 1.55 | 400 | 正文（**移动**，≥15px 保证可读） |
| `--text-lg` | 18px | 1.3 | 600 | 面板主数值 |
| `--text-xl` | 24px | 1.15 | 650 | 区块标题 / KPI |
| `--text-2xl` | 32px | 1.05 | 650 | 页面级指标 |

**数字全部 `font-variant-numeric: tabular-nums`**（时间、ID、指标、计数），保证纵向对齐与读数稳定。

## 四、间距与布局

4pt 基数，语义命名：

```
--sp-1:4  --sp-2:8  --sp-3:12  --sp-4:16  --sp-5:24  --sp-6:32  --sp-7:48
```

- 面板内边距：`--sp-3`（紧凑表格）/ `--sp-4`（常规）
- 面板间距：`--sp-3`；与页面边缘：`--sp-4`
- 用 `gap` 而非 margin 做兄弟间距（无 margin 塌陷）
- 面板标题行固定 **32px**，全站统一（扫读时的节拍）
- 圆角：`--r-xs:4 / --r-sm:6 / --r-md:9 / --r-lg:14 / --r-pill:999px`
- z-index 语义刻度：`--z-bar:50 --z-drawer:200 --z-modal:300 --z-toast:500 --z-tip:600`

## 五、响应式策略

**移动优先 + 内容驱动断点**（不是设备尺寸）：

| 断点 | 布局 |
|---|---|
| `< 768px` | 顶栏 46px（品牌 + 状态点 + 主题切换）· **底部标签栏 6 项** · 可视化 = 单机位 + 机位切换条 · 左右侧栏 → 全屏抽屉 · 工具条单行横滚（右缘渐隐） |
| `768 – 1023px` | 顶栏 50px 含导航（永不换行）· 单列主区 · 左右侧栏 → 抽屉（工具条按钮触发） |
| `1024 – 1439px` | 三栏紧凑：左 210 · 主区 · 右 288 |
| `≥ 1440px` | 三栏：左 232 · 主区 · 右 316 |

- 用 `@media (pointer: coarse)` 放大触控目标到 ≥44px，`(hover: none)` 下不依赖 hover 反馈
- 支持 `env(safe-area-inset-*)`（`viewport-fit=cover`）
- 面板内部用**容器查询** `@container` 自适应，不感知视口

## 六、动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 即时反馈（按下、开关、颜色） | 120ms | `--ease-out-quart` |
| 状态变化（悬停、浮层、面板展开） | 220ms | `--ease-out-quart` |
| 布局变化（抽屉、手风琴） | 320ms | `--ease-out-expo` |
| 进场（页面、抽屉内容） | 420ms | `--ease-out-expo` |

- 只动 `transform` / `opacity`（高度用 `grid-template-rows: 0fr → 1fr`）
- 禁用回弹/弹性曲线
- 全程尊重 `prefers-reduced-motion: reduce`（退化为纯淡入）

## 七、交互规范

- **六态齐备**：default / hover / focus-visible / active / disabled / loading
- **焦点环**：`outline: 2px solid var(--accent); outline-offset: 2px`，**永不移除**
- **触控目标 ≥44×44**（视觉可小，用 `::before` 扩大热区）
- **破坏性操作**：先执行 + 提供撤销（`重置聚类`、`删除整簇` 用琥珀色二次确认区）
- **空状态有教育性**：说明"这里会出现什么 + 怎么触发它"
- **抽屉/浮层**用 `position: fixed` + 顶层层级，避免 `overflow:hidden` 裁剪
- **键盘**：`/` 聚焦搜索、`空格` 播放/暂停、`←/→` 逐帧、`1-6` 切换机位、`Esc` 关抽屉

### 8.1 轨迹同人复核（2026-11-10 新增）

同一机位、不同时段的**两段轨迹**并排，判定「是不是同一个人」。与「跨机候选对」的分工：
后者问跨机匹配，这里问**同机跨时段的重识别**，用来给没有身份真值的卷（v2559 / v2526）补真值。

- 行式布局：每行 = 一条轨（左侧 150px 全景缩略图 + 右侧 3 帧裁图横向条带）。裁图**已内嵌红框**标出目标，
  因为俯视工位密集，一条轨的局部裁图里常有 3–5 个邻座。
- **默认盲标**：外观余弦 / 位置距离 / 是否同簇都收在「判据」开关后面，不点不显示。
- 类别 A/B/C/D 构成两组实验：A 测精度、B 测召回；**C（位置近）vs D（位置远）是同一外观区间的对照组**，
  同人率之差才是位置先验的证据。分类统计放在 `details` 折叠区并标注"会泄露假设，标完再看"。
- 键盘 `1` 同人 / `2` 不同人 / `3` 不确定、`J`/`K` 切换；判定后自动前进，「清除判定」留在原地。
- 数据：`data/trackpair/pairs.json` + `data/trackpair/strips/`；判定落 `data/trackpair_labels.json`（独立文件，不动 `labels.json`）。
  抽图脚本 `tmp/label/build_label.py`（**建议在远程跑**，本地 16 GB 内存易 OOM）。

### 8.2 簇纯度核验（2026-11-10 新增）

「这个**簇**里混没混别的人」——与 8.1 的问题不同：那里是两两比，这里是以簇为单位量**误合并**。
用在 v2545（走廊机位，无任何身份真值）：0.78 配置下只有 15 个单卷簇覆盖 129 条轨，
**15 个判断就能覆盖全部轨**，而 pairwise 要几百对且给不出纯度。

- 一簇一页：成员按时间排序，每条轨一排 3 帧裁图（等分宽度、`object-fit: cover`，
  因为视线远近让裁图宽窄差很大，按原比例排会把行撑歪）。
- **单击缩略图循环**：主体 → 外人 → 看不清 → 主体。不做模式切换，手不离开图。
- 底部动作条：`1` 整簇同一人 / `2` 提交（外人 N）/ `3` 不确定 / `4` 明显多人。
- 语义分层（决定了指标怎么算）：
  - `pure` 纯度 1；`mixed` 按「每个外人各是一个独立身份」保守计，纯度 (n−k)/n；
  - **`看不清` 的轨从分母剔除**——走廊 19% 的轨框高 < 80 px，把剪影算成「不同人」会系统性压低纯度；
  - **`明显多人` 不计入纯度**，只记数量。试过按 k=1 保守计入，46 轨的簇标了「明显多人」纯度仍 0.978——
    那不是保守，是自欺。宁可缺一条，也不虚高。
- 数据：`data/clusterver/items.json` + `data/clusterver/strips/`（每条轨 3 帧，红框）
  + 判定 `data/clusterver_labels.json`；抽图脚本 `tmp/label/build_cluster_ver.py`（远程跑）。
  ★ 取帧三条规则（都是踩出来的）：避开轨迹首尾 15%（首帧常是「人还没进画面」的空框）、
  只在**框偏大**的帧里挑（远景只有剪影）、**置信度不低于本轨中位**（v2545 簇内 24% 的轨中位置信度 < 0.30）。

### 8.3 身份选择器（2026-11-13 新增）

把已验证的运行时机制搬进控制台：**形态条件化模板**（按 `exp(-|ln(h_i/h_q)|/σ)` 加权，
σ=0.6）+ **人脸触发的实时池**（池不进聚类、不改簇结构，只改选择器能看到什么模板）。

- 三栏并列而不给单一融合分：**仅历史库 S0 / 库+池 S1 / 仅池 S2**。融合分把「库有模板」
  和「池有样本」压成一个数，看不出增益来自哪一侧；本包的诊断价值恰在这三栏的差。
- 候选表必须显示**模板条数**（`4 库 / 1 池`）：分数 0.99 若只由 1 条模板给出，它和由 4 条
  加权给出的 0.99 不是同一个东西。
- **留一是默认且不可关**：查询轨从模板与池里都剔除。不剔的话查询轨在自己身份的模板里，
  top-1 恒等于自己。单轨实体留一后模板为空，按口径**不进候选**（不是判成「不是这个人」）。
- 形态解释面板列出模板构成（哪几条、框高多少、权重多少、与查询的余弦），让「为什么是这个分」可查。
- 锚定入口有两处：**人脸卡**（人工判定过的 `g####`，44/45 落在 ReID 库里）与候选行的「锚入」。
  锚定时如果该轨自身实体 ≠ 目标实体，界面用 `--warn` 明确写出「轨自身实体 305-E025」——
  人工改聚类是允许的，但静默错配不允许。
- 质量门（默认框高 ≥60 px）先拦一道：小框的外观特征不可靠，写进池等于污染模板。
- 包内自评面板给出四种口径（留一/前后半 × 真实池/池上限），但**同名标注证据边界**：
  实体来自聚类不是人工真值，池增益的证据在 8 段（56.4→68.2→79.3），不在这个 10 分钟包里。
- **缩略图（2026-11-19 新增，替换此前「不取缩略图」的做法）**：库与渲染轨的 `tid` 确实不同源
  （305 只有 3/106 同号），但**几何是同一组坐标**——按「时刻 + 位置」把库轨匹配到渲染轨，
  实测 538/539 命中、归一化距离中位 0.000。匹配上就用该轨在本轨时间窗内**框最大且不贴边**
  的那一帧、按真实框裁；匹配不上退回库内 `(u,v,h_med,f_rep)`。
  服务端 `GET /api/selector/thumb?cam=&tid=&w=`（缓存 `data/reid/thumbs/{cam}_{tid}.jpg`，宽 448），
  身份列表 / 查询轨条 / 候选表 / 模板构成 / 实时池五处共用，点图放大（`⤢` 或直接点）。
  ★ 裁图固定按「高度 × 0.5」取宽：坐姿/桌面场景的检测框常是方的（1:1），照框裁会得到
  「一张桌子 + 一个小人」，缩略图里认不出人。
  ★ 不用 `/api/track/thumb`（按 tid 查 `tracks/{cam}.json`）——那会裁到别人。

### 8.5 倒影 / 源复核（2026-11-19 调整）

- **「掩膜区」不再是这个页签的类别**：列表只收 `reflection` 与 `source`，筛选只有「倒影 / 源 / 全部」。
  理由：两者判据不同——倒影看**镜像运动学**（`v_R ≈ 2·v_脚 − v_源中心`，人往哪走、反光往哪走），
  掩膜区看的是**区域**（哪块玻璃/地面会反光）。混在一个队列里，本包 281 条掩膜轨会把 28 条真倒影淹掉。
- 掩膜区仍在**独立页签「玻璃区域圈选」**里维护（它是渲染遮罩的来源，不是身份判定）。
  两处数据不共享：这里改判定不会改 `masks.json`，反之亦然。

### 8.6 科研工作台 / 实验卡（2026-11-24 新增，`#/workbench`）

补的是**流程载体**而不是新算法：台账里 `experiment` 表早有记录（4 条 `ops_ingest_train` 自动汇总的
训练变体），但控制台没有任何入口；研究报告 §09 要求的「实验卡 + 四关 + 审批记录」也没有落点。

- 版式：左 240–300 列表（`id` / 标题 / 状态 / A–D 四个关口点 / 待确认标记，待确认置顶）/ 右详情。
  详情自上而下＝问题与假设 → 基线（不改）vs 候选（单变量）→ 主指标·同时报·失败条件 → 预算与风险
  → 四关 → 人机分工 + 七件套 → 运行与审批记录。≤1023px 单列。
- **关口 append-only**：每个关口可反复记录，最新一条即当前决定；`退回 / 暂缓` **必须写理由**，
  `同意` 也建议写范围——审批记录本身是交付物。
- **联动而不二次点击**：A 同意 → 状态转「已批准」、A 退回 → 「需修订」、D 同意 → 「已采纳」、
  D 退回 → 「需修订」。其余流转（方案/编码 → 自动测试 → 运行 → 独立评测 → 自动复核 → 待成果验收）
  由人用下拉推进；**「已采纳」前置 D=同意**，堵住「没验收就上线」。
- **只种计划、不种成绩**：五张卡来自 11-23 报告 §10，数值指标一律为空（截至 11-23 均无项目实测结果）。
  七件套勾选只是**证据索引**，勾上不等于验收通过；运行挂载只校验 `run_id` 存在，不评价它。
- 与 `experiment` 表**并存不互写**：后者由 `ops_ingest_train` 自动汇总，前者是人立项的卡；
  自动流程不碰 `exp_card`，人工流程不改 `experiment`，避免再次出现「自动汇总盖掉人工结论」。

---

### 8.7 流程层：从实验卡贯穿到交付物（2026-11-24 新增，K0）

8.6 的实验卡是**流程起点**，但当时没有任何东西从卡里长出来——卡上写着假设，证据在论文里，
两者互不认识。8.7 补的是这条竖线，也是工作台的真正定位：**它服务「任何一次实证研究」，
human-count 只是第一个 study**。

七环节：立题 `study` → 立卡 `exp_card`+`exp_gate` → 备料 `asset_version`/`label_set`/`code_version`
→ 定协议 `eval_protocol` → 执行 `eval_run` → 立论 `claim`/`claim_anchor` → 交付 `deliverable`/`deliverable_ref`。

四条守恒（与领域无关，换场景只有取值变化）：

| 关系 | 要求 | 当前实测 |
|---|---|---|
| C1 | 每条 claim 能回答「属于哪张卡」 | **0 / 238（未达成，卡与证据断链）** |
| C2 | 每条 claim 有可执行 run 或已裁定 | 101 / 238 |
| C3 | 每次 run 有输入版本哈希 | 100 / 101 |
| C4 | 每个交付物能说出引用了多少、核了多少 | r2 引用 91、已裁定 90 |

诊断报告由 `tools/ledger_flow.py` 生成（`ops/reports/ledger/FLOW.md`），只读。
**C1 是当前唯一未达成的环节**：这说明最初「实验卡形同虚设」的问题并没有被 8.6 解决，
只是从「没有卡」变成「有卡但没接上」。补法是人工归属，不自动写。

界面上的落点（K2，未做）：`#/workbench` 卡片详情增加「证据链」页签，
五列＝实验卡 → 资产 → run → claim → 交付物，任一端可反向钻取；
未挂卡的 claim 单列一个「待归属」入口，按出处容器分组（不是按时间）。
