# 320 机位为什么答得少：25 条卡在分数，不在决策规则

> 2026-10-23｜前置分析（不引入新数据），对应 V0.4 里程碑 M2 的「320 未答拆解」
> 复现：`PY tools/diag_320_unanswered.py`（复用 `diag_320_gallery.build_variant`，与 `A_baseline` 同口径：生产图库、**无 veto**、K=111、θ=1.85）
> 产物：`results/diag_320_unanswered.{csv,json}`；分母链见 `docs/loss-decomposition-2026-10-23.md`

## 0. 结论

1. **320 不是「答得不一致」，是「分数根本到不了」。** 31 条可回答查询里 25 条（80.6%）两片都不过 θ；「两片异簇」在 320 只有 1 条。所以这不是多片投票能修的问题。
2. **调阈值救不回来。** 320 全机位只有 **3 条**查询的 top-1 分数落在 θ 下方 0.25 内；把 θ 降 0.25 最多多答 3 条，而 320 的 top-1 命中率只有 23.8%（5/21），大概率把「拒答」换成「答错」。
3. **不设阈值的天花板是 5 条。** 320 的 31 条可回答查询里，两片 argmax 簇都有身份的 21 条，其中判对 5 条——即 **16.1%**；其余三机位是 61.8%（323）到 82.2%（305）。**这是机位信息量的问题，不是决策规则的问题。**
4. **建议**：把 320 从「精度不降的前提下多答对」里剔除，改报「在场人数/计数误差」，M2 的分机位校准不对 320 生效。

读法：`top-1 命中 @可回答` 是「假设完全不用阈值、直接取两片一致的 argmax，能对多少」——它的上限值就是该机位的结构性天花板。320 的 16.1% 比 305 低 5 倍。

## 2. 31 条可回答查询的归因（互斥）

| 归因 | 条数 | 占比 |
|---|---:|---:|
| A 分数到不了 θ（两片都不过） | 25 | 80.6% |
| B 过阈值但两片异簇 | 0 | 0% |
| C 过阈值但候选簇无身份 | 0 | 0% |
| D 答对 | 5 | 16.1% |
| E 过阈值、候选有身份但答错 | 1 | 3.2% |

B 和 C 都是 0，意味着「多片投票」「候选拒识」这两类改法在 320 上**没有作用面**。

## 3. 为什么：四个结构性原因（按证据强度排序）

**① 320 的查询与图库不是同一个「视角」。** 320 是鱼眼俯视吊装，查询里 **34/40 = 85% 是 head 型**（305 为 57%、323 为 48%），框宽高比中位 1.26（近方形），即只拍到头顶或肩部以上；图库侧 257 条已标成员里 body 型占 39%。身份信息主要长在躯干和衣着上，头顶视图把它裁掉了。

**② 图库侧身份太少。** 320 只有 **33 条**轨迹过 6 帧门槛（579 的 5.7%），而查询侧承诺 31 条可回答——图库与查询的规模严重不对称。其训练段 `320_train_514` 空帧率 90.5%（0.11 人/帧），本来就采不到人。

**③ 分数分布整体下移，不是个别失败。** 320 的 top-1 分数中位 1.20，305 是 4.15；320 的 p90 = 2.76，仅略高于 θ。这说明是系统性域偏移（domain shift），不是阈值选错。

**④ 换图库段已被证否，排除「段选错了」这个解释。** `docs/diag-320-gallery-2026-10-20.md`：固定分母 n=108，把 320 图库段换成有人流的新段，`add` 变体 −6 条（−5.5pp）、`repl` 持平、`repl_drop` 持平。换段救不了，说明瓶颈不是素材时段。

## 4. 一条被瀑布掩盖的错误

320 唯一一条「接受且真值不在图库」的查询是 **`320_test_518#825`（真值 male23，head 框）**。
它被 196 可回答集排除，所以瀑布里 320 的答错是 0、精度 1.000。写论文时必须显式交代这一条，否则「320 精度 100%」会被读成该机位可靠。（详见损失分解 §5(1)）

## 5. 对 M2 验收门槛的修改建议

原文：M2 =「精度 ≥ 0.95 下 C/229 显著提升；320 未答原因得到量化」。

建议改为：

- **320 未答原因已量化**（本文即交付），结论是结构性不可答，不作为 M2 的增益来源；
- M2 的增益目标限定在 **305 / 318 / 323**，并同时报「320 应答率」作为不改坏的证据；
- M2 的 C/229 增益预期应按「查询多片投票的硬上限 = +8 条」设定（见损失分解表 3），而不是「显著提升」这种无上界的表述；
- 若坚持让 320 参与身份回答，则必须先做**分机位特征归一化**（相机级去偏），并在 320 上单独报精度——按当前 23.8% 的 top-1 命中率，它会把总体精度拉到 0.90 以下。

## 6. 限制与未复算项

- 「320 head 框 top-1 17.4%（4/23）」「h/w 1.26」「图库 33 条 / 空帧 90.5%」引自 10-20 的生产配置（veto 0.30、K=100）分析，本文未复算；本文全部数字来自本次 K=111 无 veto 的一次运行，两者方向一致（320 最差且差距是数量级），但绝对值不可混用。
- top-1 判据是「两片 argmax 同身份且等于真值」，比生产口径更严（生产只要求 accept_a/accept_b 同时过阈值并同簇）；因此表 1 的「@可回答」不能与生产精度直接对比。
