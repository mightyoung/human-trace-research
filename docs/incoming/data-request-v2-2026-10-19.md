## 0. 四条总原则

1. **两层真值分开标，互不引用。** 图库层只回答"这个图库成员是谁"，查询层只回答"这条查询是谁"。标查询时不看它被分到哪个簇、也不看簇是否纯；标图库时不看任何测试查询。
2. **簇到身份的映射只由图库决定。** 一个簇的"身份"＝簇内图库成员的多数匿名身份（并列时记为"无主体"）。不得看了测试查询再选映射。
3. **先定规则，后看标签。** 最终输出函数、否决阈值、阈值扫描范围在看查询真值之前写进配置文件并提交（记 git commit 号）。看过真值后再改的，要在文中标为"开发数据上调参"。
4. **全部用匿名身份。** 每天一套编号（如 `P1012-001`），不记录姓名；第二天另起一套，不做跨天对应。

## 第二批：统一协议重跑（约 2–3 天）

### D7 实验配置清单

全部使用：机位感知基线图库、同一 229 条查询、D0 写定的最终输出函数、D4 的查询真值。每个配置都按 D2 格式导出逐查询结果。

| 组 | 配置 | 扫描范围 | 回答的问题 |
|---|---|---|---|
| A 查询拒识 | 只调 θ | 1.40–4.50，步长 0.05 | 普通查询拒识的前沿；补 θ<1.85 一侧 |
| B 簇否决·直接拒识 | 命中被否决簇即拒识，θ=1.85 | d_max 0.22–0.40，步长 0.01 | 单纯整簇拒识的效果 |
| C 簇否决·删簇重搜 | 删簇后在剩余簇中重新搜索，θ=1.85 | 同上 | 重分配贡献多少；90→87 的逐条转移 |
| D 跨机位边切开 | 若 mst_max 为跨机位边且 >0.15，在该边切开，保留机位子簇 | 切开阈值 0.15–0.30 | 能否保住簇 69、55 的正确标签 |
| E 簇否决 × θ | B/C 的最优几档 × θ 扫描 | θ 1.40–3.00 | 等覆盖、等错误预算下的比较 |
| F 评分层变体 | T-norm、T-norm+绝对余弦、AS-norm、竞争簇校正、每机位原型、1-NN 多原型、簇大小门 | 每个各自扫阈值 | 6a/6b 统一到同一基线 |
| G 消融 | 全局聚类 0.20 + 否决；机位感知但跨机位改成员级 complete-linkage | — | 污染来自哪个聚类环节 |

每个配置产出一行汇总（脚本生成，写入 `results/summary.csv`）：

| 列 | 说明 |
|---|---|
| `both_accept_rate` | 两片均接受率 |
| `ab_same_rate` | 两片一致率 |
| `final_output_rate` | 最终单一身份输出率 |
| `C`, `W`, `U` | 主口径的对、错、不明 |
| `precision` | C/(C+W) |
| `C_over_229` | C/229 |
| `merged_identities` | 辅口径：被合并的身份对数 |
| `fm_raw`, `fm_clean` | 原始 fm；剔除同人重复后的 fm（各带分子分母） |
| `added`, `dropped`, `relabeled` | 相对 baseline：新增、退出、改判的查询数及各自 C/W/U |

**统计**：对 precision、C、W 及相对 baseline 的差值，做按图库簇（或按匿名身份）重采样的配对 bootstrap（2000 次），给 95% 区间。脚本与随机种子一并提交。

**完成标准**：能画出图 2（A 组与 B/C 组的精度—覆盖曲线，F 组各点叠加）；能填表 6、表 9 的新口径版本。

### D8 人级计数（人工 2–3 天）

前提：D0 确认四机位查询片段时间同步。若不同步，先取一个四机位都覆盖的同步 15 分钟窗口。

**真值定义**：U_W ＝ 同步 15 分钟窗口内，至少在四个机位之一出现过的真实唯一人数。**从原始视频标注**，包含检测器漏掉的人，不能只在 229 条查询上标。

文件：`gt/window_persons.csv`

| 列 | 说明 |
|---|---|
| `window_id`, `t_start`, `t_end` | 窗口 |
| `person_id` | 匿名身份（与 D4 同一套） |
| `cams_seen` | 出现过的机位 |
| `detected` | 是否至少有一条检测轨迹覆盖到此人 |

系统侧需事先写定**未打 ID 轨迹的计数规则**，并分别报告三种：进入复核队列（不计入自动人数）、每条按新人计、丢弃。

每个配置（至少 baseline、veto、D 组最优）报告：每窗口人工人数与系统人数、MAE、有符号偏差、身份拆分数、身份合并数、待复核轨迹数与估计复核耗时（实测一次人工复核单条的平均用时）。

### D9 第二天复验（采集 1 天 + 计算 1 天）

- 新一天：上午建库、下午查询，机位与时长同 10-12；**不使用 10-12 的图库**。
- 跑之前冻结：D0 的全部规则、否决阈值（D7 选定的那一档）、θ 选择规则。冻结配置记 commit 号。
- 按 D1–D4 同样标注（可只标被接受的查询 + 关键簇，时间紧时）。
- 无论结果好坏都报告；若看过真值后调参，第二天改称开发数据。

### D10 公开数据受控实验（2–4 天）

- **权重**：先按 D0 核对 OSNet checkpoint。若训练用了 MSMT17 全部图像（`combineall=True`），就不能在 MSMT17 上做实验，改用未参与训练的数据集。
- **数据**：优先 MARS（自动检测与跟踪得到的轨迹，更接近本任务）；它与 Market-1501 同源，文中注明不算完全独立的现场复验。
- **构库**：用数据集自带的轨迹，不要按真实身份把图像拼成伪轨迹。按本文流程（机位内 + 跨机位质心合并）聚类。
- **困难污染**：除了自然产生的不纯簇，专门构造"外观相似身份"混入的不纯簇（按特征距离挑选），报告"不纯但直径小"的簇有多少、`d_max` 漏掉多少。
- **未知身份**：删掉某个身份的图库簇后，不要把其查询改记为"未知"再把拒识算成正确。
- **报告两种阈值**：直接沿用 0.30 的迁移结果；在该数据上重新校准的结果。
