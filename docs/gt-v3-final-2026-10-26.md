## 3 κ 主口径：为什么报 v2 而不是 v3

三个候选口径（`results/kappa_a3_by_layer*.json`）：

| 口径 | 图库 257 | 查询 100 | 合并 357 | 说明 |
|---|---|---|---|---|
| **v2：A1 复核前**（主报） | **0.937**［.904,.966］ | **0.924**［.861,.978］ | 0.934 | 双方各用自己词表、互不知情 |
| v3：A1 复核后 | 0.979［.958,.996］ | 1.000 | 0.985 | 含词表统一（16 条 shadow→no-human） |
| 留一法映射（v2） | 0.925［.888,.958］ | 0.902［.837,.956］ | 0.919 | 保守下界 |

选 v2 作主口径的理由：

1. **v3 的涨幅主要不是"更一致"。** A1 把 `shadow1/2/3` 统一成 `no-human` 后，A3 的 `shadow` 编号下多数派随之变 `no-human`，
   7 条查询分歧和 5 条图库措辞分歧自动消失，**而 A1 一条查询标签都没为此改**。报 v3 就必须同时解释词表，
   否则读者会以为判对率提高了 0.04。
2. **v2 是唯一"双方独立"的数字。** 复核发生在 A3 已看过分歧统计之后，且由 A1 单人完成，不是独立测量。
3. v3 仍然要报，只是报成"词表统一后的敏感性"，并写明机制（稿件 §4.1 第三段已写）。

可辩护区间不变：**图库 0.91–0.94、查询 0.90–0.92**。稿件报的是 v2 点估计 + bootstrap 区间 + 留一法下界，三层都在区间内。

复现命令（v2 需要 A1 的归档真值，`--a1-*` 参数为本次新增）：

```bash
PY tools/eval_kappa_a3_by_layer.py \
  --a1-gallery deliverable/data-request-v2/gt/gt_gallery_members_FILLED.v2.csv \
  --a1-query   deliverable/data-request-v2/gt/gt_query_gt_FILLED.v2.csv \
  --out        deliverable/data-request-v2/results/kappa_a3_by_layer.v2.json --loo
```

实测输出与稿件逐项一致：0.937［0.904, 0.966］、0.924［0.861, 0.978］、留一法 0.925［0.888, 0.958］。
