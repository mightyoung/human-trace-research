# 人脸这一半的计数：跨机位桥几乎不可用人脸

> 2026-11-10 · 承接 `mainline-step1-baseline-2026-11-10.md`（基线 thr 0.78）与交接桥计数（13/31）
> 数据：8 段人脸抽取 `face8/`（SCRFD-2.5G + w600k_mbf，1178 轨 / 77 条轨有可用脸 = 6.5%）
> 口径：原子簇 = thr 0.78；可用脸 = `usable≥1`（pd≥20 且 fw≥32 且 lap≥50 且 |yaw|≤0.35 且 0.25≤pitch≤0.95）
> 作用域：445 具名有嵌入轨（与步骤 1 一致）；桥 = Σ(该身份机位数−1) = 31

## 0. 结论先行

1. **49 个「身份×机位」组里，最大簇含可用人脸的有 11 个（22%）。** 覆盖面集中在 305/318。
2. **31 条所需桥里，两端最大簇都有可用人脸的是 0 条**；即使放宽到「任一侧另有一个带脸簇」也只有 **1 条**。
   → **人脸不能当作跨机位桥的机制**，与交接桥不是互补关系，是几乎不相交。
3. 交接可覆盖 **13/31**（≤60 s），与我独立复算完全一致 → **步骤 3 应该是交接桥，人脸降级**。
4. 顺带修正一处会静默出错的口径：**跨机位交接必须用绝对时钟**。用段内相对帧号会把「同时在场」算成交接，
   交接覆盖会从 13/31 虚高到 25/33（我第一次就是这么算错的）。

## 2. 为什么 31 条桥一条都过不了

按机位统计桥的分布（从 0.78 聚类的桥表）：

| 机位对 | 桥数 | 该侧最大簇有脸的比例 |
|---|---|---|
| 318–323 | 10 | 318 侧常见，**323 侧 0** |
| 305–323 | 8 | 305 侧常见，**323 侧 0** |
| 305–318 | 5 | 两侧都很少（这 5 个身份恰好都没脸） |
| 305–320 | 3 | 320 检出多为反光，几乎为 0 |
| 318–320 | 2 | 320 侧 0 |
| 320–323 | 2 | 323 侧 0 |

**323 出现在 22/31 条桥里，而它 384 条轨只有 9 条有可用脸（2.3%）。** 一条桥要求两端都有脸，
只要有一端是 323 就基本判死。320 的 fake 率 0.78 意味着它的"人脸检出"多数是屏幕反光，不能用于身份。

## 3. 与交接的关系：不是互补，是几乎不相交

- 交接覆盖 13/31；人脸覆盖 0/31（放宽 1/31）。
- 13 条交接桥里，两端都有脸的是 **0** 条 → **人脸补不上交接剩下的 18 条**。
- 也就是说，跨机位那一行目前**只有交接这一种机制**，人脸在这一版数据上对它是零贡献。

这与之前"人脸锚点 F1 0.5076→0.6132"并不矛盾：那次增益发生在**同一批聚类内部的合并**，
主要吃的是 305/318 这类能出脸的机位，并且是簇级用法。跨机位建桥是另一回事。

## 4. 一处口径修正：交接必须用绝对时钟

`segments_meta.json` 里各段 OSD 起点不同（08:03 / 08:22 / 08:35 / 09:28 / 12:57 / 13:28 / 14:22 / 15:03）。
第一版我直接用 `frame/25` 当时间戳，得到「25/33 桥有交接」，且出现 178 对"同身份跨机位同时在场"——
这些都是假的：跨机位的同一人不可能同时出现在两个画面里（除非时钟有偏或标注噪声）。

加上 OSD 偏移后：

- 桥数 33 → **31**（相对时钟把机位分组也算错了）
- 交接覆盖 25 → **13**
- 同身份跨机位重叠对 178 → **18**（集中在 7 个身份，与"9 对重叠 >10 s"同一现象，多为 323）

**结论：任何跨机位的时间推理都必须先做 OSD 对齐**，这条已经沉淀为项目铁律。

## 5. 对步骤 3/4 排序的影响

| 原计划 | 调整后 | 理由 |
|---|---|---|
| 步骤 3 人脸锚点补到 8 段 | **降级**：只做簇级纯度核验 + 同机位内补链 | 跨机位 0/31 覆盖；49 组只有 22% 有脸 |
| 步骤 4 验证交接桥 | **升级为步骤 3**：60 s 窗口取候选 → 外观前 3 → 簇级核对后并簇 | 唯一能覆盖跨机位 13/31 的机制，且窗口 60 s 时真对象排第 1 占 70% |
| —— | **新增前置**：323/320 的可用脸问题要单独立项 | 323 是 22/31 桥的枢纽，2.3% 可用率是结构性瓶颈（姿态+走廊），加帧数收益有限 |

建议的验收顺序：先在 60 s 窗口把交接桥做到 13 条里的高精度子集（外观前 3 + 簇级核对），
量到 P≥0.95 下召回增益；人脸作为**核对手段**参与，不作为桥来源。
