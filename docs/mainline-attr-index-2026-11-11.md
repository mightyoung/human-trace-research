# 属性索引：从标注池到可检索的产品（2026-11-11）

> 上游：`docs/mainline-attr-baseline-2026-11-10.md`（模型选型、字段能力、假框率、池内到顶）
> 本文只讲**已收口交付的东西**：索引怎么建、能承诺什么、边界在哪、怎么复现。

## 0. 一句话结论

**1202 个实体里 673 个出了属性结论（9 个字段），可在控制台「标注 → 属性索引」按属性筛选。** 产品对象从"733 条抽样待标样本"换成了"全部轨迹实体"，并且每条结论带框高档位的能力标记——不是给标注池再补几个字段。

## 1. 为什么索引不能直接复用标注池

| | 标注池（attr_items） | 属性索引（attr_index） |
|---|---|---|
| 对象 | 733 条抽样样本 | 1202 个实体（1028 个能出帧） |
| 选样 | 机位 × 档位 × 概率富集 | 全量，不挑 |
| 每实体帧数 | 1 帧（标注用） | 最多 3 帧，按框高加权聚合 |
| 用途 | 训练 / 评估 | 查询 / 筛选 |
| 假框 | 人工判过 | `is_person` 头自动过滤 |

标注池的图是"标注当时的单帧"，索引要的是"这个人在整段录像里最清楚的那几帧"，所以必须重跑一遍。

## 2. 建索引的四步

### 2.1 抽代表帧

对每个实体的所有碎片轨，取**框高最大**的帧；按框高排序取前 3 张（优先不同轨），不足再从最长轨补不同时刻（间隔 ≥100 帧）。从 1440p 原始卷裁 bbox + 10% padding。

**为什么是"框最高"**：属性判读的瓶颈是框高，同一条轨里框高差异可达 2–3 倍。取最高帧等于把可判率拉到自己能达到的上限。

### 2.2 一个差点漏掉的坑：坐姿

第一版按"人形宽高比 1.45–6.0"过滤，只抽到 860/1202 个实体。查下去发现缺的 180 个不是小框，而是**宽高比 0.6–1.4 的坐姿框**——这批素材有大量工位场景，人坐着时框接近方形。放宽到 0.5 后补回 168 个实体。

真假交给 `is_person` 头判断，不要用几何规则替它做决定。

### 2.3 训练生产头

457 条标注 → EG2 图向量（768 维）→ 每字段 `StandardScaler → PCA(min(64, n/3)) → LogReg(C=0.1, balanced)`。

再加 **1 个 `is_person` 头**：把标注时判的 144 条「不是人 / 糊」当负例。这是标注顺带产出的免费能力，**AUC 0.986**，直接解决索引里"三成是反光倒影"的问题。

`age_group` 不进索引（三分类 0.829 < 多数类 0.832，壮年 AP 0.569）。

### 2.4 全实体聚合

同实体的多帧按**框高加权平均概率**；同时记录各帧 top-1 一致性 `agree`。418 个实体是多帧（占 40.7%）。

## 3. 覆盖率：能覆盖多少、为什么覆盖不了

| 环节 | 实体数 | 占 1202 |
|---|---:|---:|
| 实体总数 | 1202 | 100% |
| 抽到合法代表帧 | 1028 | 85.5% |
| 通过 `is_person ≥ 0.5` | **673** | **56.0%** |

按机位看，`is_person` 通过率把假框问题暴露得很直白：

| 机位 | 实体 | 出帧 | 像人 | 像人率 |
|---|---:|---:|---:|---:|
| 305 | 175 | 150 | 143 | **95.3%** |
| 320 | 111 | 105 | 104 | **99.0%** |
| 318 | 338 | 202 | 173 | 85.6% |
| 316 | 140 | 138 | 88 | **63.8%** |
| 343 | 82 | 81 | 42 | **51.9%** |
| 323 | 356 | 352 | 123 | **34.9%** |

323 只有三分之一是真人——与标注实测的 47.9% 假框率一致。**这 529 个被挡掉的实体不是索引的缺陷，是检测层的问题在该页面上第一次变得可见。**

## 4. 能力边界（交付的核心）

字段 × 框高档位的可承诺矩阵，随索引一起存在 `capability` 里，页面「能承诺到什么程度」展开即是：

| 字段 | S | M | L |
|---|---|---|---|
| 性别 | 可承诺 | 可承诺 | 可承诺 |
| 上衣颜色 | 可承诺 | 可承诺 | 可承诺 |
| 帽子 | 可承诺 | 可承诺 | 可承诺 |
| 上衣类型 | 参考 | 可承诺 | 可承诺 |
| 下装颜色 | — | 参考 | 可承诺 |
| 下装长度 | — | 参考 | 可承诺 |
| 戴眼镜 | — | 参考 | 可承诺 |

## 5. 与人工标注的一致性核对

同一实体上，索引结论 vs 457 条人工标注（**这是训练集内的一致性检查，不是泛化验证**；独立泛化看上游文档的实体分组 CV）：

| 字段 | 一致率 | 置信 ≥0.85 时 |
|---|---:|---|
| 帽子 | 0.995 | 431/431 = **1.000** |
| 下装长度 | 0.989 | 270/271 = 0.996 |
| 背包 | 0.986 | 330/330 = **1.000** |
| 下装颜色 | 0.961 | 243/245 = 0.992 |
| 上衣类型 | 0.954 | 316/324 = 0.975 |
| 拎东西 | 0.953 | 271/276 = 0.982 |
| 戴眼镜 | 0.951 | 261/265 = 0.985 |
| 上衣颜色 | 0.930 | 327/332 = 0.985 |
| 性别 | 0.971 | 414/416 = 0.995 |

多帧聚合比标注时的单帧更稳，所以这些数字高于单帧 CV（0.884–0.965）——是真实增益，但**不能当泛化指标报**。

### 5.1 v2 的两个改动：一个几乎免费，一个小幅但确定

第一版交付后跑了 `tmp/attr/crop_fusion.py`（457 条、实体分组 CV、同口径），探「局部区域融合能不能救背包/拎东西」，结果顺手暴露了一个更基础的问题。

**① PCA 维度是被自己掐死的（已采纳）**

原来 `PCA(n_components=min(64, n/3))`，n=363 时只保留 64 维。改成 `min(128, n/3)`（≈121 维）后：

| 字段 | AP@64 | AP@121 | 变化 |
|---|---:|---:|---:|
| 背包 | 0.427 | **0.507** | +8.0 pt |
| 拎东西 | 0.536 | **0.622** | +8.6 pt |
| 上衣颜色（对照） | 0.884 | 0.888 | +0.4 pt |

稀有字段涨 8 个点、常规字段基本不动 —— 说明 64 维把稀有信号压掉了，不是普遍过拟合。

**② 拎东西加「下半身」拼接（已采纳）**

| 特征 | 背包 AUC / AP / P90 召回 | 拎东西 AUC / AP / P90 召回 |
|---|---|---|
| 全身（基线） | .8754 / .5070 / .222 | .9105 / .6223 / .179 |
| 上半 | .8227 / .4719 / .333 | .8356 / .3893 / .071 |
| 下半 | .7531 / .2641 / — | .8877 / .5834 / .179 |
| 全身+上+下 | .8335 / .4339 / .111 | .8991 / .6062 / .143 |
| **全身+下半** | .8564 / .4001 / .167 | **.9092 / .6703 / .321** |
| 全身+上半 | .8715 / .5133 / .278 | .8981 / .5147 / .107 |

- **拎东西**：全身+下半 AP +4.8 pt、**P90 召回 .179 → .321**（5/28 → 9/28）。物理上也对——手在下半身。
- **背包**：拼上/下/全都无收益，三区全拼反而掉 7 个点（多余信息稀释）。**保持全身。**
- **对照**：上衣颜色三区拼接 −0.9 pt，符合"非局部属性会被稀释"的预期。

v2 的一致性核对（对比 v1）：

| 字段 | v1 | **v2** |
|---|---:|---:|
| 上衣类型 | 0.932 | **0.954** |
| 上衣颜色 | 0.916 | **0.930** |
| 下装颜色 | 0.944 | **0.961** |
| 背包 | 0.969 | **0.986** |
| 拎东西 | 0.937 | **0.953** |
| 戴眼镜 | 0.945 | **0.951** |

⚠️ 这些提升都在 18 / 28 个正例上量出来的，置信区间很宽。方向可信（符合物理直觉 + 对照字段不动），幅度别当真。


## 6. 三个必须说清的缺陷

### 6.1 裙装被判成「短裤」，而且是高置信度

`bottom_type` 只有「长裤 / 短裤」两类：裙的标注只有 3 条，低于 8 条训练门槛被剔除。筛「短裤」返回的 22 条里**几乎全是裙装**（连衣裙、短裙加长袜），置信度 0.99+。

处理：改口径，不假装能分。界面上显示「下装长度：过膝 / 未过膝」，并明写「不分裙与短裤，要看裙装请人工复核」。

要继续往下做只有一条路：补 20–30 条裙装标注，重训三分类（约 15 分钟标注）。

**R4 批次已上线**（`tmp/attr/build_r4.py`）：把索引里 `bottom_type=短裤` 的 23 个高置信实体抽成一批（它们大概率就是裙），界面上只显示「下装类型」一个字段，标完即可训三分类。图片走 `/attr_ent_crops/`，条目带 `crop_base="ent"`。

### 6.2 「拎东西」学到的是「手里有东西」

看图为证（316-E112）：一人双手各拿一个保温杯，标注意义上水杯不算（规则写"包/袋/箱"），模型判 `carrying=是`、置信度 1.00。

模型学到的是视觉上的"手部有物体"，与标注口径「拎包」不一致。对"找手里拿东西的人"这个用途反而是对的，对"找拎包的人"是错的。**用这个字段时要先明确要的是哪一个。**

### 6.3 背包 / 拎东西的准确率低于「全猜否」

| 字段 | CV 准确率 | 多数类 | 差值 |
|---|---:|---:|---:|
| 背包 | 0.926 | 0.950 | **−0.025** |
| 拎东西 | 0.912 | 0.909 | +0.003 |

这不是失败，是**低正例率下的准确率陷阱**：模型为抓到 5% 的正例付出了负例误报。它们只有 AP（0.427 / 0.536）和 P≥0.9 时的召回（11% / 18%）能说明能力，所以页面上标成「参考」，并明写"只能当提示"。

## 7. 场景决定了上限

抽帧时确认：这批素材以**办公楼工位与走廊**为主，不是通道/闸机。直接后果是背包（挂在椅背上）、帽子、口罩的正例都极少（索引里帽 16 / 背包 24 / 拎东西 24 个实体）。

换到入口闸机、电梯厅这类场景，比例和能力会完全不同，**这批数字不能直接搬**。

## 8. 复现

```bash
# 1 抽代表帧（本地，读 1440p 原始卷；全程约 13 分钟）
python tmp/attr/build_ent_crops.py            # 全量
python tmp/attr/build_ent_crops.py --resume   # 只补缺口

# 2 训练 + 全实体推理（远端 GPU，~/venvs/embgemma/bin/python）
python build_attr_index.py                    # 产出 attr_index.json

# 3 落库（图片目录已在 build_ent_crops 里直出到后端静态目录）
cp attr_index.json webapp/backend/data/

# 4 前端
cd webapp/frontend && npx vite build --outDir dist_attr --emptyOutDir false
cp dist_attr/index.html dist/ && cp dist_attr/assets/* dist/assets/
```

接口：

- `GET /api/attr/index?field=top_color&value=黑&min_conf=0.8&min_person=0.5&cam=316&band=L&limit=60`
  - 只给 `field` 不给 `value` = 列出所有该字段有结论的实体（按置信度降序）
  - 返回 `facets`（取值分布）、`capability`（能力矩阵）、`meta`（构建时间、训练量、一致性）
- `GET /attr_ent_crops/{name}` 代表帧图片

## 9. 页面坑（给后来者）

1. **`.bar` 是全局进度条类名**（`theme.css` 里 `height: 5px; overflow: hidden`）。筛选栏用 `.bar` 会被压成一条缝、内容全看不见。改名为 `.fbar` 解决。
2. 全局 `select { width: 100% }`，在 flex 工具条里会让每个下拉各占一行。必须显式 `width: auto; flex: 0 0 auto`。
3. `vite build` 会 `emptyOutDir` 清掉 `dist/faces`、`dist/s6b_thumbs`——一律 build 到 `dist_attr` 再只拷 `index.html` + `assets/`。

# 六、补标「裙装」：一次被证伪的尝试（2026-11-11 09:55）

## 结论先行

**在当前素材里，裙与短裤分不开——不是模型不够好，是单帧画面上没有这个信息。**

**事后更正（标注者确认）：这位女性穿的确实是裙。** 也就是说标签是对的，但这 23 张单帧里没有任何能支撑它的证据。这比"标错了"更值得记：模型不是被错误标签教坏，而是被"看不见的真相"要求猜一个它无从判断的答案。

提出补标的理由是「索引把裙一律判成短裤」。补标 23 条之后发现，那 23 条正是**长外套盖住胯部**的情形：能看到的只有露在外面的小腿和黑色及膝袜，裙与短裤在像素层面没有区别。所以这批标注不能用来训练，已按「不可判」作废。

## 做了什么

从索引里取 `bottom_type=短裤` 且置信度最高的 23 个实体（当时判断"大概率是裙"），做成 R4 批次，标注页只显示「下装类型」一个字段。23 条全部标完：

| 取值 | 条数 |
|---|---:|
| 裙 | 20 |
| 其他 | 2 |
| 长裤 | 1 |
| 短裤 | **0** |

表面上看，模型在这 23 条上 **0/23**，像是"把裙全判成短裤"。但逐张看图之后，这个结论不成立。

## 逐张核对后的事实

**1. 下摆不可见。** 23 张里 20 张是同一位女性：棕色/深色长外套盖到膝上，外套下缘就是可见的最低衣物边缘，再往下是裸露的大腿和黑色及膝袜。会不会是短裤？有可能；会不会是连衣裙？也有可能。**画面里没有能区分的信息。**

**2. 那 20 条基本是同一个人。** 同款棕色长外套、同款黑色及膝袜与黑皮鞋、同一只带挂饰的深色手提包，其中两张还有同一只白色发夹。跨 305 / 316 / 318 / 323 / 343 五个机位。

**3. OSNet 没能把它们合并，这是已知问题不是新发现。** 两两余弦最大 0.81、中位 0.49，0.80 阈值下得到 22 个簇、最大簇只有 2 条。这正是「跨机位搭桥失败」的典型形态，说明不能指望 ReID 特征来判身份，也说明属性索引继承了实体碎片化——同一个人在这里是 20 个实体。

## 三条理由说明这批数据不能用来训练

1. **标签对，但证据不在这一帧**：她确实穿裙（人工确认），可单帧里只有"外套下摆 + 露腿 + 及膝袜"。拿它当正例训练，模型学到的是「棕色长外套 + 黑袜 = 裙」，而不是「裙的样子」；
2. **身份集中**：20 条 = 1 个人 20 段素材，模型会学「棕色长外套 + 黑袜子 = 裙」而不是「裙的样子」；
3. **产品上不需要**：「过膝 / 未过膝」已经覆盖了这批数据能提供的全部信息（露腿 = 未过膝）。

## 处理

- 23 条标注**保留为有效真值**（`verified: true`），但标 `no_train: "hem_hidden"`，训练脚本跳过带该标记的行（它们仍是 `is_person` 的正例，因为这些确实是真人）。
  `no_train` 与 `skip` 语义不同：`skip` = 这条判不了；`no_train` = 标签为真，但该字段在本帧没有证据；
- 索引 **保持 v2 不变**：裙的旧标注只有 3 条，低于 8 条门槛，从来没有进过 `bottom_type` 的训练，所以模型无需重训；
- 页面说明同步改正：从"裙的标注太少"改为"胯部被遮住时裙与短裤没有区别"。

## 换来的两条经验

**标注选项要与问题同粒度。** 页面上的跳过项是「框太小 / 画面模糊 / 严重遮挡 / 不是人」，都是在形容**整个人**；而这批人是清楚的，只是**下装**被上衣遮住。语义不贴，标注的人就会被迫去猜。下装类字段需要独立的「下装看不清」。

**"模型判错了"要先排除"人给了错答案"。** 如果只看数字，会得出"模型把裙全判成短裤、准确率 0/23"的结论，进而去重训模型——方向完全错了。正确顺序是：先看数据能不能支撑这个标签，再看模型。

## 如果一定要分裙与短裤

已经知道答案（她穿裙）之后，问题就从"能不能判"变成"证据在哪"。这批单帧没有，但有两条别的路：

1. **多帧 / 视频**：走路时裙摆会摆动、坐下时裙会摊开，而短裤的裤腿分衩不会。人认出"她穿裙"多半就是靠这个，而不是靠某一帧。
2. **换素材**：正面视角、下摆形状可见（裙的摆幅/开衩 vs 短裤的裤腿分衩）、且覆盖多个身份。当前 35 分钟办公场景里，穿裙的人本身就极少，20 段素材全是同一个人。

单帧分类这条路在本素材内到此为止：再标 100 条，大概率还是同一个人。

# 七、r3 抽样收尾：16 条入库，属性线正式收口（2026-11-11 21:45）

## 结论先行

**r3（稀有类富集批）剩下那 16 条标完了：13 条「不是人」、3 条真人——假框率 81%。**
这批数据同时给了一件事的答案：**剩余 116 条不值得再标**。

主表指标**完全不变**：新增 3 条真人全在 r3，而主表口径是 r1+r2 = 416 条。只有参考口径
C 从 457 升到 460（r3 有效 13→16 条，仍在统计噪声内）。

## 一、这一批的明细

`tmp/attr/r3_closeout.py` → `deliverable/attr_check/r3_closeout.json`

| 结果 | 条数 | 说明 |
|---|---:|---|
| notperson | 13 | 反光、剪影、画面杂物 |
| valid | 3 | `323#59`（黑衣黑裤男）/ `323#571`（红衣男，戴眼镜）/ `323#511`（红衣男，戴眼镜） |
| 被 is_person 拦下 | 9 | 8 条拦对了（假框），1 条拦错了（`323#59` 是真人，p=.073） |
| 无实体 | 5 | 抽「框最高帧」时就被丢弃（宽高比/尺寸不合格），本来也不是人 |

**81% 的假框率比预想的高得多。** 之前按「323 假框 47.9%、316 39.8%」估算这批富集抽样，
实际是 **13/16**。原因是 r3 的选样逻辑是「稀有字段概率取高」——而概率高的往往是
**反光倒影、剪影、桌面杂物**这些被模型误认成背包/拎东西的框。富集和假框在这批素材上是**正相关**的。

## 二、抽样正式关闭

| | 条数 |
|---|---:|

## 三、顺带把 is_person 闸门体检了一遍

索引在 07:57 建（457 条训练），当时还没这批标注。用 460 条人工标签反查它的判定：

|---|---:|---:|

假阴性是假阳性的 5 倍——**闸门偏保守，宁可少收真人，也不多放假框**。对「属性索引是筛选工具」

# 八、多帧投票：封顶验证，否（2026-11-12 15:15）

## 结论先行

**把「每轨 1 帧」改成「每轨最多 5 帧投票」，对 9 个字段全部没有收益**，
两个稀有字段还更差：拎东西 AP .656→.639、P≥.90 召回 **.32→.07**。

唯一有一点用的是一个受限变体（尺度门：只用高度 ≥ 最优帧 80% 的帧）——
背包 AP **.458→.519**、P90 召回 .11→.17，但同时把拎东西的 P90 召回砍到 .14。

**结论：不采纳。稀有字段的瓶颈是「证据质量」（框只有 40–70 px、遮挡），不是时间聚合。**

## 一、为什么值得试这一刀

现状 `build_ent_crops.py` 每个实体取「框高最大」的一帧为主，补帧还要求与已选帧间隔 ≥100 帧，
结果 **610/1028 实体只有 1 张裁图**——59% 的实体是纯单帧证据。
而单帧判「手里有没有东西」本来就是信息不足，所以「多帧投票」是最后一个没试过的低成本改法。

## 二、做法（模型不动，只改推理聚合）

`tmp/attr/build_multiframe_crops.py` → 756 条已标注条目，**3243 张**：
同一条轨按时间分桶、每桶取框最高帧，最多 5 帧（535 条拿到 5 帧）；
裁图口径与训练集完全一致（bbox 外扩 10%、原生分辨率、q95）。

远端 `~/.venvs/embgemma` 跑 EG2 编码（全图 + 下半 62%），3243×768 两套向量。
自检：j0 帧与生产嵌入的余弦中位 **.988**（说明裁图口径一致，可比）。

`tmp/attr/eval_multiframe.py` 用与生产完全相同的头（StandardScaler→PCA(n/3)→LogReg C=.1），
实体分组 5 折 OOF，只换推理聚合方式。

## 四、为什么多帧反而更差

基线的「框最高帧」不是随机帧，而是**该轨可判性最好的那一帧**。
再补 4 帧，等于往最好的证据里掺更弱、更糊、更遮挡的证据：

- 「取最大」把噪声当信号（任意一帧说「是」就判是）→ 全线下降，上衣色 .908→.817；
- 「平均/中位」按高度加权也不够，弱帧仍占 20–30% 权重；
- 「尺度门」限制到 ≥80% 高度后，多数字段回到基线附近，背包小幅受益（背包是轮廓级特征，
  多视角有一点边际价值），但拎东西的手部细节经不起任何弱帧。

## 五、这条结论改变了什么

| 旧判断 | 新判断 |
|---|---|
| 单帧证据不足 → 多帧投票应该能提召回 | ❌ 实测无收益，拎东西 P90 召回从 .32 掉到 .07 |
| 稀有字段还能靠「更多帧」救 | ❌ **封顶**：瓶颈是框只有 40–70 px 与遮挡，不是时间聚合 |
| 背包/拎东西可以再调参数 | ❌ 参数、PCA、拼接、多帧四条路都已试完，全部在 .45–.66 之间 |

**背包/拎东西到此为止。** 要再进一步只有换采集（更高分辨率、正面视角）或换范式
（把背包当**物体检测**而不是人框分类）——后者是唯一还没试过的方向，但需要物体级标注。
