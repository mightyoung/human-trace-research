# 人脸活体识别技术近邻研究（面向 human-count 人脸证据链）

> 调研日期：2026-10-14 ｜ 定位：人脸能力第三问（P0 抓取 / P1 增强已交付；本文 = 活体识别的"研究 + 集成设计"，未实施）
> 结论先行；文中数值均标注来源，标 ★ 为与本项目直接相关的判断。

---

## 0. 结论摘要（TL;DR）

1. **★ 本项目场景 ≠ 认证场景**：银行/门禁的活体是"防攻击者冒用"；本项目是办公场所人员追踪，真正的威胁是"**非人的脸**"混入人脸证据链——海报（已有实证：305「50所」海报被检出）、手机/屏幕里的脸、倒影（S5/S6 已有完整证据链）、3D 人模。因此活体在本项目的正确语义 = **证据质量控制 flag（降权不删除）**，而非身份判定的门禁。
2. **★ 硬件方案不可用，纯软件是唯一路径**：红外/结构光/深度必须专用模组，"普通 RGB 摄像头软件无法模拟"（旷视/虹软口径一致）。本项目 6 路普通定焦机 → 只能选 RGB 软件路线。
3. **可落地的软件路线**有两族：**纹理/频域分类器**（MiniFASNet 族，ONNX INT8 仅 600KB~1.1MB、CPU 0.2ms/脸，已有 Rust tract 推理先例）与 **rPPG 生理信号**（照片/面具无心跳，最难伪造；已有商用产品落地）。**跨域泛化是共同的最大风险**（域内 98% → 跨域 15~30% 常见）。
4. **★ 建议三阶段**：**L0 轨道级活体规则**（零成本、立即可做：轨迹运动一致性 + 脸体一致性 + 静态性）→ **L1 RGB 纹理模型旁路**（MiniFASNet ONNX，同序列 A/B 定阈值）→ **L2 rPPG 试点**（仅 316/343 大脸场景）。全程只标注/降权，**不进 GIL 身份判定主链**。
5. **★ 与现有资产的关系**：S5/S6 解决"空间复制"（倒影），活体解决"介质复制"（印刷/屏幕）——互补过滤层，不可互替；且 L0 可立即在现有 4491 张 shot + 已知 5 例误检上跑通出报告。

## 1. 威胁模型：监控场景的活体到底防什么

| 层级 | 攻击手段 | 认证场景后果 | 本项目后果 | 已有证据 |
|---|---|---|---|---|
| L1 | 打印照片 / 海报"脸" | 冒用 | 假人脸入库、虚增人数 | ★ 305「50所」海报误检（P0 已知） |
| L1' | 手机/平板/显示器屏幕里的脸 | 冒用 | 假人脸入库 | 尚未见实例，但场景存在（办公区屏幕多） |
| L1'' | 反光/玻璃镜像中的脸 | 冒用 | 身份证据被"空间复制"污染 | ★ S5 倒影指派 / S6 墙镜几何（已解决 68/138 起） |
| L2 | 预录视频循环 | 冒用 | 类 L1' | — |
| L3 | 3D 打印 / 硅胶面具 | 冒用 | 极低概率 | — |
| L4 | Deepfake 注入 | 冒用 | 不适用（无注入链路） | — |

★ 关键推论：本项目"活体"验收口径不应照搬 iBeta（其测试是**配合式**近距采集），而应自定义："在本楼现场拍一张同事照片/手机播放视频对着相机 → 系统是否把它当人脸证据"。

## 2. 技术全景：四条路线与防御矩阵

| 维度 | 静默活体（RGB 软件） | 动作活体（RGB 软件） | 双目红外 | 3D 结构光 |
|---|---|---|---|---|
| 原理 | 纹理/微表情/皮肤反光 | 指令动作（眨眼/张嘴） | RGB+红外（体温/皮肤纹理） | 红外点阵建 3D 人脸模型 |
| 抗照片 | 中 | 高 | 极高（屏幕/照片在红外下"白花花一片"） | 极高 |
| 抗重放视频 | 低~中 | 中 | 高 | 极高 |
| 抗 3D 面具 | 低 | 低 | 中（面具无体温） | 极高 |
| 抗 Deepfake | 弱 | 弱 | 中 | 极高（可结合） |
| 硬件 | 普通 RGB | 普通 RGB | 专用双目模组 | 专用点阵模组 |
| 成本 | 低 | 低 | 中偏高 | 最高 |
| 典型场景 | 门禁/考勤（低风险） | 在线实名/直播 | 安防门禁/ATM | 刷脸支付/高保密 |

来源：旷视 Face++ 方案对比、CSDN 端云协同、门禁选型多篇（见 §8）。
★ 对本项目：动作活体需用户配合 → **排除**；双目/结构光需换硬件 → **排除**；**只剩静默 RGB 软件**，且必须自建验证。

## 3. RGB 软件路线的三族技术

### 3.1 纹理 / 频域分类器（工程最成熟）
- 判别依据：打印纸纹理梯度平坦、屏幕像素网格呈周期性摩尔纹、3D 面具过光滑；中心差分卷积（CDCN）显式建模梯度分布差异；MiniFAS 训练引入 **傅里叶变换辅助损失**学习频域伪影特征（开源实现有 98.2%/AUC 0.9984 的域内成绩，CelebA-Spoof 70k+ 样本）。
- ★ 关键实物：`MiniFASNet V1SE/V2-SE`（80×80 输入）——ONNX INT8 **600KB（量化后）/ 1.1MB**，手机级 CPU 单帧 **0.18~0.23ms**；GitHub `facenox/face-antispoof-onnx` 提供 600KB 量化版；`abhay-2108/Secure-Face-Liveness-Suite` 展示了"检测→活体→识别"三段式 INT8 流水线，且用 **Rust tract 引擎**推理（与本项目 Rust 交付目标一致，可借鉴）。
- ★ 警示：上述 98% 是**域内**（CelebA-Spoof）成绩。跨数据集测试 HTER 常见 15~30%（2025 年 CLIP 类 SOTA 借助大规模数据也只压到 ~3~11%）。监控部署前必须在本楼数据上重验证。

### 3.2 rPPG 远程生理信号（最难伪造的被动信号）
- 原理：心脏搏动 → 面部皮肤微血管血容积周期变化 → 皮肤颜色出现肉眼不可见的周期性波动；血红蛋白对绿光吸收最强 → 绿通道携带最强脉搏信号；照片/面具**没有心跳**。
- 工程现状：银行远程开户已在后台静默使用；商用产品 **天地伟业「四微」**（普通摄像头无感监测心率/血氧等）；Fraunhofer HHI 用 rPPG 做 PAD（口罩/遮挡区域可视化）；2025 年澳门理工 HRMamba（多光照鲁棒）、BRPDNet（遮挡场景）发表在 IEEE JBHI/TCE。
- ★ 本项目可行性计算：rPPG 一般需要**脸区 ≥80px + ≥15~30fps + ≥5~10s 窗口**。本项目 316/343 大脸 80~120px、源视频 25fps → 理论上可行；305/318 小脸（<60px）不可行。运动/光照变化是 SNR 主要杀手（行走者、逆光）。
- ★ 注意：rPPG 与现有"多帧合成"管线天然衔接（都是"同 tid 多帧时序分析"），是 L2 阶段最值得试的方向，但**先做 SNR 评估再谈判定**。

### 3.3 时序 / 运动一致性（本项目 L0 的立足点）
- 眨眼/微动作检测：适合配合式近距，监控远距不可靠。
- ★ 对我们最有效的其实是**结构性规则**（零模型成本）：
  1. **轨迹运动一致性**：真人脸通常属于一条有连贯位移的 tid；海报/屏幕脸要么无轨迹（脸在静止物上），要么其"轨迹"与所在人体框运动不同步。
  2. **脸-体一致性**：脸应位于人体框头部区域、朝向与运动方向大体一致（结合 P0 已有 in_head 关联 + 运动方向）。
  3. **静态性检测**：脸相对画面静止且持续 >N 秒、周围无人体轨迹 → 海报/屏幕嫌疑（305 海报即此类）。
- 已知可验证样本：P0 人脸墙上已识别 5 例误检（海报"50所"、后脑勺、门饰）——L0 规则的天然测试集。

### 3.4 单目深度（补充，非首选）
- MiDaS 类单目深度对"平面照片"有先验约束（脸区深度方差≈0 → 大概率平面）；但计算重、脸区小尺度深度估计不稳。★ 与项目已有结论一致（深度在本项目仅"调度器"级），不建议作为活体主特征。

| 数据集 | 规模 | 模态 | 攻击类型 | 备注 |
|---|---|---|---|---|

- 评测协议：**跨数据集 HTER**（泛化才是真考题）；域内 accuracy 无意义。

- ★ 对项目的启示：我们不追求 iBeta 级认证（无此需求），但可**借用其口径**定义内部验收：自建小型攻击集（打印照片/手机视频各 N 次呈现），统计"APCER（假脸被判真）"。

## 5. 与本项目现状的集成设计（推荐方案）

**总原则（沿用项目纪律）**：活体分数只进"标注/降权"层（obs.flags / annotation 视图无关真相层），**不改 GIL 身份判定主链**；阈值一律 val 校准；模型产物与原始图成对存储。

### L0（零成本规则层）——建议立即实施
- 输入：现有 `face_shot_p0b.json` + GIL 轨迹 + 人体框。
- 规则（经验初值，待 val 校准）：`static_face`（脸相对画面位移 <ε 持续 >10s 且无关联轨迹运动）、`face_body_mismatch`（脸不在关联人框头部区/运动方向相悖）、`no_track_face`（无轨迹可关联的大脸）。
- 产出：`liveness_rule_v0.json` + 每张可疑脸的证据卡（帧、框、规则命中）。已知 5 例误检（海报等）应立即被命中即算通过。

### L1（RGB 纹理模型旁路）——需 1~2 天
- 模型：MiniFASNet V2-SE ONNX（600KB INT8），对每 tid 最优脸 + 融合图跑 spoof score（全量 1062 张 <1s CPU）。
- ★ 验证设计（无 GT 攻击集 → 用代理）：已知非人样本（海报/后脑勺/门饰）+ **自建攻击样本**（现场对镜头举照片/播放手机视频，拍 20~50 张）vs 正常人流样本 → 看分数分布分离度；**先看分布，后谈阈值**。
- 风险提示：跨域泛化（见 §3.1），若分布分离度差 → 按"负结果"记录，不硬上线。

### L2（rPPG 试点）——条件成熟后
- 仅 316/343 大脸高分段（脸≥80px、可见时长≥5s）先跑 SNR 评估；再谈是否做"心跳存在性"判定。
- 复用多帧合成管线的对齐/堆栈基础设施。

### 明确不做
- 动作活体（非配合场景）、硬件改造（红外/结构光）、把活体分数当身份门禁（防"活体幻觉"进入主链）。

## 6. 风险清单

1. **跨域泛化**（最大风险）：学术模型→监控场景迁移，分数分布可能整体偏移 → 必须先本地分布校验。
2. **低质量样本**：小脸/暗光下纹理线索本身不可靠 → 与质量门串联（质量差的先降权），不做"低质量也要判活体"的强求。
3. **数据合规**：自建攻击样本采集需在场人员知情同意、仅本地使用。
4. **与倒影链的分工**：倒影（空间复制）已由 S5/S6 处理；活体（介质复制）是新维度；二者叠加时需注明"双重可疑"。
5. **验证集规模**：本楼场景的真实攻击样本极少（好事也是坏事）→ L1 结论表述为"代理验证"，非认证级。
