## 0. 结论速览

### Q1：6 路空间拓扑 / 简易空间模型
**已建立"统计与功能层面"的拓扑关系，未建立"几何空间模型"。** 二者必须分开说：

| 层 | 状态 | 关键证据 |
|---|---|---|
| 视觉重叠关系 | ✅ 已建立（318×320 为真重叠，其余走接力） | 8 对人工 GT + 映射 M（时空残差 AUC≈1.000） |
| 门户转移关系 | ✅ 已建立并已量化 | 196 边（main 182 + gate 14）、Parzen 转移时间分布（峰 4.5s）、窄窗显著性 316→318 z=6.45 / 343→323 z=4.90 / 343→316 z=4.71 |
| 物理可达关系 | ⚠️ 仅假设（"走廊星型"），未验证 | `portal-topology-baseline.md` §1 |
| 简易空间模型（几何） | ❌ 未建立（条件增强，未启动） | 无标定/位姿/地面坐标/BEV；仅有"每机位图像空间门坐标 + 重叠对映射" |

**能力判断**：从画面建立拓扑的**工具链已齐、且有实测**（置换检验 / 门聚类 / 转移分布 / 门户通道 7 件套）；"简易空间模型"目前只到**图像空间层**，跨机位几何（相对尺度、地面平面、局部 3D）为条件路线、零实施。统计功效还有明显短板：35min 同步视频只检测了 316/318/320 三路，305/323/343 缺（窄窗显著性只覆盖了部分机位对）。

### Q2：聚类模型与轨迹预测器的"自动评价模型"
**要素已有一部分，GPT 提议的完整机制尚未加入。** 逐条对照 GPT 评审（review_next.txt）的三项提议：

| GPT 提议 | 现状 | 判定 |
|---|---|---|
| 聚类评估升级"证据规则库"（六层）+ 小模型评审（输出 保留/隔离/拆分/合并/暂缓） | 六层中的**散片**已有（共现负对 F1、跨段保持、val 校准、margin per-cam、互斥约束），但**没有统一的评估器**，更无小模型 | ⚠️ 部分要素（约 40%） |
| 轨迹预测器验收改挂"固定误接下的正确接续/漏接/交接延迟"，预测输出{动作分布、下一门户、到达时间} | **未做**。意图 BERT 仍只有分类指标（acc 0.668 / mF1 0.477）；无下一门户头；预测器**未被任何下游消费**（grep relay/c0/handover 无引用） | ❌ 未加入 |
| 周期更新流程（冻结窗口→候选→回放→影子→发布/回滚） | 评测协议 §6 有**发布门槛预注册**；`replay_eval.py` 是"决策策略"回放（mirror/match30/relay 三面板），**不是**聚类/预测器的训练约束环 | ⚠️ 地基有、机制无 |

**一句话**：项目已有"自监督代理指标 + 回放评估器 + 证据状态机"三块与"自动评价"相关的资产，但它们各自服务的是**建库选型 / 决策参数 / 拓扑更新**；**"用评价模型评估训练效果并约束训练方向"这条闭环没有建成**——尤其"门控自训练"（H1 主线）还停留在 10-12 的实验（DINOv3 +0.048），未进生产。

**未建立（诚实清单）**：
1. **几何空间模型**：无内外参、无共享坐标系、无地面平面/BEV——`depth-ownership-and-camera-topology.md` 定位为"条件增强"（门户拓扑 → 重叠子图局部几何 → 相对 3D/2.5D），零实施；
2. **语义门户发现（WP2）**：一条未跑（G1–G4 四组对照全空缺）；
3. **物理可达图**：走廊星型仅为先验假设；
4. **统计功效**：35min 全六路窄窗显著性缺 305/323/343 检测（现有仅 316/318/320 三路 long35 检测+嵌入）；
5. 305 时钟偏移（建议 −7.5~−15，收益 +2 边）为**待批准口径变更**（改则破坏 v2 对账）。

### 1.2 Q2：自动评价——已有要素与缺口

**已有（服务对象各不相同）**：

| 资产 | 服务对象 | 产物 |
|---|---|---|
| 共现负对 F1（自监督代理） | **建库时模型选型**（`select_best` 网格选择标准） | `tools/train_selector_cluster.py`（`pairwise_f1_cooc`）、`build_selector_v2.py`（train 侧验证） |
| 无标签评估协议 | 选择器三档（分片一致性 / 跨集匹配 / 惰性最近邻对照） | `tools/selector_eval.py` |
| 跨段保持率 | 选择器跨时段稳定性（0.972/0.977/1.000 三档） | `tools/selector_crossseg.py` |
| margin per-cam 校准 | 拒识阈值按机位校准（r80 保留率） | `tools/selector_margin_percam.py` |
| 回放评估器 | **决策参数**（镜像/match30/relay 三面板，护栏区间） | `tools/replay_eval.py`（baseline 全复现） |
| 证据状态机 | **拓扑边的更新门控**（E 分 + active/candidate/suspect/dormant 四态） | `tools/relay_states.py` |
| Truth 指标条 | 排序质量（AUC 0.837 / Brier / 外推 / 同预算效率） | webapp `/api/truth/metrics` |
| 发布门槛预注册 | 上线纪律（误接上升即拒绝；覆盖率不得靠拒判） | `research-agenda/evaluation-protocol.md` §6 |

**缺口（对照 GPT 提议）**：
1. 无**统一的聚类质量评估器**（六层：数据质量/几何/稳定性/约束冲突/跨相机跨时段/下游收益 → 四动作输出）；
2. 无**学习式评审器**（不代替、只辅助规则基线的对照模型）；
3. 无**门控自训练环**（H1：伪标签+质量门控 vs 无门控的长期对照）——早期实验（DINOv3 +0.048，10-12）未工程化；
4. **轨迹预测器**：验收停在分类层，无"下一门户/到达时间/不确定性"输出，未接跟踪层指标（接续/漏接/交接延迟），未与 relay 图联动；
5. 无影子发布/回滚的**机制**（协议已有，流程未建）。

## 2. 近邻研究（本次核验的文献与可迁移点）

### 2.1 拓扑与空间模型

**经典链（免标定、非重叠，与本项目同构）**：

| 方法 | 核心机制 | 对本项目的补充点 |
|---|---|---|
| Makris & Ellis 2003 | GMM 聚出入口区域 + 事件互相关 + 峰检测 | 我们已有更严格的 Parzen + 显著性 |
| Stauffer 2005 | "离开-出现"相关系数**显著性检验** | 我们已实现（置换检验） |
| Tieu 2005 | 非参数互信息，处理**多模**转移时间 | 已实现（Parzen 多模） |
| Javed 2003 | Parzen 时空概率（假设对应已知） | 已实现 |
| "三因素"拓扑（NLPR） | **N-邻累积互相关**压低伪对应、锐化峰 | 可用于 305/323/343 补全时的长窗估计 |
| TCLM（arXiv 2105.01213） | MeanShift 分区 + 入口/出口密度分类 | 与我们的门户四分类同思路 |
| **城市级自监督 camera link（arXiv 2405.11345）** | **zone-pair 置信分**：`Score = −α·cos + β·N_pair − γ·Var(dt)`；高置信轨迹对构建 | ★ 直接可借：替换我们"每出口只留最佳一条"的启发式 |
| RoundaboutHD（2025） | zone discovery（起终点聚类）→ 最大 zone-pairing → **KDE 转移时间** | 与我们的 v7 口径互证；多出入口场景的手递逻辑可参考 |

**2025–2026 新线**：

| 方法 | 核心机制 | 适用/限制 |
|---|---|---|
| **CALIBFREE**（arXiv 2605.09245） | 免标定自监督特征解耦（view-agnostic vs view-specific）MCMOT | 无标定多机；评测在重叠数据集，盲区接力未覆盖 |
| **GRAP-MOT**（arXiv 2510.21482） | 图 + 位置加权 + 在线标签更新（无监督） | 重叠视角、拥挤空间 |
| Distance-based camera network（arXiv 1712.00158） | 用**人体身高**做单机自标定 → 相对尺度 → **与步行速度无关的距离拓扑** | ★ 简易空间模型的低成本路线 |
| Pose-guided calibration（ICCE 2025） | 人体关键点当标定物，多机自标定（<0.5px 重投影） | 需重叠视野（318×320 可试） |
| VisualSync（2025） | 用 CoTracker3+VGGT+MASt3R 从运动轨迹反推**时间同步** | 与 OSD 对齐互补（漂移维护） |
| StudioRecon（SIGGRAPH 2026） | 低重叠 4 机→人物 3D 重建（背景扩散 + 人体参数化） | 面向"人物活动三维影像"，非跟踪；作长期参考 |

### 2.2 自动评价 / 训练约束

| 族 | 代表 | 可迁移点 |
|---|---|---|
| **Label-free 模型评估（AutoEval）** | Deng & Zheng 2020 / TPAMI 2024；半结构化数据集表示（2021）；CAME（对比统计）；PCR（检测 pre/post-NMS 一致性，2025） | ★ "无需真值预测当前模型精度"的回归框架：用**数据集级统计 → 精度**。可借鉴到"聚类更新采纳"的分数回归 |
| **伪标签质量** | 语义稳定性指标（TPAMI 2025：衡量伪标签语义质量并重分配）；DBSCAN 参数稳定性=可靠性指标（JCADC 2024）；ICPL 置信过滤 + **静态编码评估协议**（2025）；IIG+PLC 伪标签净化 | ★ 语义稳定性/参数稳定性可整入"六层规则库"的"稳定性层"；静态编码协议防"旧类被新任务改写" |
| **小模型评审** | Compact VLM judge（arXiv 2507.20156）；**ScoreRS**（NeurIPS 2025：学习式打分器做数据筛选 + RL 奖励）；自改进 VLM judge | ★ 与 GPT 提议"小模型评审"同构；纪律：先确定性规则基线，再对照学习模型（不能替代真值） |
| **跟踪/交接验收** | **ReWorld-Track**（arXiv 2609.36677：预测下一机位/到达时间/入口区域，闭合"预测-关联-等待"环，HOTA 增益、身份保持跨多次交接增强）；SMO-MCTF（WACV 2025，which-when-where） | ★★ 预测器的正确验收范式：**下游跟踪指标**而非分类精度；"等待/未观测也有证据"的信念更新可直接对应我们的"盲区待接" |
| ReID 无监督（供对照） | Asperti 2025 综述；USVI-ReID 机制盘点（memory bank / 软标签 / 动态权重 / 双向一致性） | 自训练环的挖对与加权策略库 |

## 3. 实验与改进方案

**总原则**：不覆盖任何既有口径（v5/v6/v7、v2 边逐位保留）；不引入需要人工标注的新前置（复用 truth 55 判 + 13 判 + 4 组裁决）；每项含独立验收口径；生产发布动作单独授权。

### 3.1 Q1 方案（TOP-1 ~ TOP-4）

**TOP-1｜35min 全六路窄窗拓扑显著性补全**（低成本、解锁最多）
- 做法：远程补 305/323/343 三路 long35 检测（stride=5）+ 嵌入 → `topology_signature.py` 窄窗（≤5–10s）全 30 对重跑；对 316/318/320 与 10min 口径对照（功效 √(35/10)≈1.9×）。
- 验收：产出全 30 对 z 表（10min vs 35min 两列）+ 多重比较校正；对 343→323 等"待视频确认"对给出统计结论。
- 预期：把"有的对是噪声"与"有的对是真直连"分开；305 时钟敏感性单独列（不改 `TIME_OFFS`，先测再议）。
- 成本：3 路 ≈ 数小时 GPU（GPU0 当前被训练队列占用 → 排在训练窗口间隙或 GPU1）。

**TOP-2｜语义门户发现（WP2，G1–G4 四组对照）**
- 做法：先小样本试 SAM3/C-RADIOv4 替换路径（或独立开放词表分割）产出"门板/门框/走廊开口"候选 → 轨迹穿越验证（复用门户通道逻辑）→ 四组对照：纯轨迹 / 纯语义 / 融合 / 融合+几何。
- 验收：与 v7 的 123 个 portal 分母对照（语义召回/精确）；融合组相对纯轨迹的增量（新增有效门户数、对 196 边的解释率）。
- 预期：自动化"门区"维护（低频重算），替代部分手工门坐标。
- 风险：分割在本场面（玻璃/鱼眼）效果未知 → 先 20–30 关键帧试。

**TOP-3｜门户-边置信化（zone-pair 置信分）**
- 做法：借 City-scale 公式 `Score = −α·cos_dist + β·N_pair − γ·Var(dt)`，对每个"出口门 × 入口门"候选对打分排序（替代"每出口只留最佳一条"），产出 `portal_graph_v2`（新增文件，不覆盖 196 边）。
- 验收：对 4 组互斥裁决 + 55 判对回放：命中率不降、候选池可解释（每出口保留 top-k + 置信分）；对 v2 已判边无冲突。
- 预期：从"硬留一条"升级为"排序+多候选"，为 TOP-1 之后的图更新提供稳健输入。

**TOP-4｜简易空间模型三步（条件路线，先纸上后开工）**
- Step-1（低成本）：**相对尺度**——人体身高/步速做自标定（文献 1712.00158 路线），目标：给出跨机位"距离先验"与步速归一化的 dt 校准；
- Step-2（中成本）：318×320 **局部几何升级**（现有二次多项式 M → 试 pose-guided / VGGT 类免标定，以 AUC 0.994 为对照线）；
- Step-3（高成本，条件具备再上）：地面平面 → 2.5D/BEV。
- 验收：Step-1 用现有 196 边 dt 分布做前后对照（是否降低 Var(dt)、减少假候选）；Step-2 用 30 对判读对（8 正 22 负）算 AUC/重投影误差。
- ★ 纪律：**不为"完整三维"而拼图**——能表达"哪些关系已知/未知"优先（对齐 GPT 评审与项目原判断）。

### 3.2 Q2 方案（EVAL-1 ~ EVAL-5）

**EVAL-1｜六层评估规则库 v0（"自动评估器·规则版"）**
- 做法：新工具 `tools/cluster_eval_registry.py`（离线 CPU）：输入=候选聚类/更新（gperson、selector、relay 边集的任一新版本），输出=六层指标 + 动作建议（**保留/隔离/拆分/合并/暂缓**）：
  ①数据质量（碎片率、时长分布、嵌入覆盖率）；②几何结构（DBCV/silhouette）；③稳定性（跨段保持、重采样扰动、参数扫描）；④约束冲突（同帧互斥、时间区间违例）；⑤跨相机/跨时段（per-cam 分布、冻结段一致性）；⑥下游收益（C0 v7/v8 覆盖、truth 指标）。
- 验收：① 对 4 组裁决 + 13 判对回放：动作建议与人工结论一致率（含"暂缓"的使用正确性）；② 与 `relay_states` 四态对账不冲突；③ 对 gperson_v1 产出建议清单（抽查 20 条）。
- 预期：把散落代理指标统一成**可执行动作**；作为 EVAL-2 的确定性基线（GPT：先规则、后小模型）。

**EVAL-2｜学习式小评审器（对照实验，可选）**
- 做法：输入=规则证据向量（EVAL-1 输出），输出=5 类动作；训练样本=受控扰动+规则自动生成（**不读身份真值**；真实标签仅用于隔离评测；合成/规则/真实标签分别记录）。
- 验收：同输入下 vs EVAL-1 规则基线——动作一致率、**误拒/误放率**、延迟；若只复现规则且增误拒 → 不引入（预设失败条件）。
- 参考：compact VLM judge / ScoreRS（学习式打分器）/ Laya 类决策模型。

**EVAL-3｜门控自训练环（H1 首个可执行实验）**
- 做法（三臂）：①冻结检索（现状基线）②仅原型库更新（gperson 级维护）③伪标签自训练+**质量门控**（规则门控 vs 评审器门控）；挖对策略=跨机位×同机位**混合平衡**（10-12 教训）+ 共现负对/跨段/门户先验约束。
- 验收：留出判定对（55 判 + 扩表后）上：**同误接约束下**接续率/漏接/拒判覆盖；防自证：TG-05 留出时段、w_dt 剔除已判行（沿用既有纪律）。
- 预期：给"证据门控减少错误放大"首个系统数字；若同覆盖率下误接无改善 → H1 不成立（预注册失败条件已写在评测协议 §6）。

**EVAL-4｜预测器验收改造（跟踪层 + 下一门户头）**
- 做法：预测器输出扩为 {短期动作分布, **下一门户候选 + 到达时间区间 + 不确定性**}（输入复用 7 维 token + 门户相对关系特征）；把预测作为 relay/handover **先验**（候选预选 / 时间窗收紧 / 盲区"待接"状态），用 `handover_metrics` 口径验收。
- 验收（对照三臂：无预测 / 运动学基线 / 学习预测）：固定边级误接下——正确接续率、漏接、**交接延迟**、下一门户 top-k 命中率；**分类 acc/mF1 仅作副指标**。
- 参考：ReWorld-Track（预测-关联-等待闭环；matched-coverage 诊断）；SMO-MCTF。

**EVAL-5｜回放评估器扩展 + 影子发布**
- 做法：`replay_eval.py` 从三面板扩为四面板（+聚类更新 / +预测器），复用历史已判数据零标注；把评测协议 §6 落成流程脚本：冻结窗口 → 候选 → 回放 → **离线影子**（先不触生产）→ 发布/回滚报告。
- 验收：任一参数变更可一键输出"影响面表"；影子运行不改变生产数据（字节级对账）。

### 3.4 纪律衔接与"不做"清单
- 全部沿用：`DET_VIEW=clean2`、splits_v5 冻结、val 校准、TG-05/06/08、零静默；**新建产物一律并列不覆盖**（portal_graph_v2 / c0_v8 / eval_registry v0）。
