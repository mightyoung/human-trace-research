## 1. 研究背景、目标与边界

### 1.1 业务背景

多路摄像头分别计数再相加，会把同一个人重复计入。项目希望在以下约束下实现跨机位身份关联与人数去重：

- 办公楼多机位，主研究为 305/318/320/323 四路；另有 316/343 的六机位数据。
- 主四机位视野不重叠、无标定、无深度，跨机位只能主要依靠外观与时间信息。
- 图库不是人工整理，而是检测器和跟踪器自动产生的轨迹，包含碎轨、重复框、头/半身框、倒影和非人目标。
- 编码器冻结，不针对每个现场重新训练；人脸在现有画面中可用率过低。
- 涉及可识别人员视频，原始画面与 ReID 嵌入不进入公开交付包。

### 1.2 当前研究问题

| 编号 | 研究问题 | 当前回答 |
|---|---|---|
| RQ1 | 簇级审计能否可靠选择图库配置？ | 不能；其排序与逐条正确数负相关 |
| RQ2 | `d_max` 测到的是“混人”还是“有害”？ | 现场能测混人、不能测有害；MARS 的 H2a/H2b 在三口径下均未通过，不能将该反差写成普遍规律 |
| RQ3 | 当前系统主要损失来自错答还是未答？ | 未答：73 条，远多于 4 条错答 |
| RQ4 | self-cal 在哪些部署形态下可用？ | 需要同步、足够长轨迹、适当簇规模与足够共现对；不是通用公开基准协议 |
| RQ5 | 身份判定如何影响人数统计？ | 计数误差主要来自拒识、身份碎片和并行重复轨迹，不只是检测漏检 |

### 1.3 非目标

- 不追求 mAP/Rank-1 的新 SOTA，不提出新 ReID 骨干。
- 不把簇纯度本身当作业务收益。
- 不把六机位无标签覆盖提升解释为正确识别提升。
- 不把静态检查、页面展示或离线控制台等同于实时人数系统验收。

## 2. 数据、系统与评价口径

### 2.1 主系统链路

YOLO26s-seg 检测与 NMS → ByteTrack 单机位跟踪 → 同帧去重 → 轨迹 a/b 半段划分 → 冻结 OSNet 编码 → 机位内 average linkage 与跨机位 complete linkage → 簇原型及校准评分 → a/b 双片过阈值且同簇才接受。

生产基线为 `K=111`、`θ=1.85`、`veto_dmax=null`。图库采样 2.5 FPS，查询采样 5 FPS。

### 2.2 主数据规模

| 项目 | 当前口径 |
|---|---:|
| 图库检出轨迹 | 883 |
| 可编码图库轨迹 | 579 |
| 实际进簇轨迹 | 513（66 条孤立轨迹被过滤） |
| 查询检出轨迹 | 295 |
| 可评查询 N | 229 |
| 可答查询 | 196 = 229 − 22 非人 − 11 图库外 |
| 图库真值 | 257 条 = 22 个身份 236 条 + 非人 20 条 + 1 条远场 UNK |
| 查询真值 | 295 条，v3 现行 |
| A3 第二标注 | 图库 257 + 查询分层样本 100 |

注意：图库的 22 个身份与统计独立性分析中的 24 个查询身份组不是同一分母，不能混用。

### 2.3 不可混用的指标

- `coverage`：a/b 双侧均被接受的查询比例；不是准确率。
- `same`：已覆盖轨迹中 a/b 进入同簇的比例；可能“一致地错”。
- `fm`：同帧共现轨迹对被并簇的比例；只覆盖同机位硬负例。
- `accepted`：论文主表为可答人物查询的接受数 123。
- `C/W/U`：正确、错误、无法判定；平票簇记 U。
- `precision=C/(C+W)`：不含 U 和拒答。
- `C/N`：正确答案数除以全部 229 条可评查询，是当前主指标。
- `n_strict=138`：原始系统输出数，包含 123 条可答人物输出、14 条非人输出和 1 条图库外人物输出；不等于主表 `accepted=123`。

## 3. 当前进展与已有成果

### 3.1 现场主结果：已稳定

| 指标 | A_baseline |
|---|---:|
| K / θ | 111 / 1.85 |
| coverage / same / fm | 0.6638 / 0.9079 / 1.53% |
| final_output_rate | 0.6026 |
| 接受（可答人物查询） | 123 |
| C / W / U | 117 / 4 / 2 |
| 精度 | 117/121 = 0.9669 |
| C/N | 117/229 = 0.5109 |
| 错标占全部可评查询 | 4/229 = 0.017 |
| C/N 身份聚类 95% 区间 | 约 0.306–0.704 |

损失闭合：`196 = 117 C + 4 W + 2 U + 73 未答`；`229 = 196 + 22 非人 + 11 图库外`。

### 3.2 核心研究结论

1. **评价单位会反转配置排序。** 42 配置中，簇级继承精度与逐条正确数的 Spearman `ρ=-0.418`；继承精度最高的配置比基线少 61 条正确答案。
2. **簇纯度否决是负收益。** `d_max≥0.30` 使正确答案减少 27 条，精确配对检验 `p=1.1e-7`；已从生产配置关闭。
3. **纯度不等于有害性。** 现场 `d_max` 对混人簇 AUC 0.952，对有害簇 AUC 0.407（n=4，CI 很宽）。混人簇的多数派身份仍可能正确服务查询。
4. **没有配置显著优于基线。** 41 个非基线配置中，Bonferroni 下 22 个显著且全部为负；BH-FDR 下 24 个也全部为负。
5. **主要瓶颈是“没答”，不是“答错”。** 因此继续调阈值、评分归一化或簇纯度的收益有限；需要新视角、新身份覆盖或新的可用信息。
6. **多次“更多输入”未带来净收益。** 更强骨干、更多短轨迹、更大检测器、RGB 修正、加密采样等均出现检索或局部指标改善被跟踪、聚类和阈值系统抵消的情况。

### 3.4 MARS 三口径审计：复算完成，主口径待 G0 裁决

MARS 查询有 150 个身份，但图库只覆盖 148 个；0782/1172 共 4 条查询没有图库身份。既有主文与补充表采用了不同 query universe。审计形成三种口径：

- **A：保留图库外（include）**，实际执行实现，对应 `public_eval_tieu.py`。
- **B：排除图库外（exclude）**，与后续现场规则一致，对应 `c1_supp_table.py`，但属于后补统一。
- **R：图库外强制拒绝（exclude + forced-rejection）**，用于测量未知查询拒绝敏感性，不改变 B 的 accepted/C/W。

| 项目 | A：保留图库外 | B：排除图库外 | R：图库外强制拒绝 |
|---|---:|---:|---:|
| accepted 的计分面 | 484 | 480 | 484（含拒绝敏感性） |
| 基线 accepted / C / W / U | 320 / 255 / 33 / 32 | 318 / 255 / 32 / 31 | 318 / 255 / 32 / 32 |
| 精度 / inherited | 0.885 / 0.731 | 0.889 / 0.733 | 0.889 / 0.733 |
| H1a | -0.303，达到门槛 | -0.289，未达到门槛 | -0.289，未达到门槛 |
| H2b | 0.671，未通过 | 0.679，未通过 | 同 B，未通过 |
| H3：未答 > 错答 | 164 > 33 | 162 > 32 | 166 > 32 |
| 按预注册七条假设枚举 | **5/7** | **4/7** | **4/7** |

两条 1172 查询在全部配置中恒为拒绝，剔除它们只改 U；另两条 0782 查询合计 48 条 accepted 实例，剔除会改 accepted/W/U。42/42 配置的 C 与 McNemar p 不变；H1b=-153、H1c 低估、H2c=-15（p=0.0026）和 H3 方向稳定。H2a=0.742 与 H2b 在三口径下均未通过。B 的 H2b 审计区间约为 [0.564,0.779]，正式报告应由固定随机种子的统一脚本重算。

**处置建议：** 预注册没有显式规定这一 query universe，因此 A/B/R 先并列提交 G0，不预设主口径。若强调实际执行连续性，可将 A 作为主分析；若强调跨数据集估计对象一致，可将 B 作为主分析，但必须标注 post-hoc harmonization。R 固定作为未知查询拒绝敏感性。无论选择哪套，都不能只报对叙事更有利的一列。

主文与补充表当前不是同一计分面，不能交叉拼数；`supp_tables.tex` 的 MARS 脚注还需区分 accepted 的 480 条与 C/N 分母 484。Table 1 的图库身份数应改为 148，而不是 150。后续应由共享查询集和同一评估入口重建主表、补充表、图、VERDICTS 与 canonical；预注册是 7 条假设，旧稿“4/6”同时存在计分面与计数错误。
