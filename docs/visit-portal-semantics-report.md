# visit 门户语义接 relay 状态机（S9）

> 日期：2026-10-14　产物：`output_crosscam/analysis/relay_v2/visit_portal_link_v1.json`
> 工具：`tools/visit_portal_link.py`（新增，只读）

## 1. 问题（缺口 WP2：门户语义发现 × H2）

现有 relay 边的 **dt 与门户位置全部来自 entity 包络**（`a_tlast` / `b_tfirst`、`a_end` / `b_start`）。
而 GIL 的 `visit` 表里另有一份**独立**证据 —— 每个 entity 在每个机位的 **entry/exit 事件**
（穿越时刻 `t` + 穿越位置 `(u,v)` + 朝向 `dir` + 边缘余量 `edge_margin`）。

本实验：把 visit 的 entry/exit 接进接力证据链，回答两个问题 ——
**① 能不能更好地判别 relay 真假边？② 门户语义与 C0 的几何门一致吗？**

## 2. 数据

| 项 | 值 |
|---|---|
| visit 事件 | **650 条**（329 entry + 329 exit），覆盖 **361 个 (cam, entity)**（entity 共 411） |
| 带 entity_id | 650/658（8 条为 NULL，320 机位） |
| relay 边 | 196（active 36 / confirmed 10 / rejected 10 / audit 126 / gate 14） |
| 双端拿到 visit 证据的边 | **84 / 196（43%）** |
| C0 几何门 | per-cam exit/entry 门中心（GATE_R = 0.15，同 EVAL-4 L1 口径） |

## 3. ① relay 真假边判别（**结果：方向一致、证据不足**）

| 量 | 真边 n | 假边 n | rank AUC | 中位值（真 / 假） |
|---|---|---|---|---|
| `dt_visit`（exit_a → entry_b） | 24 | **1** | 0.042 | 4.0 / 0.6 |
| `dt_entity`（现状口径） | 46 | 10 | 0.569 | 4.8 / 20.4 |
| 门户对常见度 | 14 | **0** | — | 25 / — |

**读法**：`dt_visit` 的假边只有 **1 条**有双端 visit 证据 → AUC 无统计效力。`dt_entity` 的
AUC 0.569 也只是**弱信号**（真边 |dt| 中位 4.8s vs 假边 20.4s，方向对）。

**门户命中率无区分度**（gates 半径 0.15 太宽，几乎所有位置都能命中）：

| 口径 | 真（n=46） | 假（n=10） |
|---|---|---|
| visit-exit 命中 | 0.39 | 0.10 |
| visit-entry 命中 | 0.39 | 0.00 |
| entity-exit 命中 | 0.76 | **1.00** |
| entity-entry 命中 | 0.74 | 0.70 |

→ 真边更常"从门出去"（entry 0.39 vs 0.00）方向一致，但假边样本 10 条、且 entity 口径假边命中率反而更高 → **不可用**。

## 4. ★ ② 门户语义画像（**这才是真正的发现**）

把 visit 的 exit/entry 事件按最近的 C0 几何门归属，逐机位统计覆盖率：

| 机位 | exit 命中/总 | entry 命中/总 | 门数（exit/entry） | 结论 |
|---|---|---|---|---|
| **323** | 70/76（92%） | 72/76（95%） | 2 / 3 | ✅ 几何门可靠 |
| **316** | 39/44（89%） | 31/44（70%） | 3 / 1 | ✅ 较好 |
| 318 | 46/82（56%） | 39/82（48%） | 1 / 1 | ⚠ 中等 |
| 305 | 35/66（53%） | 43/66（65%） | 3 / 1 | ⚠ 中等 |
| 320 | 5/13 | 7/13 | 1 / 1 | ⚠ 样本小 |
| **343** | **10/44（23%）** | **0/44（0%）** | **1 / 0** | ❌ **几何门不完整** |

**关键结论**：C0 的几何门**在 343 上根本没有 entry 门**（只有 1 个 exit 门 `[0.69,0.99]`），而 visit 的
343 entry 事件 `u∈[0.014,0.864] v∈[0.092,0.998]` 散布全画面 → **几何检测漏掉了 343 的入口门户**。

> 这给「WP2 门户语义发现」缺口一个**具体定位**：**343（以及 318/305 的一半事件）需要用 visit
> 事件做数据驱动的门户发现**，而不是依赖 C0 的几何检测。

## 5. 结论与建议

1. **已接入**：visit entry/exit 作为独立门户证据进 relay 证据链，产出结构化产物（含逐边明细）。
2. **判真假边：不可用**（覆盖率 43%、假边样本 1 条）—— 但 `dt_entity` 的弱信号（AUC 0.569）说明
   **dt 本身是有判别力的特征**，值得继续。
3. **★ 门户语义：定位到缺口** —— 几何门在 343 缺失、318/305 覆盖一半。建议下一步做
   **数据驱动的门户发现**（对 visit 的 exit/entry 位置做聚类，验证/替换 C0 几何门）。
4. **不写任何生产文件**；现有 `edges_v2_gated_human.json` 与 C0 均未改动。
