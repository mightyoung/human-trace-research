## 2 P1（推荐）：风险受控的跨机位身份分配

> **★ 2026-11-09 实测更新：原方案不成立。** 开关实验（`docs/p1-conservative-check-2026-11-09.md`）给出的判定是：
> 共现对相对**跨机位**确实是保守上界（14 倍），但在**同机位**风险上**乐观 2.5 倍**（条件口径 0.39×，63 个 θ 无一例外），而误合并的 **69% 发生在同机位、24% 跨机位、只有 7.3% 是同帧同时在场**。
> 即：校准集与目标风险**不同分布**，共现对覆盖的恰是误合并最少的区域。
> 另发现共现对本身混入 6.3% 的同一人（多尺度重复框），并由此查清了 fm 指标 71% 的分子来自"正确合并"。
> **本节保留原始构想作为记录；修订后的方案见 §2.9。**

### 2.1 卖点

**无身份标签，也能给"跨机位误合并率"一个有限样本上界，并据此选工作点。**

这句话之所以站得住，是因为我们手里有一批**标签免费但身份确定**的负样本：同一机位、同一帧里同时出现的两条轨迹，必定是不同的人。它们不是"猜的负样本"，是几何事实。

> 实测修正：这条几何事实有两个漏洞——①同一个人的全身框与头部框会被分成两条轨（占共现对 2.3~6.3%），②"同帧共现"这个筛选条件会挑走更容易分开的对。

### 2.2 研究问题

- RQ1：以同帧共现对作为校准集，能否用保形/风险控制方法（如 Learn-Then-Test）对误合并率给出 $P(\mathrm{FM} \le \alpha) \ge 1-\delta$ 的保证？
- RQ2：共现对上的误合并率，是否为**全总体**不同人对上误合并率的**保守上界**？（若是，"校准集上的预算"才能推出"部署上的预算"）
- RQ3：跨天分有人流密度漂移，交换性假设失效时，按天重校准能否恢复保证？

### 2.3 方法四步

1. **构造校准集**：同机位同帧共现 ≥5 帧的轨迹对（现有 `cooc_pairs` 口径），全部为确定负样本。
2. **风险控制**：对候选阈值 θ 网格，统计校准集上的误合并数；用 LTT 的固定序列检验，取满足上界的最小 θ（等价于"在风险预算内最大化覆盖率"）。
3. **保守性验证**：从图库真值里抽随机不同人对，比较两条误合并率曲线。若共现曲线恒在上方，则校准集预算是保守的。
4. **漂移应对**：按天独立校准，报告跨天违约率；与"用前一天校准、次日部署"对照。

### 2.4 为什么这是正向的，而不是把负结果换个壳

负结果说的是"现有的选择器缺一项、且评估集在漂"。正向方法给的是"补上这一项，并且这一项**可以被证明**"。两者的关系是诊断与处方，不是同一篇文章换个标题。主稿与 E21 都不含任何风险保证。

### 2.5 证据现状

| 项 | 状态 |
|---|---|
| 负样本规模与质量 | ✅ 3178 对，三天分列 1252/725/1201；cos 中位 0.510–0.551；**cos ≥ 0.95 的 0 对** |
| 每 θ 的合并计数 | ✅ `curve.csv` 已含 42 配置 × 63 个 θ 点的 `fm` 与 `evaluable` |
| 预算约束下的工作点 | ✅ 1012 上已实测 `--thr-out 0.20 --fm-budget 0.0125` → cov 0.655 / same 0.907 / fm 12 对 |
| 保守性（RQ2） | ❌ **已测，不成立**——见 §2.9 |
| 漂移（RQ3） | △ 有三天数据与"跨天 \(fm\) 不可比"的实测（人流密度），但没有做过"按天校准 vs 跨天迁移"的对照 |

### 2.6 最小可行实验（按顺序）

1. 给 `d7_sweep` 加一个指标：在同一批 θ 上同时算"共现对误合并率"与"真值随机不同人对误合并率"。**半天**。
2. 在 1012 上跑通两条曲线，判定保守性方向。若共现曲线更低（即更容易），P1 的核心论点要改写——这是**先验风险**，必须先测。
3. 三天 E21 上做"按天校准 / 跨天迁移"对照，得出漂移下的违约率。
4. 与三条基线比：固定 θ=1.85、网格搜索最小 fm、现有 `pick`（只约束 `same`）。

### 2.7 与主稿的边界（必须写清）

主稿已含"camera-aware 两级聚类"与"label-free 选点规则"。P1 的 delta 只有两点：**①把合并率写成带保证的约束；②给出校准集的保守性证据**。若这两点不做，P1 就是主稿的一节，不能独立成篇。

### 2.8 目标期刊

方法向：*Pattern Recognition Letters* / *Computer Vision and Image Understanding* / *Machine Vision and Applications*；会议向：WACV、AVSS。若强调"部署可信"，*Journal of Imaging* 或 *Sensors* 也可，但审稿人会更看重端到端。

### 2.9 ★ 实测结果与修订方案（2026-11-09）

完整证据：`docs/p1-conservative-check-2026-11-09.md`。数据为 1012 四机位（唯一同时具备身份真值与同步检测的数据集）。

**判定（RQ2 的答案）：不成立。**

| 目标风险 | 校准集估计 | 真值实测 | 关系 |
|---|---:|---:|---|
| 跨机位误合并 | 0.419% | 0.089% | 保守 **14×** |
| 同机位误合并 | 0.419% | 0.917% | **乐观 2.5×**（条件口径 0.39×，0/63 个 θ 反向） |
| 全局误合并 | 1.250% | 0.278% | 保守，但覆盖的只是风险的 7.3% |

误合并构成：同机位异时 **69.1%** ｜ 跨机位 23.6% ｜ 同帧同时在场 **7.3%**。

**根因不是"上界不够紧"，是校准集与目标风险不同分布。**

**修订方案 P1′（三步，均未执行）：**

1. **清洗校准集**（成本最低、收益确定）。用「框完全包含 ∧ 面积比 0.2–0.6」这个**无标签**信号剔除多尺度重复对。1012 上该信号在同一身份对命中 54.9%、在不同身份对误伤 0.2%（相差 260 倍）；E21 上共现对中有 2.32% 命中。清洗后共现集纯度 93.7% → 约 99.8%，**fm 报告值也才有意义**。
2. **缩小宣称范围**。不再声称全局上界，改为：共现对给出的是**同帧同机位**风险的上界，且需乘 2.5 倍修正因子（或直接用 `same_noncooc` 的无偏估计——但那要真值）。这会显著降低论文的宣称强度，但结论站得住。
3. **另找异时/跨机位的负样本**。候选与现状：
   - 跨机位时间互斥（同一时刻不能在两处）——**当前数据不可用**：四段帧号不同步，"同一人跨机位重叠 12.5%" 与 "不同人 11.3%" 几乎相等；
   - 不同日期的同机位同位置——需假设无人连续多日同装，太弱；
   - 机位间可见性图——那是正约束，不是负样本。
   **目前没有现成可用的第三类负样本。**

**对选题的影响。** 第 3 步是死结：P1 若要保住"风险受控"的卖点，必须先解决"异时同机位"（69%）的负样本来源。现有数据做不到。**两条出路**：

- **降级为"负样本的构造与审计"论文**：主贡献改为"共现约束作为负样本的纯度有多高、偏在哪里、如何清洗"，实证完整、结论可靠，但新颖度与冲击力都降一档（更像一篇 datasets/evaluation 论文）。
- **换数据**：找一批多机位**真正时间同步**（同一 NTP 时钟、同一录制起点）的录像。有了它，跨机位时间互斥成立，69% + 24% 的负样本都能构造，P1 原方案恢复可行。这是唯一能保住原卖点的路径，代价是重新采集或申请数据。

## 3 P2：同帧互斥作为硬约束 + 机位拓扑自动推断

### 3.1 卖点

**在多机位不重叠的场景里，"同一时刻同时出现"就是一条免费的 must-not-link 约束；把它做进聚类，顺带把机位拓扑（哪些机位视野可能重叠）也推断出来。**

### 3.2 证据现状

- ✅ 同帧共现硬约束在 323 机位上**剔除 11 条"同帧同时出现却被连在一起"的误连**（真实缺陷，纯收益；与短 gap 放宽合并后净 −7）。
- ✅ 现有 camera-aware 聚类对同机位子簇强制 `FORBID = 2.0`，已经是这条约束的一个特例实现。
- ✅ 3178 对负样本中 cos ≥ 0.95 的为 **0**，说明"共现 ⇒ 不同人"在这批数据上与外观判断高度一致（意味着约束不是在与强证据对抗）。
- ❌ 缺公开集验证。MARS 的 tracklet 有摄像机号与帧数，但**本仓库的真值表没有起始帧**，无法直接导出同帧共现；需取 MARS 官方 `tracks_*_info` 或改用 CityFlow/AI City。

### 3.3 方法要点

1. 由"同机位同帧重叠"生成 must-not-link 约束图；
2. 由"跨机位共现统计"推断机位对是否可能重叠（若某对机位从未在同一时刻出现同一人，且共现分布接近独立，则判为不重叠）；
3. 在不重叠机位之间允许更松的合并阈值（因为不存在同帧互斥的可能），在可能重叠的机位之间收紧——**阈值按机位对自适应**，而不是全局一个数。

第 3 点是真正的新意：我们已经有证据表明全局单一 `thr_out` 两头不讨好（E21：0.25 偏松、0.20 在 1012 上又踩线）。

### 3.4 风险

若审稿人认为"同帧互斥"过于显然，需要靠**消融 + 公开集**把它撑成一等方法；否则会被判为工程 trick。

## 4 P3：长时段跨机位拼接

### 4.1 卖点

35 min 连续素材、6 机位、1779 条轨迹，拼成 **1273 个实体 / 134 条跨机位边 / 89 条身份链**，并给出两条判据的消融。

### 4.2 已有消融

| 判据 | 作用 | 实测 |
|---|---|---|
| 同帧共现硬约束 | 排除"同帧同时出现"的候选 | 305 排除 44 候选；323 剔除 11 条误连 |
| 短 gap 放宽 | gap ≤ 20 s 且 cos ≥ 0.90、pe ≤ 0.25、scale ∈ [0.80, 1.25] | 305 链接 117→121；合计实体 1271→1273 |

### 4.3 最大缺口

**跨机位身份链没有真值。** 现在能说的只有"结构合理"（阈值 0.65 是按结构选的，不是按精度校准的）。要做成论文，必须有 ≥200 条链的人工审计（是同人 / 不同人 / 无法判断），否则只能写成系统报告。

### 4.4 定位

适合应用/系统类刊（*Sensors*、*Journal of Real-Time Image Processing*、*IEEE Access*）或 AVSS 的 system track。不要投方法刊。

## 5 P4：合并框拒收——把 ID 切换的根因拦在检测层

### 5.1 卖点

我们的诊断已经定位到根因不在拼接层：两人靠近时检测器输出**合并大框**（h 451→862），ByteTrack 在匹配阈值 0.8 下 IoU 只有 0.71，于是开新轨；拼接层因 `pe > 0.08` 再拒一次。**拼接层最多只能挽回 6%。**

正向方法：在检测后加一条"合并框"判据（高度突增 / 长宽比突变 / 掩膜包含率），拒收或拆分后再进跟踪。

### 5.2 缺口

**必须重跑检测**。成本：GPU 数小时，或 CPU ≈30 h。目前只有"拒收后应该更好"的推断，没有实测。

### 5.3 建议

不要单独成篇。作为 P1 或 P3 的一节（"上游误差对下游的影响"）更划算——单独成篇需要一个完整的检测侧基准，我们没有。

## 6 明确不建议的方向

- **训练更好的全局 ReID 表征**：没有训练管线、没有大规模标注、没有新数据。硬做等于用两周复现 OSNet，审稿人一眼看穿。
- **非人/影子门控单独成篇**：效果真实（计数 MAE 1.279 vs 1.344）但体量不够，作为 P1/P3 的组件更合适。
- **"多机位一致性"类自监督预训练**：需要重训编码器，同第一条。

## 7 组合与优先级

**若只能投一篇** → P1。数据齐、卖点硬、与主稿互补且能互相引用。

**若要做两篇** → P1（方法）+ P3（系统）。P3 给 P1 提供"真实长时段部署"的场景证据，P1 给 P3 提供"工作点可认证"的方法；两篇互为引用，不重复。

**若想冲更好的方法刊** → P1 + P2 合并成一篇："约束与校准"双管：物理约束（同帧互斥）+ 统计约束（风险预算）。但这要求 P2 先在公开集上站住，周期至少多一个月。

**依赖顺序**（只写先后，不承诺工期）：

```
P1 第一步（保守性检验）──┬─→ P1 完整实验 → 投稿
                        └─→ 若保守性不成立，改写成"共现负样本的偏差分析"，降级为短文
P2（MARS 帧区间 → 约束聚类 → 公开集对照）──→ 可与 P1 合并
P3（≥200 链人工审计）──→ 系统论文
P4（重跑检测）──→ 并入 P1/P3 的一节
```

## 8 三条红线

1. **P1 的保证只能声称在"共现负样本分布"上有效**，除非第 2.6 步的保守性检验通过。否则就是把一个校准集上的界说成总体界——这正是我们刚在主稿里挑出来的那类问题。
2. **P3 不得在无人工审计的情况下声称"拼对了"**。现在只有结构合理性证据。
3. **与主稿的增量必须逐条写清**（P1 见 2.7；P2 的 delta 是"硬约束 + 机位对自适应阈值"；P3 的 delta 是"长时段 + 双判据消融"）。主稿已被要求补五处披露，新稿不能重复同样的口径问题。
