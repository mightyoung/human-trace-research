## 3. C0 门审计（门级）

- **强支持门**（visit 支撑 ≥3 且与簇匹配）：305 exit×3（sup 13/7/3）、305 entry×2（17/12）、316 exit×3（14/15/10）、316 entry×2（15/16）、318 出口（32）入口（21）、323 exit×2（61/9）、323 entry×3（54/15/4）、320 两门（4/7）、343 exit（7）。
- **偏差修正建议**：
  - **318 exit**：C0 门 `[0.316,0.265]` vs visit 门户质心 `[0.409,0.215]`——门中心偏 0.105（门仍落在大簇之内侧翼）；建议把门中心校正为 visit 质心（或门半径按 v2 簇半径 0.19 放宽）。
  - **318 entry**：C0 门只覆盖次簇（n=21），主导簇 `[0.404,0.175] n=45` 无门；建议增加第二个 entry 门。
- **弱支持门**（visit 支撑 <3）：无（各 C0 门在 10 分钟窗口内均有 ≥3 事件）；此前 visit 报告称"gates 半径 0.15 太宽、几乎所有位置都能命中"——本实验用 0.10 半径后 C0 覆盖率 50.8%，**推翻"过宽无区分"的担忧方向**：真问题不是门太宽，而是**门太少/位置偏移**。
- 附：323 exit 主簇 `[0.485,0.264] n=70` 同时被 3 条被否决边的事件映射（真2/假3）——如前注，假边计数不构成负证据（热区实体多，被否决的只是配对）；该簇仍是 C0 门1 所在地 + 61 事件覆盖。

## 6. 建议（供 H2 与生产化参考）

1. **门户集 v2 就绪，可作为 H2 对照实验的门户组件**（数据驱动、覆盖 85.2%）；与 C0 门**并列存放**，先不直接替换生产。
2. **343 先行试点**：entry 覆盖 0%→52.3% 是本次最大收益；配合 §4 的三个新门户 + 底边缘候补。
3. **门户质量分**：把「真/假边支撑计数」（本产物 `edge_support`）并入门户元数据——它已在 318/316/305/343 上给出与人类判定一致的排序。
4. **下一步实验（未做）**：①更多时段数据复核簇稳定性（跨 session）；②dir 朝向参与门户分类（border/portal/interior 自动判定）；③将 v2 门户接入 relay 的 dt_visit 证据链重估真假边判别（当前 visit 报告结论为"证据不足"，根因之一正是门户噪声）。
5. 纪律：本产物为**只读研究产物**；替换/合并进 c0 或 relay 需按发布门槛单独立项。

## 7. 局限

- 单时段（synced-10min）；visit 事件含轨迹碎片（343 entry 噪声 48%）；
- eps 中等敏感（0.05→49、0.08→29 簇），已给敏感性表，未做自动选参；
- dir 未参与聚类（仅统计）；320（球机）事件过少（13/13）结论弱。
