## 2 两次冒烟

### 2.1 `H_qry_323`（323 查询段：卷 527，offset 0 s，stride 5）

| 阶段 | 结果 |
|---|---|
| detect | 400 采样帧（= 2000 源帧 = 80 s），rc=0，**110 s** |

**这条是发现，不是故障**：该 80 s 内一个框都没有。密度探针（`docs/material-density-2026-10-20.json`）独立支持同一结论——320 在 12:58 与 13:14 均 0 人、323 在 13:03 为 0 人。

### 2.2 `H_gal_305_p1`（305 图库第一片：卷 529，offset 4680 s，stride 10）

| 阶段 | 结果 |
|---|---|
| detect | 400 采样帧（= 4000 源帧 = 160 s），rc=0，约 **240 s**（深偏移 seek 占大头） |
| split | **a=286 / b=297 条轨迹** |
| encode | rc=0，约 **120 s**；产出 `_emb_a.npz` / `_emb_b.npz`，512 维 |

编码键为 `{seg}#{tid}`（如 `H_gal_305_p1#17`）。这一点在本设计里是必要的：305 与 320 的图库各由两卷拼成，同一卷内的 track id 会从 0 重新计数，键必须带段名前缀才不会撞号。

**结论：全链打通**（检测 → 去重 → 切 a/b → 编码），且产物命名与前缀符合下游 `session_selector_v1` 的读取方式。

## 3 修掉的三个真问题（都是冒烟才暴露的）

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | `ModuleNotFoundError: ultralytics` | 脚本没设 `PYTHONPATH`，生产脚本 `run_yolo_u1.sh` 第 11–14 行有设 | 加 `PYTHONPATH=$ROOT/pylibs` |
| 2 | 设了仍报同一个错 | Git Bash 的 `ROOT` 是 `/d/...`（MSYS 风格），Windows 的 Python 不认 | 用 `cygpath -m` 转成 `D:/...` |
| 3 | `--only` 只对检测生效，去重仍跑全量片段 | `SEGS` 由全量 `PIECES` 拼成 | `--only` 时同步收缩 `SEGS` |
