# 人员属性标注（独立索引产品路线 · 第一步）

> 日期：2026-11-10 · 状态：标注任务已上线，等待人工标注
> 入口：`http://127.0.0.1:8010/#/annotate` → 页签「人员属性标注」

## 一、这一步要回答的问题

竞品界面那种「14 个属性字段 + 按属性检索人员」的能力，能不能用现有素材做出来、代价多大。
本步只做**数据侧**：攒一批人工标注，用来给任何候选方案（PAR 分类器 / EmbeddingGemma 2 零样本 / VLM 结构化输出）算 mA 做同口径比较。

**没有标注就无法判断精度**，所有"能不能做"的讨论都必须落在这批数据上。

## 二、样本口径

| 项 | 取值 | 理由 |
|---|---|---|
| 总数 | 136 条 | 6 机位 × 框高三档 × 8 条，够算分层 mA |
| 分层 | 机位 × 框高（S<80 / M 80–240 / L≥240 px） | 属性可判性主要由**框高**决定，必须分层报告，混算会互相掩盖 |
| 格内去重 | 优先不同实体（`entities.json`） | 同一人标多次是浪费 |
| 代表帧 | 框高 ≥0.9×轨内最大值 的帧中、最接近轨迹中点的那帧 | 与人脸锚点同策略，取最清楚且不贴轨迹边缘 |
| 剔除 | 框太小 336 / 横长误检 99 / 倒影 28 = **463 条** | 见下节，这一步直接决定标注是否有意义 |

### ★★ 决定性教训：**不能用 960×540 代理视频做属性标注**

`webapp/backend/data/media/*.mp4` 是代理（960×540），而检测坐标在原始坐标系（2560×1440 / 1920×1080）。
按 `sx=0.375` 换算后，**有效像素只剩原始的 14%**（0.375²）。第一版裁剪出来的人形全是马赛克，`h=75px` 的框实际只有 28px 像素。

改用 `media-resource/multi-cemra/long-35min/{cam}_long35.mp4`（原始卷），已验证与代理**逐帧对齐**（同帧号缩放到同尺寸，灰度均差 2–5，仅编码噪声）。重做后 S 档从"不可判"变为"多数可判"。

## 三、裁剪口径（`tmp/attr/build_items.py`）

```
窗高 = bh × 1.2          窗宽 = max(bw × 1.6, 窗高 × 0.6)    # 人形瘦高，横向补上下文
scale = min(320/窗宽, 520/窗高, 5.0)                          # 放大上限 5×，再高就是马赛克
输出 = 按比例缩放的窗口，宽度不足 132px 时横向补白
```

**输出尺寸不固定**（站立全身窄高、坐姿上半身接近方形），因为把方的人硬塞进 3:5 画布会让画面很小。缩略图由 CSS `object-fit` 统一。

## 四、字段集（11 项，与竞品界面口径对齐）

上衣颜色 / 下装颜色 / 上衣类型 / 下装类型 / 性别 / 年龄段 / 戴眼镜 / 戴口罩 / 戴帽子 / 背包 / 拎东西

**刻意去掉的三项**：
- **年龄精确值**：人脸年龄回归 MAE 通常 4–6 岁，远景更差，"年龄 25"这类数字不可信
- **运动方向**：属轨迹层信息，用首尾点位移算即可，不该走视觉
- **通道 / 抓拍时间**：元数据，不是图像属性

**空值 = 判不了**，不写进记录。留空本身是有用信息，统计里单独算「可判率」。

跳过原因分四类：`框太小 / 不是人 / 模糊 / 遮挡`。其中「不是人」的占比直接量化检测层假框率。

## 五、实现

| 位置 | 内容 |
|---|---|
| `tmp/attr/build_items.py` | 抽样 + 从原始卷裁剪，产出 `attr_items.json` + `attr_crops/*.jpg` |
| `tmp/attr/contact_sheet.py` | 按档位拼图，用于批量目检裁剪质量 |
| `webapp/backend/main.py` | `/api/attr/{schema,items,label,stats,export}` + `/attr_crops/{name}` |
| `webapp/frontend/src/components/AttrAnnotator.vue` | 标注界面（schema 驱动，字段改动只改后端常量） |
| `webapp/frontend/src/views/AnnotateView.vue` | 第 4 个页签「人员属性标注」 |
| 存储 | `data/attr_labels.json`（**独立文件，不碰 labels.json / GIL**） |

交互：点选项即存（400ms 合并提交），`J/K` 切换、`空格` 下一条、`X` 框太小。列表用**冻结快照**——标注后条目不会立刻从「待标注」消失，否则选中项会跳。

## 六、两个环境坑

1. **端口 8000 被本机 C-Lodop 打印服务占用**。Windows 允许重复绑定，浏览器请求会随机落到对方，表现为页面变成"欢迎使用 C-Lodop 打印服务系统"。改用 **8010**。
2. **`vite build` 会 `emptyOutDir` 清空 `dist/`**，而 `dist/` 里有非构建产物（`faces/`、`gil_owner*.json`、`s6b_thumbs/`）。改为 `--outDir dist_build` 再只拷 `index.html` + `assets/`。

## 七、下一步（标注完成后）

1. 算**每字段 mA 与可判率**，按框高档分层 → 得到「机位 × 档位 × 属性」可用性矩阵
2. 两条基线同口径对比：开源 PAR 多标签分类器 vs EmbeddingGemma 2 图文零样本
3. 判定门槛：**mA ≥ 0.80** 进生产过滤，0.65–0.80 只做粗排，<0.65 弃用
4. 属性**不参与身份判定**，只做排除（跨机位属性矛盾 → 合并错了）

导出：页面右上「导出 CSV」，或 `GET /api/attr/export?fmt=csv`。
