Manageable. Reading the main path in order.

Patching the encoder with an opt-in flag (default keeps the frozen baseline bit-identical), and making v2 use correct RGB.

我又看了一遍源码，主要是从检测到评估的主链路、聚类和打分、评估脚本，以及网页控制台。除了上次说的跟踪参数问题，还有一个影响所有结果的确定性 bug：**主链路编码时把颜色通道喂反了**。另外有 4 个中等问题和 1 个隐私暴露问题。

## 按严重程度排序

**1. 高：OSNet 输入的颜色通道是反的（代码事实已确认）**
- 主链路的编码脚本 `encode_1012_osnet_seq.py` 直接把 OpenCV 读出的 BGR 裁图交给 torchreid。我下载了 torchreid 0.2.5 源码核对过：它把 numpy 数组当 RGB 处理，不做转换。所以红蓝通道是对调的。
- 生产链路 `run_yolo_u1.sh` → `1012_yolo8_dd_emb` 用的就是这个脚本。另有 3 个脚本（`encode_clean_splits`、`osnet_vs_d3b_eval`、`modal_case_encode`）做了转换，所以拿它们和基线比的实验，两边颜色口径不一样，结论有干扰。
- 实测（公开数据 MOT17-04，单机位）：
  - OSNet-AIN 改成正确的 RGB 后，不同人之间的平均相似度从 0.621 降到 0.553，裁图级 AUC 从 0.963 升到 0.977，前后半轨迹互查 Rank-1 从 0.946 升到 0.973。
  - 小模型 osnet_x0_25 改不改没有差别。
  - 你们跨机位场景（颜色是主要线索）的影响**还没测**。
- 修改：我加了一个 `--rgb` 参数，默认关闭，所以冻结基线仍能逐位复现。打开后只需重新编码 8 段（检测结果可以复用），聚类阈值和 θ 都要重新标定。

**2. 中：部署配置和你们自己的结论相反（代码事实）**
- README 和 `freeze_baseline` 都写明"不要加 veto_dmax 0.30"（加了之后判对数少 28 条，p<1e-4）。
- 但 `configs/selector_deploy.json` 里 veto 0.30 仍然开着，`eval_det_switch.py` 和 `export_paper_ledger.py` 都会读这个值。谁用这份配置跑，就会拿到较差的版本。
- 建议把它改成 null，veto 只留在实验配置里。

**3. 中：重跑脚本复现不了基线（代码事实，文档已知但脚本没改）**
- `run_yolo_u1.sh` 没有显式写 `--iou 0.7`，而 `yolo_track_det.py` 的默认值已经改成了 0.5。照脚本重跑，得到的不是存档的基线。
- 另外 6 机位数据用的是 0.5，4 机位基线是 0.7，两套数据之间的对比混进了这个差异。

**4. 中：评估口径偏向基线（事实 + 量化）**
- 图库逐成员标注是从基线（249 条）和 veto0.30（162 条）命中的簇里抽的。其他配置新形成的簇没有标注，查询落进去就记为 U；而 C/229 和 McNemar 检验都把 U 当作错。
- 例如 D_split0.20_veto0.30 有 5 条查询因为"簇里没有已标成员"被记成错，基线是 0 条。这一项对比对它不公平，最多差 5 条。
- 建议把这类 U 单独列出，或者补标这几个簇。

**5. 中：参数都是在测试集上选的（事实，需要在论文里说明）**
- thr_in/thr_out 的平台和 θ 的自动选点，都是在查询（测试）集的无标签指标上扫出来的，精度又在同一个测试集上报告。
- 查询侧用的是"全部查询的平均特征"做对齐，实时部署时拿不到这个值。
- 这不是标签泄漏，但要披露。建议用 6 机位数据做留出验证。

**6. 低到中：误合并指标被重复框抬高（事实来自你们的文档）**
- 跟踪后的 IoU 0.5 去重删不掉"头框套在身体框里"的重复（两者 IoU 只有约 0.1）。
- 共现规则会把这类同一个人的两条轨迹当成"铁定不同人"。你们文档里 14 对误合并有 5 对就是这种情况。v2 的跟踪前掩膜去重可以解决。

**7. 低：潜在 bug，目前没触发**
- 编码脚本加 `--save-crops` 时，检测置信度固定从旧检测器（DINO 时期）的 `1012_final` 文件按（帧号, 轨迹号）回查。如果换成 YOLO 的 a/b 分片，轨迹号对不上，查到的是别人的置信度。
- 现在 `run_1012_crops_all.sh` 用的是同源目录，没有触发。

**8. 隐私：网页控制台在局域网裸奔（代码事实）**
- 服务监听 `0.0.0.0:8099`（文档里的入口是 192.168.11.16），没有任何登录认证，CORS 允许所有来源。
- 它直接提供原始监控视频（`/media`）、人像缩略图和人脸标注接口，POST 请求还能改标注和配置。这和你们 PRIVACY.md 的要求冲突。
- 建议至少改成只监听本机（127.0.0.1）再用 SSH 隧道访问，或者加上基本认证。
