# query 独立性与置信区间核查（2026-10-23）

> **结论一（修正 A 方案）**：229 条可评估 query 只来自 **24 个身份组**（中位 8 条/组，female3 一人占 33 条）。
> 按身份 cluster bootstrap，C/229 = 51.5% 的 95% CI 是 **[31.4%, 71.6%]**（宽 40.2pp），
> 而非按 query 计算的 [45.0%, 58.1%]（宽 13.1pp）——**真实不确定度被低估 3.1 倍**。
> 且模拟显示：**身份组数不变时，query 数扩 1.5/2/3 倍，CI 宽度纹丝不动（39.9→40.3/39.7/41.6pp）**。
> → **扩 test 时长无法提升绝对精度的可信度**，A 方案的立项理由不成立。
>
> **结论二（已有结论不受影响）**：veto（C_dmax0.30）vs baseline 的配对比较里，29 条丢失中 16 条来自 female3、6 条来自 male3，
> 只涉及 **7 个身份**。按身份 cluster bootstrap 重采样，净值 95% CI = **[−59, −7]**（不跨 0），单侧 p < 0.0001。
> → **「veto 是纯负收益」在聚类校正后依然稳健**，D4 的主结论成立。

## 1. 为什么要查这个

A 方案（test 从 15min 扩到 45min）的立项理由是"把 95% CI 从 ±6.5pp 压到 ±3.7pp"，
这个估算默认 229 条 query 相互独立。但在同一段视频里，同一个人会走出多条轨迹
（进出画面、被遮挡后重连），这些轨迹共享外观、姿态、光照，**不是独立观测**。

## 2. 事实：query 高度集中

| 口径 | 数值 |
|---|---|
| 可评估 query | 229 |
| 有身份 query | 207 |
| **涉及身份** | **23 个**（+1 组 unknown） |
| 每条身份对应 query 数（中位 / 平均 / 最大） | 8 / 9.0 / **33（female3）** |
| 已判决 138 条涉及身份 | 19 个（female3 占 33 条 = 24%） |

新段 `318_test_534b` 同样集中：80 条 query 按外观余弦（thr 0.90）连通分量聚类为 **45 组**，
最大一组 13 条（thr 0.85 时 16 条）——一人一天来回走会被切成十几条轨迹。

## 3. 主结果：两种 CI

以 `A_baseline` 的逐条判决（C 118 / W 6 / U 14 / 拒识 91）为基础：

| 方法 | 95% CI | 宽度 |
|---|---|---|
| bootstrap 重采样 **query** | [45.0%, 58.1%] | 13.1pp |
| bootstrap 重采样 **身份**（24 组） | **[31.4%, 71.6%]** | **40.2pp** |

方差的主项是"人与人之间的差异"（有人全对、有人全错），不是"同一个人的 query 数"。
解析计算的设计效应 DEFF ≈ 229/24 ≈ 10。

**扩量的模拟**（保持 24 个身份的率不变，把每人的 query 数按倍数复制后重采样）：

| 总 query 规模 | CI 宽度 |
|---|---|
| 229（现状） | 39.9pp |
| ×1.5 | 40.3pp |
| ×2.0 | 39.7pp |
| ×3.0 | 41.6pp |

差异全在蒙特卡洛噪声内。**增加同一批人的观测次数，不改变"这批人整体表现"的不确定性。**

## 4. 对已有结论的检验（配对比较）

配对比较（同一批 query，换配置）与绝对水平不同：它消掉了"人"的主效应。

veto 的 29 条丢失按身份分布：

| 身份 | 丢失 | 身份 | 丢失 |
|---|---|---|---|
| female3 | 16 | female2 | 3 |
| male3 | 6 | male9 / male12 / male20 | 各 1 |
| female1 | 1（同时新增 1） | — | — |

只有 7 个身份参与。按身份重采样 5000 次，净值（gain−loss）95% CI = **[−59, −7]**，单侧 p < 0.0001。
即使把"female3 这一个人贡献了 55% 的损失"这一最不利情形计入采样波动，**veto 仍然显著更差**。

> 附注：`compare.csv` 里 C_dmax0.30 的 `ci_lo/ci_hi = [0.3319, 0.4541]` 是按 query 算的朴素区间，同样低估了宽度；
> 该列在论文中不能直接引用，应换成本文的 cluster-robust 区间。

## 5. 结论与影响

1. **A 方案（扩 test 时长）的收益需要撤回**：它能让配对比较多几条证据，但对"51.5% 这个数有多可信"毫无帮助。
   已投入的 318 扩展段（80 条 query）仍可用于配对比较与 per-camera 分层，但不应再按"收窄 CI"的理由扩满四机位。
2. **要让绝对精度可信，只能增加身份数**——即让更多"人"进入可评估范围。
   这正好回到 B 的结论：图库标注覆盖 257/579 = 44%，是身份数的上限。
3. **论文写法必须改**：`C/229 = 0.515` 应写成 `0.515 (95% CI 0.314–0.716, cluster bootstrap over 24 identities)`，
   并在方法节说明 query 非独立、按 person 聚类。同理，任何"改进 X pp"的主张都要用配对 + 聚类校正的检验。
4. **D4 主结论不受影响**：veto 有害、评价单位决定结论（0.616 vs 0.952）、纯度信号≠有害性信号，均基于配对或簇级比较。
