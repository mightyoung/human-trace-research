**过程中有过一次自我更正，必须记下来**：原始 YOLO（未去重）的 fm 是 3.25%，一度越过 3% 预算，

fm 降到 0.75%，覆盖只掉 0.9pp。

## 5. 三个反证检查（确认增益不是假象）

**5.1 长度对齐（按轨迹观测数过滤后再算，指标定义不变）**

| 观测数下限 | 基线 cov / fm | YOLO cov / fm |
|---|---|---|
| 0 | 0.423 / 1.96% | 0.577 / 3.25% |
| ≥10 | 0.430 / 2.09% | 0.726 / 4.96% |
| ≥20 | 0.628 / 3.69% | 0.757 / 5.30% |
| ≥30 | 0.600 / 3.54% | 0.761 / 5.15% |

长度对齐后差距不收敛（+12.9pp @≥20），**说明不像试点段那样纯是碎轨迹效应**；但 fm 差距同步放大。

**5.2 门槛收紧**：见表 §3。YOLO 的 fm 对门槛不敏感，基线高度敏感（8→2 对）。
事后查明这个"不敏感"来自同帧重复框（§6.5），不是身份混淆更严重。

**5.3 图库构成**：YOLO 图库轨迹 610 vs 基线 1032，簇数 107 vs 132。两者轨迹总体不可配对（同帧 id 空间不同），
`common` 口径只剩 97 条轨迹、evaluable <100，无法用。
→ **覆盖差里有多少来自检测质量、多少来自图库变粗，本次无法分离。这是 U2 必须先做人工真值对的原因。**

## 6.5 误合并审计：3.25% 里有 18/21 是「一个人两个框」

把 same≥0.95 选中的 21 对逐对导出（`fm_pairs_yolo_same95.csv`），并画共现帧拼图（`fm_audit/audit_1..3.jpg`）：

| 观察 | 数值 | 含义 |
|---|---|---|
| 两框 IoU ≥0.45 的对 | **18/21**（中位 0.63） | 两框压在同一个人身上 |
| 两框中心距 / 框宽 | 中位 **0.15** | 同一个身体，不是相邻两人 |
| 低叠合对（IoU≤0.10） | 3 对，全在 323 | 323 玻璃场景的真误合并 |

**同帧重复框率**（同帧内两框 IoU≥0.5 的帧占比）：

| 段 | DINO | YOLO |
|---|---|---|
| 305_test | 0.0% | **22.0%** |
| 318_test | 0.0% | 10.6% |
| 320_test | 0.0% | 7.2% |
| 323_test | 0.4% | 3.5% |
| 305_train | 0.1% | 26.4% |

根因：`yolo_track_det.py` 用 `iou=0.7` 做 NMS，同一个人的「头」和「全身」两个提案 IoU 约 0.55，
低于 0.7 都不会被抑制。两条框各自成轨迹 → 同帧共现 → 合并后被计成误合并，但身份判断其实是对的。

**去重消融**（同帧按 conf 贪心保留，IoU≥0.5 的低分框丢弃，track id 不变）：

| | 覆盖 | same | fm | 误合并对数 | 去掉框占比 |
|---|---|---|---|---|---|
| YOLO 原始 | 0.577 | 0.906 | 3.25% | 31/955 | — |
| **YOLO 去重** | 0.568 | 0.908 | **0.75%** | **6/805** | 3.8% |
| 基线（同一门槛） | 0.423 | 0.903 | 1.96% | 8/408 | — |

去重后残留 6 对，其中 5 对 IoU≤0.10（真·两人被并），4 对集中在 323。
**基线自己的 2 对也在 323，IoU 0.00 / 0.04**（`fm_pairs_baseline_same95.csv` + `fm_audit_base/audit_1.jpg` 已目检确认是两个人）。

→ 校正后的"真误合并率"：**YOLO 去重 6/805 = 0.75% vs 基线 8/408 = 1.96%**；
same≥0.95 口径下 3/699 = 0.43% vs 2/349 = 0.57%。**两个口径下 YOLO 都不比基线差。**

**注意**：去重是检测后处理，与"把 NMS 的 iou 从 0.7 收到 0.5 重跑"不完全等价（跟踪关联会变）。
正式生产建议按后者重跑一次验证（约 2.5h），当前配置先用后处理版本。

## 7. 附带结论：U6（320 的 35% drop）已可解释

`320_train_514` 前 25 分钟画面内**确实无人**（目检 10min 帧为 08:13 的空办公区）：
- DINO 在该时段稳定输出 **1 框/帧**（≈300 框/300 采样帧）——幽灵框；
- YOLO 同段输出 **0 框**，直到 45 分钟才有真实人员出现（此后 600–780 框/5 分钟）。
- 该段门控 drop 43/122 = **35.2%**，与交接记录一致。

→ 320 的 drop 不是检测问题，也不该按"检测错误"处理；它是"空场时段 + DINO 幽灵框"叠加。
若切换 YOLO，该段 drop 率会自然趋零，U3 的重标可以直接用"drop 率是否接近 0"做验收。
