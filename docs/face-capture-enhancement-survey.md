# 人脸抓取与图像增强 —— 近邻研究报告

> 面向 human-count / multi-cemra 6 路固定机位场景的三个问题的调研
> 作者：AI 调研 | 日期：2026-10-14 | 状态：研究报告（未含项目实测，实验设计见 §5.4）

## 0. 结论先行（TL;DR）

三个问题的直接答案：

1. **清晰人脸抓取**：行业与标准均证实——监控单帧几乎永远不达标，正确做法是「**检测 → 跟踪 → 每人一条质量池 → 多帧/多机位优选**」。硬性门槛有国标锚点：可识别需**瞳距 ≥60px**（GB/T 31488-2015），检出可放宽到 **40px**（GA/T 1334），抓拍图宜 ≥80×80。本项目 1920/2560 宽画面中 5m 外人脸仅约 60px 宽，走廊远端约 30px → **必须靠多帧累积 + 跨机位联合选优**，且项目已有 freq/track/entity/gperson 四级结构可直接承载。
2. **逆光/反光/暗处的自动判断与处理**：判断做「**场景级 + 人脸 ROI 级**」两级诊断（亮度直方图双峰/熵/反射区域检测）；处理按四类场景分流（暗→低光增强 LLIE；逆光→自适应 gamma/Retinex 族；反光→单图反射分离；正常→直通）。★ **最重要的一条反直觉证据**：**逐帧实时增强会损害识别**（有研究实测双端增强导致精度 -33.71%，实时增强 F1 仅 +2.17%），而**离线/固化后增强稳定获益（+7.3~7.5%）**。→ 本项目的增强必须走「**证据固化路径（异步、对已选最优帧做）**」，不进逐帧主链。
3. **低清 → 高清用于识别**：三条路线——单帧盲复原（CodeFormer/GFPGAN）、超分（Real-ESRGAN 系）、**多帧聚合（推荐，监控场景天然有多帧）**。ONNX 均可行（CodeFormer 有公开导出脚本，4090 上 45~92ms/脸）。★ 红线：生成式修复存在「**身份幻觉**」（产出好看但不是本人）；修复图**不得进入身份判定主链**，只能作为与原始图成对存储的辅助证据，进入比对必须走同序列 A/B。

综合建议：三项能力统一挂到 GIL 的 **obs/visit/gperson 层**，产物 = 「**每人证据包**」（最佳原始图 + 增强图 + 修复图 + 质量分），身份判定主链不变。

## 2. 问题一：多类型固定机位下，抓取尽可能清晰的人脸

### 2.1 为什么"抓一帧"不够——数字锚点

| 指标 | 数值 | 来源 |
|---|---|---|
| 可识别条件（取证级）| 双眼瞳距 **≥60px** + 水平 ±30° / 俯仰 ±20° / 倾斜 ±45° | GB/T 31488-2015 §5.2 |
| 检出-识别放宽条件 | 瞳距 **≥40px** | 海康产品规格 / 地方反恐标准引用 GA/T 1334 |
| 抓拍图质量建议 | 人脸像素 **≥80×80** | 反恐怖防范管理 DB4401/T 10.38（引 GB/T 31488） |
| 商业相机抓拍逻辑 | 检测→抓取→**打分→选择**（"优选抓拍"输出分数最高帧；"快速抓拍"出所有帧） | 海康人脸抓拍摄像机产品文档 |

【推断】按本项目画面估算：1920px 宽、水平 FOV ~90° 时，5m 处人脸宽约 55~65px（勉强及格），走廊/茶水间远端 30px 左右（不合格）。→ **单帧抓取只能覆盖近场**，产出"每人可用脸"必须依赖时序与跨机位积累。

### 2.2 检测器选型（ONNX 部署友好，按本项目 Rust+ONNX 目标筛选）

| 模型 | 参数量 | WIDER Hard mAP | 关键点 | ONNX/部署 | 适用 |
|---|---|---|---|---|---|
| **YuNet** | 0.076M（1MB 权重内） | ~70.8%（本地复测 ~75%） | 5 点 | OpenCV 原生加载 | 起步/超轻量 |
| **SCRFD-2.5G_KPS** | 0.82M | 77.1% | 5 点 | ONNX Runtime（insightface 提供） | **推荐主选**（识别对齐需关键点） |
| SCRFD-500M | 0.57M | 68.5% | 无 | ONNX | 极限轻量（无关键点，需另配对齐） |
| RetinaFace-R50 | ~25-30M | 高（依赖额外训练数据） | 5 点 | ONNX | 小脸/遮挡最强，但重，CPU 数百 ms |

【事实】实测速度量级（引用不同来源）：YuNet 5.6ms / SCRFD 23ms / RetinaFace 25ms（M2 单张 450×450）；SCRFD/YuNet 在 640 输入下 CPU 推理均为十毫秒级。（来源见 §6）

### 2.3 质量评估（Face Image Quality Assessment, FIQA）——两层设计

**规则层（零依赖，先行）**，工程共识的评分因子：
- 清晰度：Laplacian 方差（工程阈值例：<100 丢弃）
- 尺寸：人脸框/瞳距（<80×80 或瞳距 <40px 丢弃）
- 姿态：关键点推算 yaw/pitch/roll（俯仰 >15° ~ ±20°、偏转 >30° 丢弃）
- 亮度：ROI 亮度均值 + 对比度（偏离均值 ±20% 视为异常）
- 遮挡：关键点缺失/置信度（>30% 遮挡丢弃；口罩可用"鼻尖-上唇/嘴角距离比 >0.7"启发式）
- 加权综合（工程常用 `0.4×清晰 + 0.3×姿态 + 0.2×遮挡 + 0.1×光照`）

**学习层（进阶可选）**，FIQA 家族横评结论：

| 方法 | 特点 | 备注 |
|---|---|---|
| SER-FIQ | 无训练（drop-out 方差） | 开箱可用，横评中鲁棒 |
| CR-FIQA | 学"相对可分性"，8 基准 4 识别模型下 SOTA | 需训练、依赖识别模型 |
| MagFace | **识别模型自身特征模长**即质量 | 不额外加模型，若引入 ArcFace 则白送 |
| 轻量 RF（CCTV 专用） | 106 点归一化关键点 + 随机森林，96.67% 准确 | 实地监控数据；质量过滤使 FRR 13.19%→0.04% |
| SDD-FIQA / IG-FIQA | 横评对照项 | — |

【纪律映射】本项目已验证过一条通用教训：「cos 只能排序不能阈值」（倒影与真人 cos 间隔 0.0002）。FIQA 同理——**跨样本"选优"用相对排序，单样本"准入"用绝对阈值，两者分开校准**，阈值一律 val 校准（沿用项目铁律）。

### 2.4 轨迹级质量池（多帧最优帧）——行业主流模式

- **Frigate 0.16**（2026-08 发布，31k Star 开源 NVR）：person 检测框内找人脸 → 对齐 → 嵌入比对；社区经验"正面照先可用，半侧面随后逐步可用"。
- **边缘多路流架构**（Voyager SDK 类）：每个 track ID 维护**姿态质量缓冲区**，新帧分数 > 池中最低分则替换；首批高质量 ROI 立即做初步识别，缓冲区满后批量精化；多帧识别结果**贝叶斯更新**累积置信度——"两个独立 70% 匹配 > 单个 90% 匹配"。
- 抓拍时机工程实践：连续抓 5 帧取质量最高；特征点稳定帧优先（变化量 < 阈值才抓）。

**本项目映射**：质量池天然挂载点 = `obs`（逐框）→ `frag`（S3 精化链）→ `gperson`。每层维护 Top-K 脸图 + 质量分，**零新增基础设施**。

### 2.5 多机位联合选优（本项目独有优势）

6 路非重叠机位 = 同一 gperson 有多个不同角度、不同光照的采样机会（如 343 电梯间正面 → 316 走廊侧后）。跨机位把脸图池**按 gperson 聚合选优**可实现「全楼最佳人脸」——这是单机位系统拿不到的增量，且直接复用现有 relay/gperson 结果。
注意：跨机位选优前置条件是**姿态门控**（背脸/大侧脸帧不得进入池）；320 球机若存在变焦/巡航行为，抓取参数需 per-cam 适配。

### 2.6 落地形态（GIL 扩展建议）

- 新表 `face_shot(shot_id, obs_id, cam, ts, bbox, kps_json, q_rule, q_fiq, is_best)`，复用「文件真相 + SQLite + numpy 缓存」三层结构；
- 每人证据包 = `best_shot`（+增强版 +修复版，见 §4）；
- webapp：可视化页加「人脸卡」视图（每人一张最佳脸 + 质量分 + 来源机位 + 时间）。

## 3. 问题二：逆光 / 反光 / 暗处的自动判断与处理

### 3.1 自动判断（场景诊断）——两级机制

**场景级（每机位每时段）**：
- 暗处：全局亮度均值低 + 低对比 + 高噪声估计；工程触发例：连续 5 帧熵值 <4.5 报警
- 逆光：直方图**双峰**（背景亮部+前景暗部）；或"背景过曝面积比 > 阈值 且 前景亮度 < 阈值"
- 反光：本项目已有更强手段（镜像运动学 v2 / 脚点残差 / 几何兄弟检测）——**但那是"倒影判定"；对"玻璃反光污染"（非完整倒影）建议叠加区域级检测**（316/323 玻璃墙区、343 金属门区已知可先验标注）

**ROI 级（每张人脸上）**：
- 人脸 ROI 亮度均值 vs 全图均值差（逆光指数）
- ROI 内高频能量（清晰度）+ 噪声方差（决定增强强度上限）
- 反光污染：人脸区域与反射源区域重叠比例

**自动分类的现代做法（可直接借鉴机制）**：
- **DIME-Net（ACM MM 2025）**：Mixture-of-Experts 稀疏门控——按输入的照明特征**自动选择** S 曲线专家网络，统一处理低光+逆光，无需人工指定场景；
- **ZeroIDIR（2026-05）**：零参考（无需成对训练数据）+ Retinex 分解 + 空间自适应 gamma 图（欠曝/过曝两支路分别预测 γ 与权重图）；
- 自适应 gamma 公式（工程可直接实现）：`γ = α^((m−L)/m)`，L 为光照分量、m 为均值，α∈(0,1) 控制强度。

【推断】对本项目最实用的判断栈 = **统计规则层（零成本、可解释、可写断言）+ 可选一个小分类器（暗/逆光/反光/正常 四分类，用现成画面对照人工标 100~200 帧即可训练）**。

### 3.2 四类场景 → 处理策略矩阵

| 场景 | 判断信号 | 处理 | 代表方法 | 风险 |
|---|---|---|---|---|
| 正常 | ROI 亮度和对比达标 | 直通 | — | — |
| 暗处 | 亮度低 + 低对比 + 高噪 | LLIE 低光增强 | Retinexformer（ICCV'23 基座）/ MambaDPF-Net / LUXFormer（SOTA，2M 参数档）/ 轻量：LIME、Zero-DCE | **噪声放大**，需后置降噪或强度限制 |
| 逆光 | 直方图双峰 / 人脸暗背景亮 | ROI 自适应 gamma / Retinex / 提示学习 | DualPro（Pattern Recognition）/ DIME-Net / GA-CLIP（无监督） | **过增强**（前景提亮过度洗白） |
| 反光 | 已知反射区 + 区域重叠 | 单图反射分离（取透射层） | **RDNet（NTIRE'25 冠军）** / DiT+LoRA（2025-12） | ★ 见下方红线 |

★ **反光的特殊红线（与项目既有纪律强相关）**：本项目已证明「倒影必须被真人**解释**（指派问题），不能逐帧删框」。反射分离算法存在把**倒影"修复"成更清晰人脸**的可能——这会**制造更强的假证据**。因此：反射分离**只允许应用于"已知真人且非倒影"的实体**（用现有倒影指派结果做门控），且修复图标记来源。

### 3.3 关键证据：增强是把双刃剑（决定架构走向的证据链）

| 证据 | 数值 | 含义 |
|---|---|---|
| 背光/低光对识别的影响（2025，1000 万次验证分析） | 背光 -42%、低光 -35% 准确率 | 问题真实存在 |
| HDR 相机（硬件级） | 极端背光 92% vs 非 HDR 67% | 硬件链最优，但本项目已录像，只能算法侧 |
| **实时逐帧增强**（研究实测） | 大集 F1 仅 +2.17%；**双端（参考+实时）增强 -33.71%** | ★ 逐帧/静态参数增强不可靠，过增强会毁掉特征 |
| **离线/固化增强**（同研究） | 参考集离线增强 **+7.28~7.5%** F1 | ★ 增强用在"证据固化"路径才稳定获益 |
| 低光增强联动（社区实测，门禁场景） | 单灯楼道通过率 58.3%→91.2%（+12ms/帧） | 轻量增强在小尺度 ROI 上有效，但这是**受控测试**，需自行 A/B |

【纪律结论】本项目应确立：**「增强 = 固化路径 + 同序列 A/B」**——即 (a) 只对质量池选出的最优帧（异步）做增强；(b) 增强参数按 ROI 自适应（不是全局静态）；(c) 增强后必须**重过质量门**，不升反降则丢弃增强版；(d) 任何进入识别比对链路的增强必须与历史口径 A/B（沿用 SCCAI'25 纪律）。

### 3.4 实现形态

- 离线异步批处理（远程 L20，非实时）：输入 = face_shot 最优帧 → 场景标签路由 → 增强算子 → 质量复核 → 成对存储（原图 + 增强图 + 参数元数据）；
- 增强参数自适应：γ/强度由人脸 ROI 亮度直方图反推（3.1 公式）；
- 全链产物挂 GIL annotation（追加 `annot_enhance(cam, ts, op, strength, before_q, after_q)`），可审计、可回放、可撤销。

## 4. 问题三：低清晰度抓取 → 高清晰度图片用于识别

### 4.1 三条路线对比

| 路线 | 代表 | 机制 | 优点 | 缺点 |
|---|---|---|---|---|
| 单帧盲复原 BFR | **CodeFormer**（VQ 码本 + Transformer，fidelity 可控）、GFPGAN（StyleGAN 先验，保守） | 用一个"人脸先验库"补细节 | 单图即可、效果显著、ONNX 可导出 | **身份幻觉**（低 fidelity 权重产出"好看但不是本人"） |
| 超分 SR | Real-ESRGAN / SRGAN / SRResNet | 放大细节 | 通用；对识别研究 +5~6% | 不专门保身份；高倍率出现伪纹理 |
| **多帧聚合（推荐）** | **FASR++**（扩散 + 多帧特征聚合）、SR 帧融合（QUT） | 多个低质帧的特征融合互补 | **信息最多、幻觉最少**；噪声场景下 SR 比插值更有益（帧融合降噪） | 需同一人的多帧（监控天然满足） |

【事实】关键研究数字：FASR++ 在 CelebA/Quis-Campi 同升 Rank-1、PSNR/SSIM；SR + 张量子空间学习在 LFW 99.17% / QMUL-SurvFace 76.9%；GFPGAN vs CodeFormer 性能（PSNR 31.0 vs 34.2，4090 上 78 vs 92ms）。
【警戒】QUT 博士论文（最早系统研究 SR 对识别影响的文献）明确：学习型 SR 在高倍率下"人脸外观可能改变到不再像本人"——**这是 2008 年就写明的风险，至今仍是矛盾点**。

### 4.2 面向本项目的推荐链

```
多帧（同一 gperson/frag 的 Top-K face_shot）
  → 帧间对齐（关键点仿射）
  → 融合降噪（无幻觉的第一道增益）
  → 保守单帧修复（CodeFormer, fidelity w 取高值 0.7~0.9, 或跳过）
  → 质量复核（不达标的丢弃）
  → 成对存储：原图 + 融合图 + 修复图（各带元数据）
```

用途分层（硬性）：
- **人工核对 / 外部系统比对**：可用修复图（辅助价值最大化）
- **本项目 GIL 身份判定**：不用修复图——防"生成式先验制造虚假 cos 一致性"（倒影 cos 0.0002 的教训泛化）
- 若未来必须用于比对：低 fidelity 权重 + 同序列 A/B + 保留否决记录

### 4.3 ONNX 落地路径（对接 Rust 交付目标）

- CodeFormer 导出（公开方法）：`torch.onnx.export(net(dim_embd=512, codebook=1024, n_head=8, n_layers=9), (face_512, w), opset=11)`；fidelity 权重可作输入或固化为 0.7~0.9；
- 标准四段式管线（工程共识）：人脸检测（SCRFD/RetinaFace，出框+5点）→ 关键点仿射到 512×512 → 修复网络 → 逆变换 + 羽化融合贴回；
- 性能量级：GPU 45~145ms/脸（4090 级），TensorRT 可再降；CPU 慢 5~10×（512 输入重）——**建议只上远程 GPU 批处理，不进本地实时链**；
- 尺寸选择：512 效果好、256 适合 CPU；本项目按"离线批处理"定位选 512。

## 5. 面向项目的统一设计（推荐方案）

### 5.1 能力模块划分（新增五模块）

| 模块 | 职责 | 运行位置 | 阶段 |
|---|---|---|---|
| F0 场景诊断 | 光照/反射标签（每机位时段 + 每 ROI） | 本地/CPU | P0 |
| F1 人脸检测+关键点 | SCRFD-2.5G_KPS（ONNX） | 远程 GPU（批）或本地 | P0 |
| F2 质量评估 | 规则层四因子 +（可选）FIQA/模长 | CPU | P0 |
| F3 质量池 + 最优帧 | obs→frag→gperson 三级 Top-K 池 | 本地（纯 numpy/sqlite，量级极小） | P0 |
| F4 增强/修复（异步旁路） | 场景路由 → 增强/融合/修复 → 复核 → 成对存储 | 远程 L20（批） | P1/P2 |

### 5.2 与 GIL / 现有管线的挂接点

- `obs` 表挂 face 五列或独立 `face_shot` 表（§2.6），**只增不改**——不动 entity 表（splits_v5 冻结纪律）；
- `visit/owner` 是天然交付层：每个 visit 段输出「本段最佳人脸」→ 全楼唯一 owner 视角下的人脸卡；
- webapp 增「人脸」页：人脸卡墙 + 质量分排序 + 增强/修复对比查看器；
- 远程 GPU 批处理（沿用现有 remote_run 工作流），产物 npz/jpg 落 `analysis/face/`。

### 5.3 自动化策略矩阵（判断 → 动作，一页速查）

| 场景判断 | 抓取策略 | 增强策略 | 修复策略 |
|---|---|---|---|
| 正常 | 常规质量门（瞳距≥40、Laplacian≥100） | 不做 | 不做 |
| 暗处（亮度均值 < 阈值/熵<4.5） | 质量门放宽噪识限制 | ROI 局部 LLIE（限制强度）+ 后置降噪 | 融合优先、修复可选 |
| 逆光（双峰/光比超限） | 姿态门收紧（侧脸更不可用） | ROI 自适应 gamma（公式见 3.1） | 融合优先 |
| 反光区重叠 | **先过倒影指派门控** | **仅真人实体可增强** | 仅真人的脸区可修复 |

### 5.4 验收设计（可验证，分三阶段）

- **P0（抓取+质量池）**：人工抽查 30 人「最佳人脸可用比例」+ 每 visit 至少 1 张达标图的覆盖率 + 瞳距分布统计。零模型风险，纯规则，可先跑。
- **P1（增强，离线）**：同序列 A/B——增强前/后 (a) 质量分分布 (b) 若接入 ArcFace 类嵌入则比 cos 分离度。**唯一判据是 A/B 增益**，不采信文献数字。
- **P2（修复，可选）**：仅在确定有比对图库（如与外部名单）时启用；同序列 A/B + 人工核验身份保真（防止幻觉）。
- 全线指标记录进 GIL annotation，保留来源与版本（项目纪律）。

### 5.5 风险清单与红线

1. **修复幻觉**：修复图不得入身份判定主链；成对存储；fidelity 取保守值；
2. **过增强**：-33.71% 前车之鉴；增强后必过质量复核；参数必须 ROI 自适应；
3. **反光区假证据**：反射分离/修复仅限"已知真人且非倒影"实体（复用倒影指派门控）；
4. **算力预算**：修复/增强只上远程 L20 批处理，不进实时链；注意远程根盘 95% 满（产物控制体积）；
5. **口径纪律**：所有新增消费实体的脚本沿用 `DET_VIEW=clean2` 等既有铁律。
