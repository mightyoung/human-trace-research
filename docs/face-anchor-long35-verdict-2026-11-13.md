# 人脸锚点能不能平移到生产聚类？—— 判定：不能（2026-11-13）

> 起因：6 卷评估集上「人脸接聚类」测得 R .3436→.4467（+10.3 pt）、P 还升了 0.65 pt，是这条线上唯一有正收益的召回改动，一直没平移到 long35 生产身份图（443）。
>
> 本轮把它当成「照抄配置」的活来做，做下来发现**问题不在配置，在验收集**。以下是证据。

---

## 0 结论先行

**不要把 ①人脸锚点平移到生产离线聚类。** 不是因为它无效，是因为它**在这份数据上无法被验收**，而无法验收的合并不能进生产。

四条独立证据：

| # | 证据 | 数 |
|---|---|---|
| 1 | 人脸覆盖 | 154 / 1574 轨 = **9.8%** |
| 2 | 可验收性 | 27 条人工盲标判读里，同人 12 对中**只有 1 对两端都有脸**（且 v0 已合上） |
| 3 | 实际行为 | thr .40 触发 3 次簇级合并，**被真值覆盖 0 / 3**；召回与误合一个没动 |
| 4 | 方向风险 | 唯一可比同人对 sp25 cos **0.353**；已知异人对 sp15 cos **0.499** |

第 4 条是致命的：**脸余弦在这批数据上把两个已知答案排反了**。阈值往上调会砍掉唯一可能的正例，往下调会放入已知反例。

## 1 为什么 6 卷的 +10.3 在 long35 上不成立

不是算法退化了，是**两个数据集的真值形状不同**：

| | 6 卷（2622 轨） | long35（1574 轨） |
|---|---|---|
| 人脸覆盖 | 257 轨（9.8%） | 154 轨（9.8%） |
| 验收集 | GT 映射 86 条具名轨 / 20 身份，**按轨全覆盖** | 27 条人工判读，**按物理矛盾挑出来的难例** |
| 真值命中 | 28 条合并边里有对得上的 | 27 对里只有 5 对两端有脸 |

关键差别：6 卷的 GT 是**按轨全覆盖**的，所以 257 条有脸轨里总能碰上几条被真值覆盖的；long35 的 27 条是**刻意挑的难例**（时空矛盾对），这些对大多至少一端是远景/坐姿/背向 —— 正好是人脸最出不来的情况。

**「难例」和「人脸可用」这两个集合天然不相交。**

## 3 试过补采：14 条缺脸轨，只救回 2 条

用新的采集链路（原生 1440p、按框裁头部 ROI、按框高挑 12 帧）定向补采 14 条缺脸轨：

| 轨 | 中位框高 | 检到脸 | 可用 | 结果 |
|---|---:|---:|---:|---|
| **305:728** | 600 | 7 | **3** | ✓ pd 28 / lap 145 |
| **343:17** | 349 | 3 | **1** | ✓ pd 20 / lap 806 |
| 316:196 | 274 | 0 | 0 | 框高够，**检不到脸**（背向） |
| 323:209 | 220 | 9 | 0 | 检到但 pd/清晰度不够 |
| 318:131 | 205 | 9 | 0 | 同上 |
| 318:448 | 195 | 12 | 0 | 同上 |
| 318:342 | 148 | 10 | 0 | 同上 |
| 305:199 | 103 | 12 | 0 | 太小 |
| 305:389 | 101 | 8 | 0 | 太小 |
| 305:173 | 84 | 6 | 0 | 太小 |
| 318:157 | 73 | 3 | 0 | 太小 |
| 323:557 | 143 | 8 | 0 | 检到但不够 |
| 323:534 | 123 | 9 | 0 | 检到但不够 |
| 318:356 | 46 | 0 | 0 | 太小 |

**关键否证：框高不等于能出脸。** 中位框高 195–220 的四条轨（318:131 / 318:448 / 323:209 / 323:534）都检到了 9–12 张脸，**一张都过不了质量门**。这和 `mainline-face-anchor-2026-11-10.md` §8.3 的结论一致 —— **天花板是姿态，不是框高**。

补采后的净影响：

- sp19：305:728 有脸了，**323:557 还是没** → 仍桥不上
- sp01：305:173 中位框高 84，**出不了脸** → 仍桥不上
- sp22（已知异人，v0 已误合）：补后两端有脸，cos **−0.077** → 人脸不支持这条误合。这是唯一的好消息，但它本来就该被拆，人脸也拆不了（人脸只能合不能拆）。

**结论：补采 14 条轨，27 条真值上的召回与误合一个都没变。**

## 5 那生产该怎么做

保留现状，不做平移：

| 通道 | 状态 | 作用 |
|---|---|---|
| ② 运行时选择器（`#/selector`） | **已上线** | 覆盖 53%→73%、判对 91.8%→94.0%。不依赖离线覆盖 → 人脸稀疏也能用 |
| ③ 自动人脸通道（`#/auto-face`） | **已上线** | 46 轨 / AUC .777。定位是「单轨实体」的唯一提问通道 |
| ① 人脸锚点硬合并 | **本轮判定：不上** | 验收集覆盖不够，无法判断对错 |

如果一定要让 ① 参与生产，唯一站得住的形态是**给人脸候选边排序，不做硬合并** —— 和项目对位置先验的定论完全同构（`mainline-reid-roadmap`：位置只配候选排序）。硬合并这条路要重新打开，前提只有一个：

> **让 11 条缺脸同人对里至少 5 对变成双端有脸。** 这要求采集端在出入口/工位正面加近场机位（人脸中位 52 px → ≥80 px），属于硬件决策，不是阈值或模型能解决的。

## 6 顺带发现（与本轮判定无关，但值得记）

27 条人工判读里，**v0(434) 已误合 4 条**（sp09 / sp15 / sp22 / sp26），精度 10/14 = 71.4%。这 4 条都是跨机位（323-343、305-343、316-323），与「6 个机位对里只有 318↔320 可用」的定论一致 —— **弱机位对的贪心合并仍在制造误合并**，这是比人脸更值得修的事。
