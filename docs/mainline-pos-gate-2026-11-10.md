## 1. 怎么接进去的

候选对层面已验证的判据是（`pos_vs_appearance.py`，24,706 对）：

```
merge  <=>  cos >= 0.80  OR  (cos >= 0.70 AND dist <= 0.10)
```

层次聚类里没法对不同对用不同阈值，所以实现成「**用 thr-lo 聚类 + 对不满足空间条件的对做否决**」：

```python
# 外观落在 [thr_lo, thr_hi) 且位置远 → 否决（距离推到 >1，与共现约束同样处理）
veto = isfinite(dist) & (S >= thr_lo) & (S < thr_hi) & (dist > pos_gate)
# 外观连 thr_lo 都不到、位置也远 → 同样不许被 average linkage 顺带拉进来
veto |= isfinite(dist) & (S < thr_lo) & (dist > pos_gate)
D[veto] = 1.0 + 1e-6
lab = fcluster(linkage(squareform(D), "average"), t=1 - thr_lo, "distance")
```

位置坐标：`x = 框中心 x / W`、`y = 框底边 y / H`（脚的位置比框中心稳），距离用「前一条尾点 → 后一条首点」的归一化欧氏距离。

## 2. ★★ 坑一：跨卷位置不可比，thr 一降就把精度吃掉

**第一版直接把 thr 从 0.80 降到 0.70**，结果：

```
基线     TP 100  FP  3   P 0.9709  R 0.3247
位置门控 TP 127  FP 23   P 0.8467  R 0.4123     ← FP 涨 7.7 倍
```

召回涨了 9 个点，精度掉 12 个点，**净收益被吃光**。

原因：`thr` 是全局的，降到 0.70 会同时放松**跨卷对**。而位置门控对跨卷完全无效——7 个卷是 7 个不同机位、不同坐标系，位置距离没有意义。跨卷合并只能靠外观。

修法：`--gate-scope same-vol`（默认）。位置不可用的对（跨卷 / 同卷时间重叠 / 走廊卷）**不享受 thr-lo 的放宽**，仍按 thr-hi 判：

```python
veto_strict = (~isfinite(dist)) & (S < thr_hi)
```

修完：`FP 23 → 9`，`P 0.8467 → 0.9280`。

## 3. ★★ 坑二：评估集分母会跟着覆盖率膨胀

第一次比对时看到一个漂亮的提升：

```
基线     评估集 62 轨   P 0.9709  R 0.3436
位置门控  评估集 68 轨   P 0.8467  R 0.4137
```

**但评估集从 62 变成 68 了。** `eval_full.py` 原来的口径是「落在簇里的具名轨」，聚类覆盖越多，分母越大——这和论文线踩过的 `fm` 分母漂移是同一类错。

改成固定分母：**评估集 =「有嵌入的具名轨」**，与聚类版本无关；不在任何簇里的轨按各自独立簇处理，自动记作 FN。

```bash
export EVAL_EMB_DIR=tmp/full/pull/emb
export EVAL_SEGS=v2518,v2526,v2534,v2540,v2545,v2559
python tmp/full/eval_full.py <clusters.json> tmp/full/gt_on_vol.json
```

统一后所有版本都是 70 轨，数字才可比。**注意 70 轨口径的 R 与旧的"62 轨口径"数值不同，不要混用。**

## 4. ★ 坑三：驻留约束想当然，实测有害

`#4`（71 轨、全在 v2534、跨度 207 分钟、总覆盖只有 6 分钟）看着像误合并，于是加了个「两侧时长都 ≥ N 秒才让位置生效」的约束（固定通道点上人人位置都近）：

| min-sec   |   簇 |  最大 |      TP | FP |      P |          R |         F1 |
| --------- | --: | --: | ------: | -: | -----: | ---------: | ---------: |
| **0（不加）** | 204 | 113 | **116** |  0 | 1.0000 | **0.3766** | **0.5472** |
| 10        | 243 | 103 |     111 |  0 | 1.0000 |     0.3604 |     0.5298 |
| 30        | 250 |  87 |      90 |  0 | 1.0000 |     0.2922 |     0.4523 |

**加了反而单调变差。**

再去看那个簇的真实构成，发现我判断错了：

```
簇 #3  n=71  cos_p10 0.861  cos_p50 0.910  cos≥0.80 占 100%  时长中位 4s
```

**这 71 条轨两两余弦全部 ≥0.80**，也就是 `thr=0.80` 本来就会合并——不是位置门控造成的。形态是「同一个人 71 次经过同一处」（每次几秒、位置固定、外观高度一致），合并是正确的。

→ 保留 `--pos-min-sec 0`（默认即关闭）。

## 5. 参数敏感度：是平台，不是尖峰

| thr-lo / pos-gate |  TP | FP |      P |      R |         F1 |
| ----------------- | --: | -: | -----: | -----: | ---------: |
| 0.70 / 0.10       | 116 |  9 | 0.9280 | 0.3766 |     0.5358 |
| 0.73 / 0.10       | 116 |  0 | 1.0000 | 0.3766 |     0.5472 |
| **0.75 / 0.10**   | 116 |  0 | 1.0000 | 0.3766 | **0.5472** |
| 0.75 / 0.08       | 116 |  0 | 1.0000 | 0.3766 |     0.5472 |
| 0.75 / 0.12       | 116 |  0 | 1.0000 | 0.3766 |     0.5472 |
| 0.78 / 0.10       | 114 |  0 | 1.0000 | 0.3701 |     0.5403 |
| 0.80 / 0.10       |  82 |  0 | 1.0000 | 0.2662 |     0.4205 |

`thr-lo ∈ [0.73, 0.75]`、`pos-gate ∈ [0.08, 0.12]` 结果完全一致，是一个宽平台。

★ 值得记的一点：**候选对层面的最优阈值（0.70）在端到端变差**（FP 冒出 9 个）。局部最优 ≠ 全局最优——候选对层面那 9.3% 的误接受率，到了 1,911 条轨的聚类里会被放大。

最大的几个簇都查过形态：位置 std ≤ 0.05、时间重叠对全是「交替轨」（从不共现）、内部外观余弦中位 0.85–0.92。**是碎片化，不是误合并。**

### 顺带修掉一个隐患：`face_anchor.py` 的链式传递

逐边做共现校验挡不住传递性：A∪B 无冲突、B∪C 无冲突，但 A∪C 有冲突。加了合并后的整体兜底拆分（按簇内 face cos 强度降序贪心装箱）。

当前数据上**兜底未触发**（在各版本上实测簇内真冲突均为 0），但链式条件是存在的，留着作为保险。

★ 检查共现冲突时**必须用剔除嵌套框的正确口径**（`cooc_track_set(..., nested_cover=0.60)`）。我一度用「简单同帧判定」算出 130 个冲突、全簇报错，实际那些全是同人双框（全身框 + 上半身框），换成正确口径后是 0。

## 7. 复现

```bash
P=C:/Users/might/.workbuddy/binaries/python/envs/default/Scripts/python.exe
export EVAL_EMB_DIR=tmp/full/pull/emb
export EVAL_SEGS=v2518,v2526,v2534,v2540,v2545,v2559

# 1) 位置门控聚类（thr-lo 0.75，位置只对同卷生效）
$P tmp/full/cluster_pos.py \
  --emb-dir tmp/full/pull/emb --det-dir tmp/full/pull/out \
  --segs v2518 v2526 v2534 v2540 v2545 v2559 \
  --out tmp/full/sens_0.75_0.10 \
  --pos-mode gate --gate-scope same-vol \
  --thr-hi 0.80 --thr-lo 0.75 --pos-gate 0.10 --pos-min-sec 0

# 2) 叠人脸锚点
$P tmp/full/face_anchor.py --clu tmp/full/sens_0.75_0.10/clusters.json \
  --face tmp/full/face/face --det tmp/full/pull/out --gt tmp/full/gt_on_vol.json \
  --mode apply --tau 0.45 --proto full --min-usable 1 --min-selfcos 0.0 \
  --out tmp/full/clu7_final

# 3) 固定分母评估
$P tmp/full/eval_full.py tmp/full/clu7_final/clusters.json tmp/full/gt_on_vol.json
```
