# 同机位跨时段重连：长间隔位置判据

日期：2026-11-10
定位：主线（多机位 ReID 全程身份识别）第 1 步 —— 轨迹预测在**同机位**落地。
代码：`tools/track_stitching.py`（新增 `--long-gap-*` 分支，默认关闭）、`tmp/mainline/{stitch_eval,long_gap_stitch}.py`

---

## 0. 一句话

**位置先验不随 gap 衰减**——500 秒以上的断点，同一个人两头的位置距离中位仍是 0.058，而随机对是 0.331。把拼接层「速度外推 + 30 秒上限」换成「两端位置距离」，同机位身份完整度从 **27.4% 提到 37.7%**，误接从 1 增到 3。

---

## 1. 起点：现有判据的假设是错的

`track_stitching.py` 原逻辑：从 A 尾状态（脚点 + 最近 15 帧速度）外推 gap 帧后的位置，与 B 首位置比距离；门槛 `pe_adj ≤ 0.08`；**gap 上限 750 帧 = 30 秒**。

这个假设是「人走了就不知道去哪，速度外推很快失效，所以只接短间隔」。

**实测（305_train_529 / 318_train_525，均为 9000 帧/60 分钟）恰好相反：**

| gap 档 | 同身份对数 | 两端位置距离（中位） | ≤0.05 占比 |
|---|---:|---:|---:|
| 0–30 s | 50 | 0.052 | 48% |
| 30–60 s | 26 | 0.014 | 62% |
| 60–120 s | 38 | 0.037 | 55% |
| 120–300 s | 59 | 0.022 | 61% |
| **300–1200 s** | **255** | **0.058** | **47%** |
| **随机不同轨对（对照）** | 1853 | **0.331** | **5.7%** |

读法：**间隔 5–20 分钟的同一个人，两头位置距离中位 0.058；随便挑两条不同轨，0.331。差 5.7 倍。** 而 0–30 s 短间隔是 0.052，与 300–1200 s 几乎相同。

原因是场景本身：办公环境里人离开（开会、下楼、去洗手间）之后**回到原来的工位**。所以「位置」在长间隔下仍然是强信号，而「速度」在长间隔下完全无意义（人不走直线）。

**这就是「历史素材」的第一个真实用处**：位置分布是场景的稳定属性，不需要训练，统计即可。

---

## 2. 改动

给 `track_stitching.py` 加一个**长间隔分支**（默认关闭，既有行为逐格不变——已验证 862 行候选、共有列 0 差异）：

```
短间隔（gap ≤ gap_max=750 帧）：原逻辑，速度外推 + pe_adj ≤ 0.08
长间隔（gap_max < gap ≤ --long-gap-frames）：两端位置距离 ≤ --long-gap-dist，不走外推
mutual-best 打分：score = cos − 2·pe_adj − (long_gap ? --long-gap-penalty : 0)
```

**长边必须加惩罚**，这是本轮一个反直觉的坑：不加惩罚直接放开，真接上从 102 **掉到** 57。因为长边的 `pe_adj = dr` 很小、`cos` 又高，在 mutual-best 里抢走了短边的名额，把本来正确的链打断。加 0.20 惩罚后回到 120。惩罚 0.20 / 0.40 / 0.60 结果完全一致，说明 0.20 已经足够把长边压到短边之后。

---

## 3. 端到端结果（两段合计，305_train + 318_train）

指标口径：链内**两侧都具名**的轨对（真接上 / 误接），以及「每个身份的最大链覆盖轨数 / 该身份总轨数」（完整度）。

| 配置 | 真接上 | 误接 | **平均完整度** | 完全串起的身份 |
|---|---:|---:|---:|---:|
| **生产** `0.80/0.08`，gap≤30 s | 102 | 1 | **27.4%** | 0 |
| `0.80/0.18` | 107 | 1 | 28.8% | 0 |
| `0.70/0.30` | 113 | 2 | 33.6% | 0 |
| 长间隔 `cos≥0.80` | 113 | 1 | 32.2% | 0 |
| **长间隔 `cos≥0.70`（推荐）** | **120** | **3** | **37.7%** | **1** |
| 长间隔 + 关同帧硬约束 | 123 | 3 | — | — |

- **完整度 +10.3 个百分点**（27.4% → 37.7%），代价是误接 +2。
- 只放宽 `pe`（0.08→0.18）就能零代价多接 5 对，可以单独上线。
- 关掉同帧共现硬约束只多 3 对 → **该约束不是瓶颈**（同帧并存只占身份对的 6.6%）。

## 4. 天花板在哪

具名身份对的构成（305）：**先后关系 590 / 时间重叠 42**。重叠那 42 对的「重叠区间内同帧占比」中位 0.054 —— 近乎完全交替，是同一人被反复换号。

但 **590 个先后对只成链 120 个**，剩下 470 个卡在 `mutual-best`：一条轨只能有一个后继/前驱，而「一人多轨」时多条轨都指着同一个人，形成竞争——A 的最佳后继是 B，但 B 的最佳前驱是 C，于是 A→B 不成立。

个案 `female3`（305_train，**一个身份被切成 26 条轨**，325 个身份对）：

| 轨 | 时间跨度（帧） | 入链 |
|---|---|---|
| t8 | 0–9370 | 链 3 |
| t67 | 1040–14890 | 链 4 |
| t809 | 14430–36370 | 链 3 |
| t2093 | 23110–39910 | 链 4 |
| … | | |

26 条轨被分成 **6 条链**（最长一条 9 段、跨 2577 s）。链 3 与链 4 是**平行的两条**——不是拼接失败，是 `mutual-best` 在一人份的候选里只能选一条。

**所以下一步不是继续调阈值，是换链接算法**：把 `mutual-best` 换成「一对一最优分配」（贪心或匈牙利），允许一个身份的候选被分给不同的后继。这才是把 470 个未成链的先后对吃掉的办法。

另一个独立的天花板是 **656 个身份对来自 16 个身份**——`female3` 26 条轨、`male6` 17 条、`female2` 13 条。一个人被切成 26 段，说明根因在跟踪层（ByteTrack 在遮挡/合并框时换号），拼接层只是补救。这与 P2 的结论（合并框是 ID 切换第一大根因）一致。

## 5. 建议

**可以立刻上线的**（零风险）：

1. `--link-pe 0.18`：多接 5 对，误接不变。
2. 长间隔分支（`--long-gap-frames 30000 --long-gap-dist 0.05 --long-gap-penalty 0.20`）+ `--link-cos 0.70`：完整度 27.4% → 37.7%。

**下一步（按收益排序）**：

| 步 | 内容 | 预期 |
|---|---|---|
| 1 | `mutual-best` → 一对一最优分配 | 吃掉 470 个未成链先后对的大部分 |
| 2 | 检测层去重换覆盖率判据（`docs/p2-joint-ablation-2026-11-10.md`） | 直接减少「一人多轨」的源头 |
| 3 | 跟踪层（合并框拒收） | 根治，但需重跑检测 |

**未验证**：`--link-cos 0.70` 是在这两段上选的，虽有 318 做独立验证（两段提升方向一致），但严格说仍需第三段（test 四段）确认。test 四段帧数少（500 帧级），样本不足，本报告未纳入。
