## 1 判定规则（每条轨迹最多一个动作 → 碎片有硬上限）

| 条件 | 动作 | 说明 |
|---|---|---|
| 外观最低跳 < τ 且位置 **pos ≥ 0.90** | **截断** `truncate` | 丢掉换人点之后的样本，不产生碎片 |
| 外观最低跳 < τ 且位置 **pos < 0.90** | **拆分** `split` | 在该点切成两条子轨迹 |
| 其余（含无下探） | **保留** `keep` | 不动 |

`pos = (切点 − 该轨首帧) / (末帧 − 首帧)`。**每条轨迹最多一刀**，所以碎片倍率上限是 2×（实际 1.28×，因为只有部分轨迹触发）。

参数：`τ = 0.60`（外观相邻样本余弦，0.8s 步长）、`TAIL_POS = 0.90`、命中容差 `±1s`。

## 2 四项指标与基线（首次运行即写入基线文件）

| 指标 | 定义 | 基线（τ=0.60） |
|---|---|---|
| **M1 中段召回** | pos<0.9 的真混人轨里，切点落在真值 ±1s 的比例 | **5/14 = 35.7%** |
| **M2 尾部污染** | pos≥0.9 的真混人轨里，「换人之后采样点数 / 总采样点数」中位数 | **0.0%**（n=10） |
| **M3 群体碎片** | 全部轨迹的平均子轨迹数（干净轨触发率 + 混人比例折算） | **1.28×** |
| **M4 总处理率** | 全部真混人轨里被正确动作覆盖的比例 | **12/33 = 36.4%** |

基线写在 `results/m1_gate_baseline.json`；之后每次运行都与它比，任何一项变差即 `FAIL`。

### M2 的结论需要更正上一轮的判断

上一轮我把「usable 类命中 11/22 = 50%」当成了 M1 的召回，其中有 9 条其实是**位置在 0.90–1.00 的尾部换人**，
被 `truncate` 正确处理。但 M2 显示：**这些尾部换人之后剩下的采样点中位数是 0.0%**——
也就是说，尾部换人本来就不污染 8 帧表征，**不需要动作**。

把这类从召回里剔掉后，真正的**中段**拆分召回是 **5/14 = 35.7%**。
上一轮报的 50% 是口径不对，这里更正。

## 3 容差敏感性（同一批数据，τ=0.60）

| 容差 | 中段（n=14） | usable 全量（n=22） |
|---|---:|---:|
| ±1s（审计口径） | 5/14 = 36% | 11/22 = 50% |
| ±2s | 5/14 = 36% | 12/22 = 55% |
| ±3s（效用口径） | 6/14 = 43% | 13/22 = 59% |
| ±5s | 7/14 = 50% | 14/22 = 64% |

**为什么要两套口径**：±1s 用于和人工标注对齐审计（V0.4 原判据）；而下游关心的是"两段是否分给了两个人"，
切点偏 2–3 秒仍能把两个人分开（重叠 3s ≈ 4 个采样点）。汇报时两套都要给，不能只报宽的那个。

## 4 τ 取舍（碎片预算 vs 召回）

| τ | 中段召回(±1s) | 群体碎片 | 干净轨误切 | 总处理率 |
|---:|---:|---:|---:|---:|
| 0.45 | 1/14 = 7% | 1.10× | 10% | 9.1% |
| 0.50 | 3/14 = 21% | 1.11× | 10% | 18.2% |
| 0.55 | 4/14 = 29% | 1.12× | 10% | 21.2% |
| **0.60（基线）** | **5/14 = 36%** | **1.28×** | 24% | 36.4% |
| 0.65（召回优先） | 6/14 = 43% | 1.46× | 43% | 39.4% |

**选 0.60 的理由**：碎片 1.28× 在 1.30× 预算内；0.65 虽然召回高 7 个百分点，但碎片 1.46× 已越界，
且干净轨误切率从 24% 跳到 43%——代价大于收益。

## 5 闸门怎么用

```bash
# 每次改动切分/阈值后跑一次；与基线对比，退化为 FAIL
PY tools/m1_gate.py

# 需要动作清单（喂给下游切分执行）：额外产 results/m1_actions.csv
PY tools/m1_gate.py --emit-actions

# 明确要重设基线（只有口径变更时才允许）
PY tools/m1_gate.py --reset-baseline
```

产出：
- `results/m1_gate.json`（当次全部指标与逐条明细）
- `results/m1_gate_baseline.json`（基线，勿随意改）
- `results/m1_actions.csv`（33 行逐条：**16 split / 11 truncate / 6 keep**，含真值与误差便于对账）
- `results/m1_mid_detail.json`（中段 14 条的逐条误差）

## 6 已知限制（写进论文/汇报时必须带）

1. **样本量小**：中段只有 14 条、尾部 10 条。36% 的 95% 置信区间约 16–61%，不能当作精确值。
2. **只用已标注的 39 条**：未标注的 800+ 条没有真值，M3 的干净轨触发率只来自 21 条对照。
3. **检测底表限制**：`1012_yolo8_dd` 帧间隔固定 0.4s、每轨检测点中位 11–20 个。
   在换人点附近往往只有 3–5 个样本可比，这是召回上不去的第一原因（详见 `m1-b-result` §4）。
4. **两种失败模式无法区分**：切错位置（偏 2–10s）和完全没切（keep）在指标上都记 0 分，
   但下游影响不同——前者制造一条半污染子轨，后者保留整条污染轨。

| | M1 v1（本文） | M1.5（增益） |
