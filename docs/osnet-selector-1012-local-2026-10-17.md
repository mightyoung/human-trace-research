# OSNet 身份选择器：1012 本地重训与时间隔离评估

日期：2026-10-17
设备：AMD Radeon RX 5700 XT（DirectML）+ CPU
数据：1012 数据集，train 4 段（上午 08:03–09:35）/ test 4 段（下午 14:22、15:03 起，各 15min）

## 0. 结论

1. **OSNet 编码器跨时段可迁移**：test 同轨前后半余弦均值 **0.9230**，高于 train 的 0.9178——外观表征本身没有退化。
2. **原型库不可迁移**：同一条轨迹对原型的最高分中位数从 train 的 **0.929 掉到 test 的 0.810**，导致生产阈值（0.853）下覆盖率仅 **27–31%**（双侧同时接受 **20.5%**）。
3. **已接受部分的身份一致性仍然可用**：条件一致率 **0.911**（train 0.933），共现误合并 **1.41%**（train 1.63%）。
4. **瓶颈定位**：不是"换编码器"能解决的问题，而是**跨 session 的原型/阈值失配**。下一步应做 session 自适应（新时段 bootstrap 重定阈值或增量原型），而不是继续比较编码器。

## 1. 链路与设备归属

| 环节 | 设备 | 实测 |
|---|---|---|
| OSNet 前向 | **GPU**（DirectML，privateuseone:0） | 批量 32：**6.0–8.7 ms/裁剪** |
| 视频解码 | CPU（OpenCV FFMPEG） | 6.6 ms/帧（151 fps） |
| 聚类 / 评估 | CPU（numpy / scipy） | 1032 轨训练 13s |

**GPU 证据**：模型参数 device 实测为 `{privateuseone:0}`，适配器名 `AMD Radeon RX 5700 XT`；CPU 版与 DML 版同轨嵌入余弦 = 1.000（前序实验）。

**批量化的收益（本次改动）**：`torchreid` 的 `FeatureExtractor` 每次调用有约 **185 ms 固定开销**；原脚本按轨（≈8 张）调用，只有 30.7 ms/裁剪。改为全局按 32 张分批后降到 **6.0 ms/裁剪**，单段 3600s 的编码耗时从约 95s 降到约 20s。

**等价性校验**：320 段用新路径重编码后与旧结果逐轨比对，cos 均值 0.99999998、最小 0.99999988（60+61 轨全命中）。批处理只改变前向分组，不改变特征。

**GPU 化的边界（已实测，不再优化）**：
- 硬解码无收益：FFMPEG + D3D11 硬件加速 **8.6 ms/帧**，比 CPU 的 6.6 ms 更慢（需回读到系统内存）；MSMF 后端在本机无法打开该文件。
- 3600s 段落的剩余耗时 95% 在解码，与该段需要的 3277 次取帧强相关，不是算力问题。

## 2. 训练（1012 train，上午）

| 项 | 值 |
|---|---|
| 轨迹数 | **1032**（305:397 / 318:234 / 320:59 / 323:342） |
| 分片判别力 | pos 0.9178 / neg 0.4993，**AUC 0.9925** |
| 共现负对 | 4482 对（同帧共现 ≥5 帧） |
| 阈值校准 | pos_p5 0.782，cooc_p99 0.924 → thr_unknown **0.853** |
| 最优聚类 | 层次平均连接 thr=0.2 → 223 簇 |
| 原型库 | 去小簇后 **132 个原型** |
| 训练集指标 | **F1 0.886**（P 0.844 / R 0.933），same 0.933，coll 0.016 |

三方法对比（pairwise F1，负对=共现对）：hier-avg 0.2 → 0.886；hier-avg 0.3 → 0.842；kmeans K=60 → 0.833；mutual-kNN k=5 → 0.821。

## 3. 评估（1012 test，下午，时间隔离）

两组口径必须分开看，否则会误读：

### 3.1 可比口径（无条件 argmax，与训练报告同定义）

| 指标 | train | test | 变化 |
|---|---|---|---|
| same（同轨 a/b 同簇） | 0.933 | **0.782** | −15.1pp |
| F1（正=同轨，负=共现） | 0.886 | **0.784** | −10.2pp |
| P / R | 0.844 / 0.933 | 0.785 / 0.782 | — |
| 同轨 a/b 余弦 | 0.9178 | **0.9230** | +0.5pp |

编码器没变差，簇归属变差——这是"原型库对不上人"的典型签名。

### 3.2 运行时口径（带 thr_unknown=0.853）

| 指标 | 值 |
|---|---|
| 接受率（a / b / 双侧） | 0.273 / 0.314 / **0.205** |
| 条件一致率（双侧已接受） | **0.911** |
| 共现误合并率 | **1.41%**（928 对中 213 对可评） |
| 使用簇 / 原型总数 | 29 / 132 |
| 跨机位复用簇 | 2 |

分机位：305 n=83（接受 0.35/0.36，same 0.96）、318 n=65（0.20/0.29，0.90）、323 n=44（0.32/0.41，0.89）、**320 n=28（0.14/0.07，样本仅 4 条，不作结论）**。

### 3.3 阈值扫描（test，运行时口径）

| thr | 双侧接受 | 条件一致 | 严格一致 | 误合并 | 可评对 |
|---|---|---|---|---|---|
| 0.65 | 0.986 | 0.783 | 0.773 | 4.00% | 924 |
| 0.70 | 0.918 | 0.787 | 0.723 | 4.07% | 910 |
| 0.75 | 0.723 | 0.780 | 0.564 | 3.61% | 693 |
| 0.80 | 0.505 | 0.820 | 0.414 | 2.36% | 509 |
| **0.853** | **0.205** | **0.911** | 0.186 | **1.41%** | 213 |
| 0.88 | 0.132 | 0.966 | 0.127 | 0.00% | 127 |
| 0.92 | 0.055 | 1.000 | 0.055 | 0.00% | 49 |

曲线形态是关键：**放低阈值换覆盖的代价很高**——把覆盖拉到 90% 时，条件一致率跌到 0.787、误合并升到 4%。说明单纯调阈值无法同时拿到"高覆盖 + 稳定 ID"。

### 3.4 分数分布对比（诊断核心）

| | 最高原型分 中位 | p5 | 阈值 0.853 下接受率 |
|---|---|---|---|
| train（同 session，样本内） | 0.929 | 0.774 | 0.89 |
| test（跨 session） | **0.810** | 0.698 | 0.27–0.31 |

−0.12 的系统性偏移。注意 train 是样本内（原型由这些向量建成），真实同 session 值会低于 0.89，因此实际偏移幅度小于表中差值。

## 4. 边界与未验证

1. **1012 test 无人工身份标注**，以上除"误合并"外均为无标签代理指标，**不能当准确率**。
2. same 指标衡量的是"同一条轨迹前后半是否同簇"（时序 ID 稳定性），**不是跨机位配对准确率**。跨机位精度仍未测。
3. test 仅 220 轨；320 机位 28 轨、接受 4 条，统计无效。
4. train 指标为样本内，乐观偏置；与 test 的差值只能作方向判断。
5. 未做 per-camera 阈值与多原型（multi8）升级——本版为单原型 + 全局阈值，与 cradio 生产版（412 子原型 + per-cam 两档）不是同一复杂度。

## 5. 下一步（推荐顺序）

1. **session 自适应（首选）**：新时段前 N 分钟做 bootstrap——重算 per-cam 阈值、可选增量原型。这是唯一能同时保住覆盖与一致性的方向，且不需要重训编码器。
2. **多原型 + per-camera 阈值**：把 selector_v2 的 multi8 结构迁到 OSNet 空间，缓解"一人多外观"被压成单中心的问题。
3. **补跨机位标注集**：在 test 时段（下午）人工判定一批跨机位对，才能回答"跨镜头 ReID 是否稳定"这个原始命题。在此之前，任何"跨机位精度提升"的说法都缺证据。
