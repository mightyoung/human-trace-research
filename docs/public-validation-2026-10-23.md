## 1 数据与子集（MARS）

`datasets/bbox_test/`：**681,089 张 jpg / 12,180 条 tracklet / 636 个身份目录**，与官方口径逐项吻合。
目录名即 pid：`0000` = pid 0（junk，3248 条）、`00-1` = pid −1（invalid，870 条），其余 634 个为名册身份。

**划分用官方文件，不是自造**：`MARS-evaluation/info/query_IDX.mat` + `tracks_test_info.mat`（本次下载）。
关键点：`query_IDX` 是 **1 基的 `tracks_test_info` 行号**（uint16，max=12180），不是全库图序 —— 按图序解释只会解出 317 条查询轨迹，是错的。

## 2 方法：为什么 MARS 能复用同一条流水线

MARS 只有切好的裁图，没有视频，所以跳过检测/跟踪，把它改写成"伪视频段"：

- 每条 tracklet 当成一条轨迹，按机位分到 `c1_g…c6_g`（图库）与 `c1_q…c6_q`（查询）；下游用 `seg.split("_")[0]` 取机位，机位感知聚类直接生效。
- 每条轨迹按帧序对半切 a/b，每半取 8 帧求 OSNet 均值 —— 与现场 `make_ab_jsonl` + `encode_1012_osnet_seq` 的口径一致。
- 同段内轨迹的帧号互不重叠（每条间隔 10000），**因此段内共现对恒为空**。这是刻意的：MARS 没有多机位同步，不能伪造 co-occurrence。
- 图库/查询的隔离用**轨迹级互斥**（官方 query_IDX），不是现场的时间切分。这是最本质的一处口径差异。

新增脚本：`tools/mars_build.py`（构造数据包）、`tools/encode_mars_tracklets.py`（编码）、`tools/public_eval.py`（H1/H2/H3 判定）。
`d7_sweep.py` / `eval_precision.py` **一行逻辑没改**（只加了 `--min-eval` 参数），所以簇、查询、评价三层与现场完全同源。

## 3 ★ 一个必须写进论文限制的结构性问题：self-cal 依赖同步

按 VALIDATION §1「不调参」，`self-cal` 用同一条规则选 θ：`same ≥ 0.90 且 evaluable ≥ 100`，取覆盖最大。
在 MARS 上**这条规则不可用**：

- `evaluable` 是 `false_merge` 的分母 —— **共现对**里两边都过阈值的对数；
- MARS 无同步 → 共现对为 0 → `evaluable ≡ 0`；
- `min_eval=100` 永远不满足 → **42 个配置全部"self-cal 无可行点"被跳过**，第一次跑的结果是"0 配置 / 0 曲线点"。

处理：退到只保留 `same ≥ 0.90` 的分支（`--min-eval 0`），θ 仍由「可行域内覆盖最大」选出。已写进 `validation/mars/run_info.json` 的 `deviations`。

**这不是 MARS 的缺陷，是判据的边界**：任何没有同步多机位视频的数据集（MARS、MSMT17、Market-1501、CUHK03…）都无法执行我们这套 self-cal，也就无法执行 fm 预算。论文的"可复现性"一节必须写明：**该判据的适用范围是有同步采样的多机位场景**。

同样的规则在 CHIRLA 上成立（有同步帧），所以两个数据集正好互补：CHIRLA 验"判据能不能用"，MARS 验"结论方向对不对"。

## 6 CHIRLA：两版设计都跑完了，**都判不了**，但原因不同、且都有用

### 6.1 主设计（预注册：seq_000 → seq_001/002）：无法判定，卡在跨场域偏移

15 段全部跑完（seq_001/002 的 camera_5/6/7 标注为空，只跑 camera_1..4），自动真值框匹配率 79.2%–100%。

| 项 | 数值 |
|---|---|
| 图库 / 查询 | 196 条（158 有身份，8 身份）/ 59 条（52 有身份，9 身份，含图库外 id 8） |
| 自动真值排除 | no-match 22｜id_switch 24 |
| A_baseline | K=27｜θ=1.40（网格下界）｜**覆盖 0.034**｜接受 **2/52**｜C=1 W=1 |

三层诊断（`validation/chirla/run_info.json` → `diagnostics`）：

| 配对 | 同人余弦 | 异人余弦 | AUC | top-1 |
|---|---|---|---|---|
| 图库内·同机位 | 0.837 | — | — | — |
| 图库内·跨机位 | 0.758 | 0.592 | **0.857** | — |
| 查询 vs 图库（跨场 50 min） | **0.662** | 0.569 | **0.758** | 28.8%（同机位 36.5%） |

**图库内部完全正常（AUC 0.857），塌陷只发生在"查询 vs 图库"**：同人余弦从 0.758 掉到 0.662，异人几乎不动（0.592→0.569），可分间距被削掉一半。原因是两段录制相隔约 50 分钟（11:14 vs 12:03/12:09），服装/光照/姿态全变。

**所以这不是"F1/F2 不成立"**，是设计不成立：现场的图库/查询是同一天同批人同批相机，而不是隔 50 分钟的另一场。

### 6.2 补救设计（日内时间切分，非预注册）：表征没问题，但判据不适用

`seq_000` 前 60% 帧作图库、后 40% 作查询（切分帧 5350/8916，7 机位同步）。约 20 分钟跑完。

| 项 | 数值 |
|---|---|
| 图库 / 查询 | 121 条（97 有身份）/ 75 条（61 有身份），8 身份，无图库外身份 |
| 查询→图库 top-1（无聚类） | **77.0%（47/61）** — 对比主设计的 28.8% |
| 同人 / 异人余弦 | **0.763 / 0.589**，AUC **0.845** |
| 描述性工作点（θ=0.95） | 覆盖 **0.373**｜接受 23｜C 19 / W 2 / U 2｜精度 **0.905**｜C/61 **0.311** |
| 正式判据（same≥0.90）下唯一可行点 | θ=3.00｜覆盖 **0.013**（**1/75 条**）｜same 1.0｜fm 0｜可评估 **3** 对 |
| 描述性放宽点（same 门槛临时降到 0.82） | θ=0.95，即上表那一行 —— **只作描述，不作判定** |

两个结论：

1. **域偏移假设被证实**：同场切分后 top-1 从 28.8% 回到 77.0%，同人余弦 0.662→0.763。表征完全够用。
2. **冻结的 self-cal 判据在这类数据上只剩退化解**：`same` 并不是"到不了 0.90"，而是**到了 0.90 就只剩 1 条查询**。θ=3.00 时 same=1.0、fm=0，但覆盖 0.0133（1/75）、可评估只有 3 对共现——任何读数都是 1 个样本。根因是**轨迹长度**：CHIRLA 里人穿过画面只有 2–5 秒，2.5 FPS 下整条轨迹 5–12 帧，a/b 两半各 2–3 帧。现场的轨迹动辄上千帧，两半各几百帧，`same` 才能在**有覆盖的前提下**到 0.909。

> 更正一处此前写法：6.2 初稿写"same 最高 0.821，任何 θ 都到不了 0.90"——那是把**放宽门槛后选中的描述性工作点**当成了曲线上的最大值。曲线本身在 θ=3.0 是 1.0，只是覆盖塌到 1 条。正确的说法是"可行点存在但退化"，不是"不可达"。

把 `same` 门槛降到 0.82 才拿到一个描述性工作点（θ=0.95），**只作描述、不作判定**：接受 23 条 < 门槛 30，`public_eval.py` 的硬守卫仍判"无法判定"，但方向与现场一致（继承精度 0.696 < 逐条精度 0.905；veto ΔC −2）。

### 6.3 这条对论文的价值：判据的适用边界

两个数据集合起来给出了一条此前没写下来的边界条件：

> **冻结评价判据（self-cal：same≥0.90 + 共现 fm 预算）要求「轨迹足够长且多机位同步」。**
> - 没有同步（MARS 类纯裁图基准）→ `evaluable` 恒为 0，判据整条失效；
> - 轨迹太短（CHIRLA，2–5 秒/条，a/b 各 2–3 帧）→ `same` 上不去 0.90，判据同样失效。
>
> 该判据的适用范围是"同步多机位 + 长轨迹"，这正是本系统部署的形态，但也意味着**它不能直接搬到公开基准上做横向比较**。

这三条（`evaluable` 依赖同步、`same` 依赖轨迹长度、θ 网格依赖 K）都是评价方法学论文该写的东西，而且是从两个公开数据上实测出来的，不是推断。

### 6.4 加密采样（stride 12→3，10 FPS）：帧数确实是瓶颈，但收益被聚类吃掉

设计**与 6.2 完全同构**（seq_000 前 60% 图库 / 后 40% 查询，7 机位同步、同一切分帧 5350/8916），唯一变量是采样步长 4×（2.5 → 10 FPS）。产物 `validation/chirla_s3/`，检测 7 机位 2 lane 约 105 min。

**表 1 · 规模与检索层**

| 项 | stride 12（2.5 FPS） | stride 3（10 FPS） |
|---|---|---|
| 图库 / 查询轨迹 | 121 / 75 | 187 / 102 |
| 有身份查询 | 61 | **78（+28%）** |
| 每半帧数中位（图库/查询） | 14 / 14 | **43 / 44** |
| 查询→图库 top-1（无聚类） | 77.0%（47/61） | **84.6%（66/78）** |
| 同人 / 异人余弦 | 0.763 / 0.589 | 0.767 / 0.608 |
| AUC | 0.845 | 0.843 |

**表 2 · 判据与聚类层**

| 项 | stride 12 | stride 3 |
|---|---|---|
| 正式判据（same≥0.90）可行点的最大覆盖 | θ=3.00｜cov **0.013（1/75）**｜same 1.0｜fm 0｜可评估 3 对 | θ=2.50｜cov **0.147（14/102）**｜same 0.933｜fm 18.2%｜可评估 22 对 |
| 该点精度 | —（1 条，无意义） | C 8 / W 3 / U 3｜精度 **0.727**｜C/78 0.103 |
| 有身份簇混人率（thr_in 0.15） | 3/22 = **14%** | 7/28 = **25%** |
| 簇内轨迹数中位 | 2 | 1 |
| 判定 | 无法判定 | 无法判定（接受 14 < 门槛 30） |

**三条判读：**

1. **"帧不够"确实是判据贴地的直接原因之一**：加密 4× 后可行点的覆盖从 0.013 抬到 0.147（1 条 → 14 条），检索层 top-1 也涨 7.6pp。这部分假设成立。
2. **但抬起来不等于可用**：`same` 随 θ 上升，要压到 ≥0.90 必须把 θ 推到 2.50，而 θ 一高覆盖就掉。10 FPS 只是把"1 条查询"变成"14 条"，离 30 条的可判门槛还差一半。**再加密一倍也到不了**——因为 `same` 与覆盖在曲线上是反向的，这个矛盾不是采样率能解的。
3. **聚类层被加密打得更差**：每条相机内的同人轨迹更碎（簇内轨迹数中位 2→1），同时"桥"更多 → 混人簇 14%→25%，fm 0%→18.2%，工作点精度掉到 0.727。**检索层的增益在聚类层被吃回去**，这是 1012 上"同质增加 ≠ 更好"的第五个实例（前四个：l-seg、DINOv3、扩图库、纯 detect）。

**剂量反应（两版合并，按整条轨迹帧数分箱）**——支持"主因不只是帧数"：

| 整条轨迹帧数 | n | a/b 自一致余弦中位 | ≥0.90 占比 |
|---|---|---|---|
| 6–10 | 113 | 0.869 | 27% |
| 11–20 | 97 | 0.868 | 28% |
| 21–40 | 89 | 0.861 | 34% |
| 41–80 | 92 | 0.869 | 33% |
| 81+ | 94 | **0.890** | **46%** |

帧数从 10 增到 80，一致率只从 27% 到 46% —— 斜率很缓。原因是**异人余弦本身就有 0.59–0.61**，这条数据上的人与人外观距离本来就小（8 个人、同一场景、着装相近）。所以短轨迹问题不只是"帧不够"，还有"人本来就像"。

**结论：这条关掉了"多采帧就能让判据可用"的假设。** 要让 CHIRLA 这类数据可用，只有改成像（更高分辨率/更多视角）或改判据（例如把 same 定义在 top-1 一致而非同簇），不是加采样密度。
