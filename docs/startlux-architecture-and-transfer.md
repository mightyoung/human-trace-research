# StartLux-Decision 结构解剖与迁移设计（选择器 / 路径预测器）

> 日期：2026-10-17 ｜ 对象：StartLuxLabs/StartLux-Decision v1.1（arXiv 2610.17309）
> 目的：回答两个问题——① 它是不是 BERT 结构，能不能当我们的基座；② 它的"决策模型"设计里，
> 哪些能搬到身份选择器与轨迹意图预测器上。
> 证据分级：【代码】= 读仓库源码；【论文】= 技术报告；【实测】= 本机跑出的数；【推断】= 由前三者推导。

---

## 0. 结论（先行）

**1）它不是 BERT。** 它是 **Qwen3.5 系混合注意力 decoder**（线性注意力层 + 每 4 层一个全注意力层），
Instant 版只是把 **full-attention 层在 prompt 上改成双向**，线性和其余结构仍是因果 decoder。
"双向"是训练时学出来的读法，不是换了一个 BERT 编码器。【代码 bidirectional.py / 论文】

**2）它的"选择器"本质是：把选项写进 prompt，用 LM head 读选项字母的 logits，再做温度缩放 softmax。**
没有分类头、没有额外的选项嵌入——这是它和我们最大的结构差异，也是最值得抄的一点。【代码 prompt.py:107-157 / readout.py:18-25】

**3）基座不能直接换成它。** 0.8B 起步、权重 CC BY-NC、本机无 CUDA（5700XT 8GB 只能 llama.cpp+GGUF）。
我们的选择器是 768d 向量输入、125 类、1126 条训练轨——用 0.8B 语言模型做这件事，参数量放大 1000 倍，
训练数据却少 4 个数量级。【推断 + 实测环境】

**4）可迁移的是判定结构，不是模型。** 已实现并实测：`tools/selector_setmatch_study.py`
（选项即 token + 双向集合编码 + 显式 none + 温度/覆盖率标定），0.7M 参数，与现役余弦库同口径对照。
结果见 §3.3–§3.4：端到端 125 类失败，top-8 重排序成立（+7.2pp / 疑难段 +20.2pp）。

**5）路径预测器不要换基座。** 现有 `intent_model.py` 已经是 BERT 范式（d=256/4 层/4 头），
需要的是**读出层改造**（序数 score 头 + 弃权类），不是更大的 decoder。

## 1. 结构解剖

### 1.1 三层结构

```
┌─ 表示层 ─────────────────────────────────────────────┐
│ Qwen3.5 混合解码器：3/4 层线性注意力（Gated DeltaNet  │
│ + 短因果卷积），1/4 层全注意力；262,144 ctx；视觉塔冻结 │
│ （论文未点名基座；证据 = GGUF 键 qwen35.* + 层类型）    │
├─ 接口层 ─────────────────────────────────────────────┤
│ 固定 system 句 + Evidence/Question/Options 模板        │
│ 选项写成 "A) ..."，答案 = 末位 token 上 A–Z 的 logits  │
│ p_k = softmax(z_k / T_type)   ← T 在留出集上拟合       │
├─ 决策层 ─────────────────────────────────────────────┤
│ gate(0.6) → 不确定才 think → 二次读出 p1 → 混合 0.75   │
│ 可选第 K+1 个选项 "None of the above" → none_probability│
└──────────────────────────────────────────────────────┘
```

【代码】`prompt.py:25` 的 system 句是训练格式的一部分；`prompt.py:28` `MAX_OPTIONS=26`；
`readout.py:18` `probabilities(z, temperature)` 就是 `softmax(z/T)`；`modelcfg.py` 从
`decision_config.json` 读 `temperature_by_type`、`letter_token_ids`、`wide_choice`。

### 1.2 "双向"到底是什么

`backends/bidirectional.py:1-30` 写明：
- **full-attention 层**（每 4 层一个）：prompt 内所有 token 互相可见，包括末位的读出位置；
- **linear-attention 层**（Gated DeltaNet + 短卷积）：**保持因果**，与 stock forward 完全一致；
- 该行为由训练得到，推理时靠 vLLM 插件或 GGUF 的 `qwen35.attention.causal=false` 复现；
  读成因果会掉分（4B 在 DecideBench 掉 27 分）。【代码 deployment.md】

论文补充：4B/9B 是 32 层、其中 8 层全注意力。【论文】

**所以严格说：它是"prompt 双向的 decoder"，不是 encoder。**
Qwen 系 decoder 的自回归能力用于 AutoThink 的思考，Instant 只是把同一次前向读成判别式。

### 1.3 读出层（最值得抄的部分）

| 设计 | 实现 | 为什么有效 |
|---|---|---|
| 选项即 token | 选项渲染进 prompt，读 A–Z 的 logits | 候选集可变（增删身份/换题）不需要改输出层；复用预训练语义 |
| 无分类头 | 直接用 LM head | 没有新初始化的头，少一个过拟合源 |
| 温度缩放 | 每个问题类型一个 T，留出集拟合，T>1 | 校准与排序解耦；实测所有 T 都 >1，即原始输出过度自信 |
| 位置去偏 | 选项顺序**哈希置换**（训练）| 防止"总选 A" |
| 显式 none | 第 K+1 个选项，读出后重归一化 | 开放集拒识变成可学习的比较项 |
| 长选项表 | >26 时 knock-out：25 一组读、组内前 3 进决赛，落选者按组内比例分 0.001 | 把 O(K) 的 prompt 压到 O(26·⌈K/25⌉) |

【代码 prompt.py:107-157、readout.py、api.md；论文 Stage 1】

### 1.4 训练三阶段（决定了它为什么"敢报概率"）

| 阶段 | 数据 | 关键动作 |
|---|---|---|
| S1 全参 SFT | Lux-Release ~270 万例（27B 用 ~80 万） | 在末位直接对**选项分布的软交叉熵**；选项位置哈希置换；训练后**按类型拟合温度** |
| S2 Adapter | Lux-Rounds ~170 万例 | Instant：全注意力层改双向；AutoThink：保持因果；**多 seed 权重平均**后重拟合温度 |
| S3 推理 + RL | Lux-Think 每模型 4k–21k 条 | 先推理监督，再 **RLCD²**：奖励 = 恰当评分规则增益 − 软长度惩罚（λ=1e-4, B=3072），GRPO 类，只对 p₀<0.9 的题训练 |

【论文】关键洞察：**决策训练会破坏"会不会思考、什么时候停"**——4B 约 40% 的题几乎不推理、9B 约 70% 一直写到上限。
这是我们做任何"级联/二次判定"时都会遇到的同构问题（见 §4.2 的门控设计）。

## 2. 与我们选择器的结构对照

| 维度 | 现役 IdentitySelector v2 | StartLux-Decision | 可迁移性 |
|---|---|---|---|
| 输入 | 768d ReID 向量 | 文本 / JSON / 图像 | ✗ 不同模态 |
| 类别表示 | 412 个子原型（矩阵一行） | prompt 里的字母选项 | ✓ **可迁移**：原型当 token |
| 打分 | 余弦 + 簇内 max | LM head 点积 + softmax | ✓ 点积读出等价，可学 |
| 校准 | per-cam 阈值 + margin（直角边界） | 温度 + none 比较 | ✓ **可迁移** |
| 开放集 | 阈值 + margin | 显式 none 选项 | ✓ **可迁移** |
| 计算 | 1 次矩阵乘（~1ms） | 1 次前向（25–52ms，H200） | ✗ 成本高两个数量级 |
| 增删身份 | 重建 npz | 改选项列表，零训练 | ✓ **可迁移（最有价值）** |
| 训练数据 | 无监督聚类，无需标签 | 270 万条监督 | ✗ 数据量差 4 个数量级 |

**最关键的一条**：现在的架构里，"身份"绑在原型库的行号上；一旦要加人，只能重建库、重校阈值。
选项即 token 的写法把"加人"变成"往候选列表里加一个 token"——这是本项目真正的痛点（新点位/新人员上线）。

## 3. 选择器 v3 设计（已实现）

### 3.1 结构

```
query: 768d 向量 ──Linear──▶ 1 个 query token
候选: 每簇 ≤4 个子原型 ──Linear──▶ 最多 4 个 option token（不加身份 id 嵌入！）
序列: [query] + [opt_1..opt_M]        ← 双向 TransformerEncoder（3 层/d=128/4 头）
读出: logit_k = <W_q·h_query , mean(h_opt_k)> · s + b
      logit_none = <W_q·h_query , g_none> · s + b     ← 学出来的第 K+1 个选项
损失: CE([K 个候选 + none], 标签)，label smoothing 0.05
```

三点对应关系：
- **不加身份 id 嵌入**，只用原型内容——与 StartLux 不把选项 id 写进读出、只写描述同构；
- **none 是真选项**，与候选一起 softmax，而不是后处理阈值；
- 训练时按 26 个候选采样，**25% 的概率把正例从候选里拿掉**并标成 none（教"没有这个人"）。

参数量 **0.7M**（≈ 0.8B 模型的 1/1100）。

### 3.2 实验口径

- 基聚类：与 `selector_upgrade_study` 同一代码路径（mutual-knn k=5 thr=0.3 → 269 簇 → 保留 125），
  **复现一致**（F1 0.8456，125 簇）【实测】；
- 原型：multi8，412 子原型；
- 训练 1126 轨（留 10% 做早停），val 238 轨定阈值，test 348 轨只报数；
- 对照：同一 multi8 余弦库，**同一 test、同一覆盖率**（阈值都在 val 上按目标覆盖率取，比原报告
  "test 上扫阈值"更严）；
- 指标：same_known / coll_known / coverage，定义同 `selector_upgrade_study.eval_wp`。

<!--RESULTS-->

### 3.3 结果 A：端到端 125 类判定 —— 不成立

模型在 125 个候选上直接判定（含 none 拒识），阈值在 val 上按目标覆盖率标定，test 348 轨：

| 目标 cov | 方法 | 实际 cov | same_known | coll_known |
|---|---|---|---|---|
| 0.2 | 余弦 multi8 | 0.210 | 0.918 | 0.041 |
| 0.2 | **SetMatcher** | 0.322 | 0.955 | **0.120** |
| 0.4 | 余弦 multi8 | 0.405 | 0.894 | 0.032 |
| 0.4 | SetMatcher | 0.336 | 0.949 | 0.120 |
| 0.6 | 余弦 multi8 | 0.589 | 0.873 | 0.032 |
| 0.6 | SetMatcher | 0.336 | 0.949 | 0.120 |

两点观察【实测，单种子】：
1. **覆盖率上不去**：none 比较把 2/3 的轨挡在门外，最多只到 0.336；
2. **误合并翻 3 倍**：coll 0.120 vs 0.032。same 高了 3.7pp，但代价是随机两轨被判同人的概率从 3.2% 涨到 12%
   ——在身份计数场景里这是不可接受的（合并错误会直接改人数）。

诊断：1126 条训练轨 / 125 类 ≈ 每类 9 条，CE 训练会塌向大簇（预测唯一簇 54 个，最大簇占 10.1%，
余弦是 69 个 / 7.2%）。**这不是结构问题，是数据量问题**。

### 3.4 结果 B：余弦 top-8 内重排序 —— 成立

把模型降级为**重排序器**：候选集固定为余弦 top-8，模型只决定这 8 个里选谁（不参与召回、不参与拒识）。
这样开放集问题退化为闭合集比较，错误上界被余弦候选集锁住。全判定（348 轨，无弃权）：

| 口径 | 方法 | same_known | Cohen κ | 唯一预测簇 | 随机对同簇率 |
|---|---|---|---|---|---|
| 全部 348 轨 | 余弦 top-8 | 0.8017 | 0.7954 | 69 | 0.0289 |
| 全部 348 轨 | **SetMatcher 重排** | **0.8736** | **0.8672** | 54 | 0.0436 |
| 疑难 40%（n=139） | 余弦 top-8 | 0.5971 | 0.5829 | 49 | 0.0308 |
| 疑难 40%（n=139） | **SetMatcher 重排** | **0.7986** | **0.7876** | 41 | 0.0434 |

配对 bootstrap（2000 次，按轨重采样）：

| 子集 | Δ same（模型−余弦） | 95% CI | P(Δ>0) |
|---|---|---|---|
| 全部 | **+7.2pp** | [+2.6, +11.8] | 0.999 |
| 疑难 40% | **+20.2pp** | [+10.8, +29.5] | 1.000 |

κ 一并上升（0.795→0.867；疑难段 0.583→0.788），说明增益不是"两边都塌到大簇"造成的偶然一致。
**代价**：随机对同簇率从 2.9% 升到 4.4%（+1.5pp），即误合并风险约 1.5 倍。

### 3.5 可复现

```bash
python tools/selector_setmatch_study.py --epochs 40 --tag v1    # 端到端，~8.5 min（CPU）
python tools/selector_setmatch_rerank.py --tag v1 --topk 8      # 重排序，~20 s
# 产物：output_crosscam/analysis/selector_setmatch/{study_v1.json, rerank_v1.json, model_v1.pt}
```

**边界（未粉饰）**：
- 单种子、单次切分；same_known 是"同轨两视图自一致"，**不是真值标签**，κ 只能扣掉边际塌缩，扣不掉系统性同错；
- 基聚类是伪标签，模型学的是伪标签的边界，天花板受聚类质量限制；
- 未做跨日/跨点位复现；`coll` 是随机对代理，不等于真实合并率；
- 未做 seed 平均、未调 top-k（8 是拍的）、未接倒影门与 margin 档；
- 训练负例是**随机 25 个**，而评估候选是**余弦 top-8 硬负例**——即模型从未专门学过"分辨近邻"，
  这解释了为什么它的增益集中在疑难带却仍有明显 headroom：改用 hard-negative 采样应还能再涨。
- 模型未加位置编码（对候选集置换不变），与 StartLux 用"选项位置哈希置换"防位置偏置同构。

## 4. 路径预测器的迁移判断

### 4.1 不建议换基座

`tools/intent_model.py` 已是 BERT 范式（投影 7→256、CLS、位置编码、4 层 4 头、CLS 线性头 5 类），
test acc 66.8%、macro-F1 0.477。换成 0.8B decoder 的代价：

| 项 | 现模型 | 换 0.8B |
|---|---|---|
| 参数 | ~2M | 800M（×400） |
| 训练数据 | 9063 样本 | 同（更易过拟合） |
| 输入 | 7 维物理量 | 需 tokenize 成文本，丢失数值精度 |
| 延迟 | <1ms/序列 | 数十 ms 起 |
| 许可 | 自有 | CC BY-NC |

**结论：换基座是负收益。** 它的价值在读出层与训练法，不在骨干。

### 4.2 值得搬的三点

**① 序数读出（`score` 类型）替换 5 类 softmax。**
现模型的混淆集中在 `backward ↔ stop`（65% 的折返被判成停下）——两者在"纵向进度"上是**相邻**的，
5 类 softmax 把它们当无关类别，错就是全错。改成两个有序 score 头：
- 纵向：`{后退, 停, 前进}`，读出为概率加权均值；
- 横向：`{右, 直, 左}`。
则"折返误判为停"变成相邻档误差，下游可用期望位移而不是硬标签，macro-F1 与可用性都会改善。
StartLux 的 `score` 读出（2–10 档、概率加权均值 + confidence）正是为这种有序判断设计的。【代码 readout.py:35-43】

**② 弃权类 + 覆盖率语义。**
他们承认"折返不可从 2.4s 轨迹史可靠预判"，正确的工程回应不是硬猜，而是**允许 abstain**：
加一个 none/unknown 类，报"覆盖率–准确率"曲线而不是单一 acc。
`intent_model_cc.py` 已有 id_emb/unknown 的雏形，可扩展到 none 读出。

**③ 门控级联（AutoThink 的 gate）。**
只在 p₀ 低时调用更重的模型（例如用未来 0.5s 的观测做二次判定，或调用 SetMatcher 复核身份）。
他们的经验值可作先验：gate=0.6 时多数请求单趟解决；但**训练目标会破坏"该不该继续"的判断**，
所以门控必须在**独立留出集**上校准，不能跟着主损失一起训。【论文 S3】

### 4.3 不建议搬的

- RLCD²：需要可验证奖励 + 大量采样，9k 样本的 5 类任务上不成立；
- 长选项 knock-out：125 类在离线场景一次读完（125×4 token）成本可接受，无需分组；
- 视觉读出：监控裁剪分辨率低，且权重非商用。

## 6. 结论

1. **基座问题有明确答案**：不是 BERT，是 prompt 双向的 Qwen3.5 decoder；换基座不成立。
2. **结构问题也有明确答案**：选项即 token + 显式 none + 温度校准这三件事，可以脱离语言模型实现，
   已落地为 0.7M 参数的 SetMatcher（§3）。
3. **选择器的现实路线（有实测支撑）**：
   - 余弦库继续做召回 + 开放集拒识（它的阈值/间隔已经校准得很好，别动）；
   - SetMatcher 只做**余弦 top-8 内的重排序**：全量 +7.2pp、疑难段 +20.2pp（κ 同向上升，非塌缩假象），
     代价是随机对同簇率 2.9%→4.4%；
   - **不要**让它做 125 类端到端判定：coll 会从 3.2% 涨到 12%，覆盖率也被 none 卡在 0.34；
   - 身份增删走"加候选 token"，不重训——这是选项即 token 相对分类头的真实收益。
4. **路径预测器的现实路线**：不动骨干，改读出（序数 + 弃权）与门控。
5. **下一步的判定线**（若要把重排序器推到生产）：换 2 个种子复跑并做 seed 平均；
   在跨日/跨点位切分上复现 +7pp；把 coll 压回 ≤3.5%。三条任一不达标，就只保留"离线复核"用途。
