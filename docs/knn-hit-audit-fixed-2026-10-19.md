`eval_pose_prototypes.build_protos(kind="knn")` 返回的原型表**按簇分组重排**：

```

protos[k] == T[order[k]]，order = 按簇顺序展开的 ktr 索引
```

我第一版直接写 `ja = argmax(...)` 然后 `ktr[ja]`，把「原型表位置」当成「轨迹索引」用，
于是 18 张图画出的"命中成员"全是**另一个人**。这解释了为什么黄框与绿框毫无相似度。

**打分本身没有受影响**（`cluster_scores` 用 `pcl` 与 `protos` 配套，簇内取 max 是正确的），
出错只在「反查出命中的是谁」这一步。因此 1-NN 的 cov 0.7205 这个数字仍然有效。

**修法**（`tools/render_knn_hit_audit.py`）：不用 `build_protos`，自己构造与 ktr 同索引的原型表：

```python
T = _norm(Vtr - mu_g)
col_of = np.full(len(ktr), -1, np.int32)
for ci, c in enumerate(kept):
    col_of[lab == c] = ci

# argmax 得到 protos 位置 → int(keep_idx[pos]) 即 ktr 索引
```

## 2. 仍然成立的观察（不依赖原型索引）

### 2.1 z 校准不是主因

把 z 校准换成 raw 簇内 max 余弦直接 argmax，**18 条里只有 2 条改判**（#860、#1015，都是小簇之间互换）。
→ 这 18 条在未校准的绝对相似度下就已经选到了同一个簇，不是校准把它们推歪的。

### 2.2 小簇占比高

18 条中 size=2 的 6 条、size 3–4 的 4 条（合计 **10/18 来自 size≤3**）。
全库 size 分布未统计，暂不下"小簇更易吸人"的结论，只能说命中集中在少数小簇。

### 2.3 三条不同 query 命中同一个原型

`320_test#1015`、`#828`、`#916` 三条**都命中 `320_train_514#183`**（size=2 簇的成员）。
三条 query 的外观：黑T扎发年轻男 / 黑T年轻男 / 另一个年轻男；时间区间不重叠。
**若这三条不是同一个人，则至少 2 条必错。** 这一点需要目检确认（新图 15/16/17 三页）。

### 2.4 余弦无法区分"同一个人"与"极像的别人"

用**全库轨迹级 top-1 余弦**（229×579，不经聚类、不经校准）对照已有真值：

| 组 | n | top-1 余弦 p50 | <0.55 |
|---|---|---|---|
| 33 条目检**判对** | 14 | **0.624** | 21% |
| 33 条目检**判错** | 19 | 0.506 | **79%** |
| 本次 18 条（判定待定） | 18 | **0.634** | 28% |

用 top-1 余弦区分「判对」与「判错」两组：**AUC = 0.571**（0.5 = 无判别力）。

含义：**错误分两类**。一类是「图库无此人」，top-1 低（判错组 79% 属此类），能被阈值挡；
另一类是「图库有个极像的别人」，top-1 高，**与真匹配的分数分布重叠，任何余弦阈值都挡不住**。
T-norm / AS-norm / knn / 竞争簇校正 / 每机位原型 的失败都能由这一条解释。
