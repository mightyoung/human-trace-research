## 结论先行（TL;DR）

1. **两个场景共用一套模型与事件模型，只换采集适配层和确认策略。** 检测器、类别（fire / smoke / plume）、事件 schema、告警网关完全复用；园区差异在"抓图 + 轮询"，机器狗差异在"连续 + 停步复检"。**不要做两套系统。**
2. **园区轮询的算力不是瓶颈，接入方式与误报预算才是。** 200 路 @ 1 帧/5 s = 40 fps，单卡占用约 10%，纯 CPU 约 7.3 核；真正的坑是"为 200 路常开 200 个 ffmpeg 进程"。**抓图优先，RTSP 兜底。**
3. **"发现即报警"必须拆成两级，否则系统会被关掉。** 单帧即响铃：200 路、单帧误报率 1e-4 时是 **345 条/天**（值班复核约 17 小时/天），不可用；"2/3 帧命中 + 面积增长"后报警：**11.5 条/天、35 分钟/天**，时延仅 3–8 s。**"即时"是可以保住的，"单帧"不行。**
4. **误报预算决定采样率，不是反过来。** 先定"每天最多几条告警"，再反推单帧误报率上限与抽帧间隔。100 路 @10 s 时，1e-4 的模型只有 2.9 条/天；同样模型 200 路 @5 s 是 11.5 条/天。**采样率每翻一倍，误报翻一倍。**
5. **机器狗的核心不是模型，是"停—稳—复检"。** 运动模糊、视角变化、自身抖动会让单帧误报翻倍；停步 1 s + 8 帧复检在实测中可把误报压一到两个数量级（等效值，需回放验证），代价 3–5 s。**但停步是提高证据质量的手段，不是报警前置**——高置信目标允许在运动中先发预报警。
6. **曝光是机器狗的隐形杀手。** 火焰高光会让自动曝光压暗背景，烟的低对比度特征直接消失；自动白平衡还会把火焰的色温特征抹平。**曝光/白平衡必须锁定或按场景实测选择（AE / 锁定 / HDR 三者对比），不能预设关闭 HDR**，否则同一套模型在狗上必崩。
7. **分工比叠加更有价值：摄像头触发，机器狗到点复核。** 园区摄像头负责广域常开，狗负责盲区巡逻与"告警现场确认"。**双证据（相机 + 狗）比任何单点置信度都可靠**。
8. **验收口径**：园区 ≤0.2 条告警/路/天（200 路 ≈ ≤40 条/天）、事件召回 ≥90%、时延 P90 ≤10 s；机器狗 ≤0.5 条/班、3 m 内 ≥2 s 可见烟漏检 ≤5%、时延 ≤5 s。**这些是建议值，需 S2/S4 实测校准。**

## 二、共同架构

```
                 ┌─────────────── 事件总线 ───────────────┐
摄像头适配器 ─┐   │ candidate → suspected → confirmed → cleared │   ┌ 值班台
（抓图 / RTSP）├─L1┤ 统一 schema · 去重 · 冷却 · 升级 · 降级      ├─L4┼ 手机推送
机器狗适配器 ─┘   │ 证据：命中帧数 / 面积增长 / 时长 / 机位集合   │   └ 声光 / TTS
                 └──────────────────┬─────────────────────────┘
                                    │
                          L2 时序复检 · L3 共识/定位
```

| 层 | 园区 | 机器狗 | 复用度 |
|---|---|---|---|
| L0 采集 | 抓图 0.2 fps（可分层） | 连续 15 fps + 3 s 环形缓冲 | 适配层不同 |
| L1 检测 | YOLO-n 640，fire/smoke/plume 三类 | 同一模型（可换 INT8） | **完全复用** |
| L2 时序 | 短窗 2 s burst（4 fps × 8 帧）+ 长窗 30 s–5 min 趋势并行 | 停步后 8 帧 + 前 3 s 缓冲 | 规则复用，取帧不同 |
| L3 决策 | 多机方位角共识 | 位姿 + 单机多帧 | 逻辑复用 |
| L4 告警 | 同一网关、同一 schema | 同一网关、同一 schema | **完全复用** |

### 2.1 统一事件 schema

```json
{
  "event_id": "fs-20261018-234012-b2hall-031",
  "ts": "2026-10-18T23:40:12.345+08:00",
  "source": {"type": "camera", "id": "cam-031", "site": "B2-hall", "pose": null},
  "state": "suspected",
  "class": "smoke",
  "score": 0.82,
  "bbox": [812, 340, 980, 512],
  "evidence": {
    "frames_hit": 5, "frames_total": 8, "duration_s": 2.0,
    "area_growth": 1.34, "centroid_up": true,
    "cameras": ["cam-031"], "rules": ["mask", "persistence", "growth"]
  },
  "media": {"snapshot": "/ev/031.jpg", "clip": "/ev/031.mp4", "pre_s": 3, "post_s": 10},
  "location": {"lat": null, "lon": null, "method": "none"},
  "policy": {"push": "silent", "ttl_s": 30}
}
```

**要点**：`state` 是唯一的状态源；`evidence` 必须可复核（人能看懂为什么报）；`media` 必须带前 3 s（否则值班员无法判断）。

## 三、场景 A：园区全量轮询

### 3.1 接入方式：抓图优先

| 方式 | 成本 | 时延 | 风险 | 建议 |
|---|---|---|---|---|
| **HTTP 抓图**（ISAPI/ONVIF snapshot） | 极低，无解码 | 0.2–0.5 s | 部分相机限流、需鉴权 | **首选** |
| RTSP + 关键帧（`-skip_frame nokey`） | 中，每路一个进程 | 取决于 GOP（2–4 s） | 200 进程吃内存与 fd | 抓图不可用时 |
| NVR SDK 集中取流 | 低（单连接多通道） | 中 | 绑定厂商、需授权 | 有 NVR 时优先 |
| 常开 RTSP 全帧解码 | 高（200 × 2 Mbps） | 低 | 带宽与 CPU 双爆 | **不推荐** |

**结论**：200 路抓图 @0.2 fps ≈ 80 Mbps、40 次解码/s（JPEG 解码约 5 ms/张 → 0.2 核），比常开 RTSP 低一个量级。

### 3.2 调度：分层 + 令牌桶 + 错峰

| 风险等级 | 典型区域 | 间隔 | 占比（示例 200 路） | 聚合帧率 |
|---|---|---|---|---|
| A 重点 | 配电房、仓库、充电桩、垃圾房 | 2 s | 20 路 | 10 fps |
| B 常规 | 走廊、大堂、车棚 | 5 s | 150 路 | 30 fps |
| C 低风险 | 周界、绿化带 | 10 s | 30 路 | 3 fps |
| 合计 | — | — | 200 路 | **43 fps** |

- **令牌桶**：43 fps 均匀铺开 = 每 23 ms 一帧，避免 5 s 周期末尾的 200 帧尖峰。
- **优先级抢占**：确认阶段的任务插队，L1 轮询让路 200 ms 不影响。
- **时钟**：统一 NTP；多机共识用服务器接收时间，不信任相机本地时间。

### 3.3 流水线与时延预算

```
抓图 → L1 检出 → candidate ──┬─→ 静默进控制台（≤1 s）
                             └─→ 拉 2 s burst（4 fps × 8 帧）→ 规则 → confirmed → 响铃
```

| 阶段 | P50 | P90 |
|---|---|---|
| 轮询等待 | 2.5 s | 5.0 s |
| 抓图 + 解码 | 0.3 s | 0.5 s |
| L1 推理 | 0.01 s | 0.05 s |
| burst 取帧（2 s） | 2.0 s | 2.2 s |
| 复检推理（8 帧） | 0.08 s | 0.1 s |
| 规则 / 共识 | 0.2 s | 0.3 s |
| 推送 | 0.5 s | 0.8 s |
| **合计** | **≈5.6 s** | **≈9.0 s** |

> 若不拉 burst、直接用 5 s 间隔的抓图做"连续 3 帧"，确认要等 15 s；**短窗 burst 是时延的关键**。
> 长窗（30 s–5 min 的面积/轨迹趋势）与短窗**并行**，不互相阻塞：弱烟候选可以先内部预警、后升级，不必等烟羽长大。

### 3.4 容量（计算器实算，规划值）

```
$ python tools/fire_capacity_calc.py campus --sweep
   路数    聚合fps      单卡占用      告警/天    复核min    带宽Mbps
   25      5.0      1.3%       1.4        4      10.0
   50     10.0      2.5%       2.9        9      20.0
  100     20.0      5.0%       5.8       17      40.0
  200     40.0     10.0%      11.5       35      80.0
  500    100.0     25.0%      28.8       86     200.0
```

- **算力**：500 路 @5 s 也只占单卡 25%，**不需要第二张卡**（冗余另算）。
- **CPU 路线**：200 路需 7.3 核（16 核机器可用）；500 路需 18.3 核，需 24 核以上并留余量。
- **带宽**：500 路 200 Mbps，园区千兆可承受；跨楼宇需确认上行。
- **存储**：事件 clip 8 MB × 29 条/天 ≈ 0.22 GB/天，可忽略；**别存全量抓图**。

### 3.5 "发现即报警"的代价（必须选一个）

| 口径 | 触发条件 | 时延 | 全园告警/天（200 路，p=1e-4） | 值班负担 | 判定 |
|---|---|---|---|---|---|
| 单帧即响铃 | 1 帧 ≥0.5 | ≤0.5 s | **345.6** | ≈17 h/天 | ❌ 不可用 |
| 候选静默 | 1 帧 ≥0.5 | ≤1 s | 345.6（仅状态灯，不推送） | 0 | ✅ 作为内部状态 |
| **即时报警（推荐）** | 2/3 帧 或 单帧 ≥0.85 | 3–8 s | **11.5** | ≈35 min/天 | ✅ 对人仍是"即时" |
| 确认报警 | 5/8 帧 + 演化证据（增长非必需） | 6–12 s | ≈3.5 | ≈10 min/天 | ✅ 用于联动/派单 |

**建议**：`candidate` 只点亮该相机的状态灯并留图；`suspected` 静默推送（控制台 + 手机，不响铃）；`confirmed` 响铃。**对值班员而言，"发现"到"响铃"仍是 3–8 秒，符合"发现即报警"的体感**；但系统内部保住了 30 倍的误报削减。

### 3.6 误报治理四件套（按性价比排序）

| 顺序 | 手段 | 实现 | 预期削减 |
|---|---|---|---|
| 1 | 几何掩膜 | 地平线以上、水面、道路、屏幕区域置黑；球机按 preset 切掩膜 | 30–50% |
| 2 | 镜头质量门 | 拉普拉斯方差（模糊）、暗通道（脏污）、过曝比例 → 低于阈值只存证不报警 | 10–20% |
| 3 | 时序 + 增长 | 2/3 帧命中；30 s 面积比 >1.2；质心向上 | 等效 10–30×（非独立假设） |
| 4 | 硬负样本 | 每日误报自动入库，按干扰源分桶，两周一训 | 逐轮下降 |

**夜间降级**：红外画面没有颜色信息，fire/smoke 模型会退化。策略：夜间只信"高置信烟雾 + 增长"，或训练一个 IR 专用小模型；**不要在白天模型上直接跑红外**。

### 3.7 球机与 PTZ

球机定时巡航会让掩膜与背景模型失效。两条路：
- **推荐**：只在 preset 停留时抓图（读 PTZ 状态，运动中去抖），按 preset 绑定 ROI。
- 备选：巡航中只用"无掩膜 + 高阈值"模式，误报会上升 2–3 倍。

## 四、场景 B：机器狗车载

### 4.1 与固定机位的六个差异

| 维度 | 固定机位 | 机器狗 | 后果 |
|---|---|---|---|
| 背景 | 长期稳定 | 每帧都在变 | 背景建模、掩膜全部失效 |
| 视角 | 固定俯仰 | 低视角、近距离 | 烟羽形态与训练集分布不同 |
| 运动 | 无 | 步态抖动、转向 | 运动模糊、rolling shutter |
| 曝光 | 场景稳定 | 火焰高光导致 AE 抖动 | 烟对比度消失 |
| 算力 | 服务器 | 25–40 TOPS、受限功耗 | 只能用 nano 级模型 |
| 网络 | 有线 | WiFi/5G，可能断 | 需本地缓冲与断点续传 |

### 4.2 状态机：发现即停，稳像再报

```
PATROL ──候选──> STOP ──0.8s──> STABILIZE ──1.0s──> RECHECK(8帧)
   ↑                                                    │
   │                                     confirmed ─────┤
   └────────── RESUME ←── 人工确认/60s ─── ALARM ←──────┘
```

| 状态 | 动作 | 耗时 | 失败处理 |
|---|---|---|---|
| PATROL | 15 fps 连续推理，3 s 环形缓冲 | — | 网络断→本地缓存 |
| STOP | 停步、锁定曝光、IMU 判定静止 | 0.8 s | 未静止→延长 0.5 s |
| STABILIZE | 等振动衰减；读最新 8 帧 | 1.0 s | 仍模糊→降级为"存证不报警" |
| RECHECK | 8 帧推理 + 演化证据（面积/质心为正向证据，非硬门；通风/横风下烟可横向或向下） | 0.5 s | <5 帧命中→回 PATROL |
| ALARM | 声光 + 推送 + 原地待命（不接近） | 0.5 s | 人工接管 |

> 高置信目标（如单帧 ≥0.9 且面积 >0.5%）允许在 PATROL 状态直接发"预报警"，停步只用于把预报警升级为确认。
> 机器人自身安全状态与视觉识别分离：未完成复检时不得继续接近疑似火源。

**总时延 P50 ≈ 2.8 s，P90 ≈ 4.0 s**。比园区快，因为不需要等轮询。

### 4.3 五类工程约束

| 类别 | 现象 | 对策 |
|---|---|---|
| **运动** | 步态抖动 → 模糊、框抖 | IMU 门控（角速度 > 阈值不推理）；全局快门相机优先；停步复检 |
| **曝光** | 火焰高光压暗背景；AWB 抹平色温 | 实测对比 AE / 锁定 / HDR，按场景选；不要预设关闭 HDR |
| **热** | 户外阳光 + 25 W → 降频 | 散热设计；温度 > 75℃ 降帧到 10 fps；避免正午长时巡逻 |
| **电** | 计算占整机比例 | 18 W × 4 h = 72 Wh，约占整机 <10%；**不是主要矛盾** |
| **网** | 电梯/地下室断网 | 本地 64 GB 缓冲；恢复后补传事件；告警带时间戳 |

### 4.4 巡逻与联动

- **航点**：按"摄像头盲区 + 高风险点"布点，不追求全覆盖；单班 4 h 覆盖 20–30 个点。
- **摄像头触发、狗复核**：园区 confirmed 事件若在狗的路径 80 m 内且电量 >30%，派单到点；狗到点后独立复检，**双证据才升级为"火警"**。
- **不替代**：狗不能替代常开摄像头；它是"移动的复核手段 + 盲区补盲"。
- **安全**：距火源 ≥3 m；不跨越楼梯/台阶执行告警；失联自动返航；告警中不接受新任务。

### 4.5 容量与续航（规划值）

```
$ python tools/fire_capacity_calc.py robot --fps 15 --hours 4
  每天处理帧数     1296000
  候选误报/班       21.600
  告警误报/班       0.1080
  边缘算力占用        25.0 %
  计算功耗            18.0 W
  每班计算耗电        72.0 Wh
  图传带宽             4.0 Mbps
```

- 15 fps × 12 ms = 25% Orin NX，余量足够跑第二个模型（如热成像）。
- 单帧误报 1e-4 × 停步复检等效 200× → 0.11 条/班（等效值，需连续录像回放实测，不是独立乘法）。
- **若去掉停步复检**（confirm=1）：21.6 条/班，狗会被召回 20 次——这就是"停—稳—复检"的存在理由。

## 五、统一告警网关

| 规则 | 逻辑 | 目的 |
|---|---|---|
| 去重 | 同 source + 同 bbox IoU>0.5 + 60 s 内合并 | 一条事件一个 ID |
| 冷却 | 同相机同类别 30 min 内不重复响铃 | 防止持续燃烧刷屏 |
| 升级 | 第二路相机 / 狗确认 → `confirmed` | 双证据 |
| 降级 | 人工标记"干扰" → `cleared` + 入负样本库 | 闭环 |
| 路由 | suspected→静默；confirmed→响铃+手机；双证据→电话 | 分级打扰 |
| 超时 | 30 s 未确认自动升级或丢弃（按类别） | 防漏 |

## 六、验收指标

| 指标 | 园区 | 机器狗 | 测法 |
|---|---|---|---|
| 误报 | ≤0.2 条/路/天（200 路 ≤40/天） | ≤0.5 条/班 | 影子期按日统计 |
| 事件召回 | ≥90%（≥30 s 可见烟） | ≥95%（3 m 内 ≥2 s） | 人工点火/烟雾弹，或历史火情回放 |
| 发现时延 | P50 ≤6 s，P90 ≤10 s | P50 ≤3 s，P90 ≤5 s | 打点日志 |
| 定位 | 单机方位角；多机 ≤100 m | 机位坐标 ±2 m | 现场比对 |
| 可用率 | ≥99%（含镜头质量告警） | ≥95%（单班） | 运行日志 |
| 值班负担 | ≤60 min/天 | ≤10 min/班 | 复核记录 |
| 算力余量 | ≥50% | ≥50% | 压测 |

**三级放行**：影子（只记录）→ 试用（静默推送）→ 生产（响铃）。**任何一级不达标不得跳级。**

## 七、实施路径

| 阶段 | 内容 | 判定标准（完成=可验证） |
|---|---|---|
| **S0 素材与真值**（2 周） | 园区选 20 路 + 狗跑 10 条航线；采集 200 段含正负样本；人工标事件边界 | 正样本 ≥60 段、负样本 ≥140 段；每段有起止时间 |
| **S1 模型适配**（2 周） | D-Fire/FASDD 预训练 → 本地硬负样本微调；三类输出 | 本地负样本单帧误报 ≤1e-3；正样本召回 ≥85% |
| **S2 园区试点**（3 周） | 20 路影子运行；抓图链路压测；误报预算看板 | 连续 14 天有 FP/路/天 数字；带宽/时延达标 |
| **S3 全园扩容**（2 周） | 200 路接入；令牌桶调度；burst 复检 | 峰值 CPU/GPU 不超 70%；P90 时延 ≤10 s |
| **S4 机器狗适配**（3 周） | 停步复检、曝光锁定、热测、断网缓冲 | 8 h 连续跑；误报 ≤1/班；无热降频宕机 |
| **S5 联动验收**（8 周） | 摄像头→狗派单；双证据升级；出验收报告 | 完成 ≥3 次端到端演练；指标全表达标 |

**前置依赖**：园区抓图权限 + 20 路试点清单；机器狗型号与相机安装方案；点火/烟雾测试的安全审批。

## 八、风险与未知（诚实清单）

1. **路数与品牌未知**：本方案按 200 路示例，实际容量用计算器替换；若为 500 路以上，需确认上行带宽与 NVR 取流能力。
2. **抓图权限未知**：部分园区只给 NVR 客户端，不开放 ISAPI/ONVIF；若只能 RTSP，进程模型要改为"集中拉流 + 关键帧"，内存与 fd 需重算。
3. **模型未训练**：所有延迟/误报为规划值；1e-4 的单帧误报率对烟火任务是乐观假设，S1 可能达不到，届时要降采样率或加规则。
4. **球机 PTZ**：若大量球机定时巡航，掩膜方案需按 preset 重建，工作量翻倍。
5. **夜间红外**：现有公开数据以可见光为主，IR 模型需自采；夜间指标可能显著低于白天。
6. **机器狗安全**：靠近火源的热辐射、地面湿滑、楼梯，均需现场规程；本方案只给技术约束，不替代安全作业制度。
7. **合规**：本方案定位"辅助预警"，不接消防联动、不作为法定探测；若要走认证线，需按《图像型火灾探测器》新国标 / FM 3232 另立项目。
8. **误报治理人力**：没有专人做负样本回流，任何模型的误报都会在 3 个月内反弹；这项人力必须写进运维预算。

## 附录：计算器参数含义

| 参数 | 默认 | 含义 | 性质 |
|---|---|---|---|
| `--interval` | 5 s | 每路抓图间隔 | 设计值 |
| `--latency-ms` | 8 ms | 单帧端到端（GPU） | 规划，未实测 |
| `--cpu-latency-ms` | 110 ms | 单帧端到端（CPU） | 由本项目 YOLO@1280 实测 350 ms 按像素比外推 |
| `--fp-frame` | 1e-4 | 负样本单帧误报率 | **最关键假设**，S1 实测替换 |
| `--confirm-factor` | 30（园区）/ 200（狗） | 时序+几何+多机对误报的等效削减 | 规划，S2/S4 实测替换 |
| `--gpu-fps-capacity` | 400 fps | 单卡吞吐（640 输入） | 规划 |
| `--snapshot-kb` | 250 KB | 单张抓图 | 1080p JPEG q80 经验值 |
| `--review-min` | 3 min | 单条告警复核 | 含看片与记录 |

**用法**

```bash
# 园区：按实际路数替换
python tools/fire_capacity_calc.py campus --cameras 200 --interval 5

# 敏感性：模型误报率差 10 倍会怎样
python tools/fire_capacity_calc.py campus --cameras 200 --fp-frame 1e-3

# 机器狗
python tools/fire_capacity_calc.py robot --fps 15 --hours 4

# 输出 JSON 接看板
python tools/fire_capacity_calc.py campus --cameras 200 --json
```
