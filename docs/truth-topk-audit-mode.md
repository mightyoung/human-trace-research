# 真值采集改为「Top-K + 随机审计」模式（2026-10-14）

**一句话**：把 343×316 的 241 条跨机配对的判定成本，从"全表"压到"**同一人工预算 50 条**"，
并在页面实时显示"这个预算买到了多少同人 / 选择器排序有多准"，用来支撑 H1/H2 的
"**同预算下更少误接、更少漏接**"这一验收口径。

## 1. 为什么要改

- 241 条逐条判的成本远高于我们能付的人工预算；
- 已有的 19 条判定集中在"高信号"区，**不是**随机抽样 → 直接拿它算召回/误接率是有偏的；
- 外部借鉴（`docs/rsi-anything-transfer-note.md`）：RSI-Anything 的核心纪律是
  **"同一调用预算下比成功率"**（静态验证器 26.3% → 固定世界模型选择 29.2% → 适配后 31.2%，而**在线调用数不变**）。
  我们把它落到真值采集：**用预测器决定"把有限人工花在哪几对"**，同时**留随机审计**防闭环。

## 2. 选择器（不依赖人工标签）

```
pred = cos_appear + λ · ln w_dt(dt)          λ = 0.01
```

- `cos_appear`：全局 ReID 库（`analysis/global_reid/store_cradio_v4`）实体嵌入的余弦；
- `w_dt`：Parzen 过渡时间先验，取自 `output_crosscam/analysis/relay_v2/dist_v1.json`
  （0.5s 网格，-5…65s，峰值 4.5s）；
- ★ **独立性**：`dist_v1.json` 的拟合集是 47 条 relay primary 边**剔除全部已人工判定行**后的 41 条
  → **选择器与人工真值不共享信息，评价不构成自证**。

## 3. 三个分层与预算

| 层 | 规模 | 抽取规则 | 作用 |
|---|---|---|---|
| `topk` | 30 | 按 `pred` 名次贪心，**逐事件度数 ≤2**（故意允许竞争，以暴露互斥冲突） | 高收益区，把预算花在这里 |
| `audit` | 20 | 从「剩余 **且** 未预先判定」的对中**随机**抽，`seed=42` | **无偏**估计其余层同人率（外推的基础） |
| `rest` | 191 | 其余 | 默认不显示 |

**预算 = 50**；页面「★ 建议判定」默认只显示这 50 条，先判完再谈其余。

## 3.5 保存方式（显式按钮 + 快捷键）

- 工具栏新增**「保存」按钮**（primary）：显示未保存项数，如 `保存（3）`；无改动时禁用。
- 快捷键 **Ctrl+S / ⌘+S**；另有 **8 秒自动保存**作安全网（防止误关页面丢改动）。
- 状态标签三态：`未保存 N 项`（黄）→ `保存中…` → `已保存 N 项 · 时:分:秒`（绿）。
- 保存失败时**改动不会被丢弃**（回填到待保存队列）并显示错误条，可重试。
- 有未保存改动时关闭/离开页面会被浏览器拦截提醒；切换路由时尽力落盘。
- ⚠️ 行为变化：**不再 600ms 自动落盘**——这便于"成批复核后再提交"，但意味着**必须点保存**（或等 8s）才会进 `labels.json`。

## 4. 实时指标（页面顶部指标条 = `/api/truth/metrics`，改动后自动刷新）| 指标 | 定义 | 说明 |
|---|---|---|
| 预算进度 | 已标数(含"看不清") / 预算；括号内为已决数(0/1) | 区分"花了预算"与"可用于算指标" |
| 排序准确率 | 已决样本的两两比较（等价 AUC，并列记 0.5） | 选择器的排序能力 |
| Brier | `p_pred = 1-(rank-0.5)/N`（**不依赖标签**的排名先验） | 相对校准代理，越低=真同人越集中于前列 |
| 估计同人总数 / prevalence | `Σ(层内已决同人率 × 层规模)` | 审计层代表其余层 → **无偏外推** |
| 同预算命中 vs 随机期望 | 本方案 50 条实际命中数 vs `50×prevalence` | 比值 = **效率倍数**（核心卖点） |
| relay v5 精度 / 召回 | 仅已决样本内 | 固定误接下 relay v5 的表现 |

⚠️ 外推需要 **三层都有判定**才生效；只判 `topk` 时 `prevalence`/效率显示 `—`，
**绝不用高收益层的比率冒充全池**。审计层若非随机则外推失效。
