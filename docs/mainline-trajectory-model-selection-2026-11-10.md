# 轨迹预测的模型选型：结构、数据容量与取舍

日期：2026-11-10 ｜ 回答：时序驱动 + 身份 + 镜头，用哪个模型结构合适

---

## 0. 结论

**不要用端到端序列网络。用「三模式 IMM 时序层 + 身份先验层 + 镜头约束层 + 相对时间门控 α(Δ) + 绝对时刻在场段 occ(τ)」的分层条件模型。**

理由三条，全部有本项目实测支撑：

1. **数据容量只够"记忆型"模型，不够"学习型"模型**：具名身份 ~30 个、身份×机位 31 组、长轨（≥40 帧）414 条。这个量级下，参数化模型的参数/样本比会失控。
2. **本项目已经试过一次 BERT 级序列模型（`IntentBERT`），落在"能跑但极不稳定、条件化无增益"的边界**——3 个 seed 里 1 个崩溃，加社交邻域/行为条件化全部无系统增益。
3. **运动状态是一个极简的三状态粘滞链**（实测转移矩阵：静止→静止 0.971、快走→快走 0.900），用一个 3×3 矩阵就能完整刻画"时序驱动"，不需要网络去学。
4. **位置层不要压缩、也不要收缩**（本轮实测，§7.6）：31 个桶的 96 维分布要 K=16 才到 90% 能量，混合模型 K=20 才追平直方图（53.3% vs 51.6%）却多花 2.8 倍参数；向群体收缩是**单调有害**的（κ 越大越差）。位置先验就用 **12×8 直方图**。

"时序整体驱动"在这个结构里的数学形式，就是**门控函数 α(Δ)**——短时信运动、长时信身份目的地。它有三个可直接从数据估的参数，而不是要训练几十万权重。

## 1. 数据容量：这是决定性约束

| 量 | 实测 | 含义 |
|---|---:|---|
| 具名身份 | **~30** | 学不出有意义的 identity embedding |
| 身份×机位 组（train+test 都有） | **31** | 条件先验的样本单元只有 31 个 |
| 轨总数（8 段） | 1,278 | |
| **长轨（≥40 帧）** | **414** | 真正能做序列建模的样本上限 |
| 轨长中位 | train **11–20 帧**（4–8 s）、test 15–92 帧 | 轨极碎 |
| 总框点 | 188,700 | 但同轨相邻帧高度自相关，有效独立样本远小于此 |
| 采样率 | train **2.5 fps**、test **5 fps** | 时序最小步长 0.2–0.4 s |
| 状态切换频率 | 平均每条轨 **11.3 次**（轨中位仅 11–20 帧） | **检测噪声主导状态序列** |

最后一行很重要：一条中位 11 帧的轨上发生 11 次状态切换，说明**逐帧状态序列被检测断续严重污染**。这进一步否掉了"用序列模型去学状态转移"——噪声太强，必须先过滤波。

## 2. 已有反例：`IntentBERT`（本项目亲自跑过）

`tools/intent_model.py`，d_model=256 / 4 层 / 4 头，**约 3.1M 参数**；数据 train 6,690 / val 1,079 / test 1,294（滑窗切分，`L_in=12, win_stride=2`）。做 5 类运动意图分类。

| 模型 | test acc | macro-F1 |
|---|---|---|
| base（3 seed） | 0.6847 / 0.6808 / **0.6917** | 0.4636 / 0.4859 / **0.3773** |
| + 社交邻域 | 0.6406 / 0.6955 / 0.6855 | 0.4644 / 0.4611 / 0.4768 |
| + 行为条件化 | 0.6793 / 0.6669 / 0.6770 | 0.4727 / 0.4667 / 0.4554 |
| + 两者 | 0.6631 / **0.6986** / 0.6971 | 0.4547 / 0.4771 / 0.4511 |

**读法**（报告原文口径）：`s44` 是**崩溃 run**（best_ep=3、backward F1 0.03）；剔除它之后，三个配置 acc 与 mF1 **均 ≤ base**，**无系统增益**。

- **参数/样本比 = 3.1M / 6,690 ≈ 460 : 1**。经验上深度模型要稳定需要 100–1000 : 1，但分母要有**百万级独立样本**；这里独立样本数远低于 6,690（滑窗相邻样本强相关，实际约 400 条轨级别）。
- 症状完全吻合：**seed 间波动巨大**（mF1 0.377→0.486，相对差 26%），一个 seed 直接崩。
- 结论：**这个项目的数据量，正处于"序列网络能跑但不可靠"的边界上。**

现在还做位置回归（比 5 类分类更难、更细），样本还更少（414 条长轨）——**用同类结构必然更差。**

## 3. 推荐结构

不是单一网络，是**四层、一个门控**。核心原则：**时序是唯一的状态载体；身份与镜头是条件参数，不是序列 token。**

```
 观测 (p_t, v_t, 可选 id)
        │
        ▼
 ┌──────────────────────────────────────────┐
 │ ① 时序层：3 模式 IMM                      │
 │   模式 = 静止 / 慢走 / 快走               │
 │   转移矩阵（已实测）：                     │
 │        静止  慢走  快走                    │
 │   静止 .971  .028  .001                   │
 │   慢走 .233  .718  .049                   │
 │   快走 .003  .097  .900                   │
 │   每模式一套匀速模型 + 过程噪声            │
 │   输出：p̂_motion(Δ)、Σ_motion(Δ)         │
 └──────────────────────────────────────────┘
        │
        ├──── ③ 门控 α(Δ)：α = Δ^k / (Δ^k + τ^k)
        │      τ 按状态取（静止 τ 大、快走 τ 小）
        │      等价于「短时信运动、长时信目的地」
        ▼
 ┌──────────────────────────────────────────┐
│ ② 先验层：身份条件（目的地）               │
│   P(区域 | id, cam) = 12×8 直方图          │
│   驻留段时长分布（他能消失多久）            │
│   在场段 occ(τ|id,cam)（他什么时候在）      │
│   冷启动：id 未知 → 用 (cam) 群体先验 + 标低置信 │
 └──────────────────────────────────────────┘
        │
        ▼
 ┌──────────────────────────────────────────┐
 │ ④ 约束层：镜头几何                        │
 │   可见掩膜（人不能穿墙、不能贴在画面外）    │
 │   透视尺度（框高 ~ f(y)，远处像素速度小）   │
 │   跨机位：门户图（不共视机位对只能经门）    │
 └──────────────────────────────────────────┘
        │
        ▼
  输出：位置**区域分布** + 置信椭圆（不是单点）
```

### 为什么这样切

| 你的要求 | 落在这个结构的哪一层 | 参数量 |
|---|---|---:|
| **时序整体驱动** | ① IMM 状态演化 + ③ 门控 α(Δ) | 3×3 矩阵 + 3 组协方差 ≈ **30 个数** |
| **身份特征** | ② 先验层条件（不是输入 embedding） | 31 组 × 96 格 ≈ **3,000 个数** |
| **镜头特征** | ④ 掩膜 + 尺度曲线 + 门户图 | 每机位十几条曲线 ≈ **百级** |
| **绝对时间** | ② 的 `occ(τ\|i,c)`：在场段，不是位置曲线 | 48 桶 × M 段 ≈ **百级** |

**总量 < 5,000 个数，全部由计数/矩估计直接得到，不需要梯度、不需要 GPU、可逐条审计、可增量更新。**

这恰好满足"不重训、用历史素材不断迭代"——新数据进来直接累加计数，无灾难性遗忘问题。

### 三个已验证的关键点都落在这个结构里

- 静态 top-1 命中 **51.6%**（群体 17.2%）→ ② 先验层
- 真正在走的人 Δ≥15 s 先验胜出、Δ=60 s 误差 0.049 vs 原地 0.137 → ③ 门控在长 Δ 时把权重交给 ②
- 88.8% 静止、静止→静止 0.971 → ① IMM 的静止模式本来就该赢

## 4. 三个替代方案与取舍

### A. 区域级 Markov 链（比推荐方案更粗）
把画面切 12×8 = 96 格，学 `P(r_{t+1} | r_t, id, cam)`。
- **优点**：极简，转移矩阵直接数出来；天然输出"下一步去哪个区域"。
- **缺点**：96×96×31 太稀疏，必须先把区域聚成 8–12 个语义区（工位区/门口/走廊）；精度只到区域级。
- **适用**：如果需求是"预测他会不会经过某处"（比如门禁、工位），这个就够，不必上连续位置。

### B. 轻量条件化 MDN（混合密度网络）
`p(p_{t+Δ}) = Σ_k π_k(id,cam) · N(μ_k, Σ_k)`，加身份 embedding（30×16）+ 镜头 embedding（6×8），参数约 **5 万**。
- **优点**：能给出真正的多峰分布；比非参数平滑。
- **缺点**：需要 **≥ 3 万个独立片段**才能稳住；当前只有 ~400 条长轨，**差两个数量级**。
- **触发条件**：数据扩到 ≥5 天、≥100 个身份、≥10 万条独立轨时再上（届时可用推荐方案的输出做残差学习，而不是从头学）。

### C. 端到端 Transformer / LSTM
**明确否掉。** 理由见 §2：本项目已有同等规模的先例，处于不稳定边界，且条件化无增益。位置回归比分类更难，样本更少。

## 5. 什么时候该换神经网络（量化门槛）

| 条件 | 当前 | 门槛 | 说明 |
|---|---:|---:|---|
| 独立身份数 | ~30 | **≥ 100** | 否则 identity embedding 学不出结构 |
| 长轨（≥40 帧） | 414 | **≥ 30,000** | 参数/样本比才能压到 100:1 以下 |
| 覆盖天数 | 1 | **≥ 5** | 才能区分"习惯"与"当天偶然" |

满足两条以上，才值得用 B（MDN）；三条都满足且需要端到端优化时才考虑 C。

## 6. 下一步（最小实验，不需要新数据）

在写任何模块之前，先用现有 31 组数据把**门控函数 α(Δ)** 的形状拟合出来：

- 已有实测点（fast 层）：Δ=5/15/30/60/120 s 上，运动外推与身份先验的误差分别是
  `0.239/0.673/1.194/2.560/5.350`（匀速）与 `0.205/0.156/0.126/0.049/0.056`（先验）
- 反推交叉点：**Δ≈11 s 时两者相等**，之后先验单调胜出 → 支持 sigmoid/logistic 型门控，而不是线性混合
- 需要补的：把 `slow` 层也算进去，得到三条 α(Δ) 曲线（静止/慢走/快走各一条）

估完 α(Δ)，第 3 节的 ③ 层就是**确定的形式而非待调的超参**，整个模型只剩 ①②④ 三层要落地。

**这一步纯分析、无新数据、约一轮工作量。** 做完再决定要不要写模块。

## 7. 按你的形式化重写：条件混合模型 + 层次收缩

你的表述是：**一个持续条件（时序）+ 两个 tag（cam id、person id）+ 训练内容是轨迹**，目标是"某人在某时间某镜头下的轨迹预测"，且同一模型兼作行为预测。

这比我 §3 的四层描述更准确，我按这个重写，并补一件关键的事实。

### 7.1 决定实现方式的事实：桶样本量极端长尾

48 个（身份 × 机位）桶，train 点数为样本量：

| 统计 | 值 |
|---|---:|
| 桶数 | 48 |
| 中位 | **108 点** |
| p10 | **7 点** |
| **< 200 点** | **25 / 48（52%）** |
| **< 1000 点** | **34 / 48（71%）** |
| 样本集中度 | 最大 5 个桶占 **57%**，最大 10 个占 **85%** |

极端值：`female3@305` **12,837 点** vs `female3@318` **6 点**。

**这个分布决定了：两个 tag 不能用来训练共享 embedding，也不能让每个桶独立估参数。**

- 完全独立（每桶一套参数）：**52% 的桶样本 < 200，估不出 96 格直方图**，估计方差爆炸。
- 完全合并（不分桶）：丢掉最强信号——身份先验 top-1 命中 **51.6%** vs 群体 **17.2%**（3×）。
- **唯一可行：部分池化（partial pooling）**——小桶向群体收缩，大桶用自己。

这不是实现偏好，是数据分布逼出来的。

### 7.2 形式化

```
输入   h : 轨迹历史 (t−T … t)
       Δ : 预测步长（相对时间）
       c : camera id  （tag 1）
       i : person id  （tag 2）
       τ : 绝对时刻，画面 OSD 上的墙钟时间（跨天可比）

输出   p(y, present | h, Δ, c, i, τ)
       = occ(τ | i, c)                              ← 时间支：τ 的唯一入口
       × Σ_{k=1..K} π_k(i, c) · N(y ; μ_k(h,Δ), Σ_k(h,Δ))   ← 空间支：不含 τ
```

三段职责分离，这是整个设计的关键：

| 成分 | 由什么决定 | 参数 | 为什么这样切 |
|---|---|---|---|
| `μ_k, Σ_k`（**运动基元**） | 只由 `h, Δ` 决定 | IMM 的 ~30 个数，**全桶共享** | 运动学与身份无关，共享能把数据利用率最大化 |
| `π_k`（**混合权重**） | `(i, c)` 两个 tag | 48 桶 × K，**K=3 时 144 个数** | 身份/镜头只影响"更倾向哪种运动基元"，不影响基元本身 |
| `occ(τ \| i, c)`（**在场强度**） | `(τ, i, c)` | 48 桶 × M 段 × 3，**M=3 时 432 个数** | 绝对时间只影响"在不在"，见 §7.4 |

**参数量约 600 个数**（运动 30 + 混合权重 144 + 在场段 432 + 收缩 2 + 门控 3）。

**⚠️ 但「混合模型更省」这个说法在位置分布维度上已被实测否证**——见 §7.6 的验证结果：要表达 31 个桶的位置分布，秩 K 需要 16–20，参数反而比直方图多 2.8 倍。这个 600 个数的账只在**运动基元**这一层成立（运动学确实只有几种模式）；位置层不成立。

### 7.3 两个 tag 怎么进模型（收缩估计）

```
π̂_k(i,c) = λ(i,c) · π̂_k^MLE(i,c)  +  (1 − λ(i,c)) · π̂_k^group(c)

λ(i,c) = n(i,c) / ( n(i,c) + κ )
```

- `n` 是该桶样本量，`κ` 是收缩强度（一个标量，用经验贝叶斯矩估计或留一验证定）
- `female3@305`（n=12,837）→ λ≈0.98，几乎完全用自己
- `female3@318`（n=6）→ λ≈0.03，几乎完全用群体
- 12,837 : 6 的极端差异被 λ 自动吸收，**不需要人工设阈值**

**⚠️ 这个收缩已被实测否证（在位置分布维度）**：κ 从 0 扫到 10000，命中率**单调下降** 66.4% → 27.8%，没有最优点（§7.6）。原因是**群体位置分布对个体的预测力几乎为零**——群体先验 top-1 只有 10.1%，在小桶上是 **0.1%**。位置偏好是个体特异的（同身份跨时段 0.971，跨身份 0.000），**群体均值不是可借的结构**。

所以「小桶向群体收缩」这条不成立。冷启动只能靠外观 + 时间，不能假装有位置先验。

至于**运动基元的 `π_k` 是否该收缩**，是另一个问题（收缩目标是「该机位一般人怎么动」，与「位置在哪」不同），本轮**没有测**，不能据位置分布的负结果反推它。但收缩的前提「群体结构可借」已经被证伪一次，落地前必须先验证。

### 7.4 绝对时间 τ：不是「弱」，是「作用域不同」

你确认了：这里的「时间」指**画面 OSD 上的墙钟时刻**（08:35、14:22），跨天可比。

我上一版把时间拆成 `Δ` 与 `τ` 两轴是对的，但**把 `τ` 判成"可省略"是错的**。

#### 错在哪

我当时只有一条证据：同 (身份, 机位) 在上午 08:03–10:28 学、下午 13:45–15:18 测，位置分布余弦 **0.971**。这测的是**「在哪」**，我却外推成「`τ` 整体没用」——属于**把"未测"当成"无效应"**，是本项目反复踩的同一类错误（同族：把未标注当负例）。

#### 补测（`tmp/mainline/tau_probe.py`）：先把可识别性说清楚

用 `osd_start + ss` 把段内帧号还原成墙钟时刻，四件事。

**(a) `τ` 对个体的效应在这份数据上不可估。** train 覆盖 08:03–10:28（145 分钟），test 覆盖 13:45–15:18（93 分钟），**时钟重叠 = 0 分钟**。要判 `τ` 对个体「在不在」的效应，需要「同一时钟窗口、不同段」的重复观测：

| 窗口 W | 有重复观测的组数 |
|---:|---:|
| 30 分钟 | **0 / 32** |
| 60 分钟 | **0 / 32** |
| 120 分钟 | **0 / 32** |
| 240 分钟 | **0 / 32** |

`τ` 与 `split` 完全共线。**不能因此说 `τ` 没用，只能说这份数据测不了。**

**(b) `τ` 对「候选池多大」的杠杆是实测的，而且极强。** 用全部检测框（不需要身份真值），按 5 分钟绝对时刻格统计每机位平均人数：

| 机位 | 人数曲线（5 分钟格） | 动态范围 max/min |
|---|---|---:|
| **305**（工位） | 09:25–10:25 恒定 **7.2–10.3**；14:30–14:40 8.2–9.6 | **1.4×** |
| **323** | 08:40 **0.3** → 09:00 **4.4**（峰）→ 09:15 **1.2** | **13.5×** |
| **318** | 08:20 **0.1** → 09:20 **6.6**（上班陆续到） | **87.9×** |
| **320** | 08:00–08:40 **全 0** → 15:00–15:15 **1.9–3.5** | **3473×** |

同一机位、不同时刻，「有多少人可能被误认成他」差 **1.4× 到 3473×**；跨机位差 3 个数量级。这是 `τ` 的直接工程收益：**它决定候选池大小，从而决定匹配难度与误合并风险**。

**(c) `τ` 的形态是「台阶」不是「曲线」。** 318 上午是平滑爬升（08:20→09:20 从 0.1 到 6.6，像陆续到岗），下午是**从 0.2 突跳到 4.1（14:25→14:30）**（像散会）。两种形态不同 → 支持**驻留段 / 事件台阶**模型，不支持「日内正弦曲线」。这与 §4 已有结论一致（分钟占用率自相关 0.90–0.97、`male1@305` 连续在场 38 分钟）。

**(d) `τ` 对位置形状确实弱**：0.971 那一项保留，不受影响。

#### 修正后的定位

| 问题 | 谁决定 | 实测 | `τ` 的角色 |
|---|---|---|---|
| **在哪**（位置分布形状） | `h, Δ, c, i` | 上午→下午 **0.971** | **不进**，可省 |
| **在不在**（候选池大小 / 群体在场） | `τ, c` | **1.4×–3473×** | **唯一入口** |
| 个体在不在 | `τ, c, i` | **0/32 可识别** | 形式上留位，参数等跨天 |

所以 `Δ` 与 `τ` 彻底解耦成两支：

- **时间支** `occ(τ|i,c)` 回答「**该不该找、什么时候找**」
- **空间支** `Σ π_k N(μ_k,Σ_k)` 回答「**去哪找**」

`occ` 用**驻留段集合** `{(start_m, end_m, p_m)}`（M 段）参数化，而不是 24×60 的分钟曲线；并对 `π` 做同样的收缩：`occ` 向该机位的群体曲线 `occ(τ|c)` 收缩。这样 `τ` 不参与空间建模，参数量不随时刻分箱爆炸。

#### 一个必须避开的坑

`occ` 的估计**必须用同一窗口长度归一**。60 分钟的 train 段与 15 分钟的 test 段，在场率天然不可比（路过型身份在长窗口里命中率天然更高）。这是 `sti_time_probe` 里踩过的分母问题，做 `occ` 时不要再犯。

#### 需要什么数据才能把 `occ(τ|i,c)` 估出来

| 需求 | 当前 | 门槛 |
|---|---|---|
| 同一 (身份, 机位) 在同一天内跨 ≥2 个时段有观测 | **0 / 32** | ≥ 20 组 |
| 每天覆盖时长 | 每机位 1 小时（train）/ 15 分钟（test） | ≥ 4 小时（覆盖上午+下午） |
| 跨天重复（区分「习惯」与「当天偶然」） | **1 天** | ≥ 5 天 |

这正是你说的「数天到数十天」——`occ` 是**唯一必须等跨天数据的模块**，空间支不受影响。

### 7.5 轨迹预测与行为预测共享同一套参数

同一组 `π_k(i,c)` 下，换输出头即可：

| 输出 | 形式 | 用途 |
|---|---|---|
| **轨迹** | 从 `Σ π_k N(μ_k, Σ_k)` 采样 / 取分位数 → 位置区域 + 置信椭圆 | 跨时段重连的搜索范围、遮挡恢复 |
| **行为（动作）** | 对 `k` 与 `Δ` 离散化：`argmax_k` × (停留 / 移动) × (方向象限) × (区域转移) | 行为预测、异常检测（偏离该身份常规基元） |
| **行为（作息）** | `occ(τ\|i,c)` 的驻留段：几点来、待多久、什么时候走 | 该不该找、什么时候找、遮挡时该等多久 |

**行为不需要独立的模型，它是「轨迹分布 + 在场段」的离散化。** 前两行来自空间支，第三行来自时间支。这也解释了项目里 `IntentBERT` 为什么加条件化没增益——它用一个 3.1M 参数的网络去学"从序列推行为"，而行为本来就蕴含在同一套 `π_k` 里，信息是冗余的（`docs/intent-v2-study.md` §四.2 已得出同样解释）。

### 7.6 验证结果：位置分布不能压缩，也不能收缩

§7.2 的条件混合模型已实测（`tmp/mainline/pos_model_compare.py`，31 个可评估桶，train 上午 → test 下午）。
**纪律：K 与 κ 只在 train 内部（前半天 → 后半天）选，test 只报一次。**

#### 先看能不能压：秩诊断

把 31 个桶的 96 维分布堆成矩阵做 SVD：

| K | 1 | 2 | 4 | 8 | 12 | **16** | **19** |
|---|---:|---:|---:|---:|---:|---:|---:|
| 累计能量 | 9.9% | 19.3% | 37.6% | 59.3% | 77.4% | **90%** | **95%** |

**到 90% 要 K=16，95% 要 K=19——而桶一共只有 31 个。** 压缩比只有 2×，位置分布**不是低秩的**。

#### 再实测：混合 vs 直方图

| 模型 | CV top-1 | **test top-1** | test top-3 | 参数量 |
|---|---:|---:|---:|---:|
| **12×8 直方图** | 66.4% | **51.6%** | **69.2%** | **2,976** |
| 混合 K=10（CV 初选） | 58.0% | 48.9% | 64.0% | 4,150 |
| **混合 K=20（CV 选中）** | **67.8%** | **53.3%** | 67.9% | **8,300** |
| 群体模板（不用身份） | — | 10.1% | 28.2% | 620 |

- K=20 时混合 **53.3% vs 直方图 51.6%**，赢 1.7 点，但**参数是 2.8 倍**（8,300 vs 2,976）。
- K=20 已经接近桶数 31，所谓「压缩」在这里是**扩张**。
- 结论：**12×8 直方图就是以最少参数表达最多信息的方案。位置层不压缩。**

#### 收缩：单调有害

对直方图本身做 `λ·hist_bucket + (1−λ)·hist_group`，`λ = n/(n+κ)`：

| κ | 0 | 10 | 30 | 100 | 300 | 1000 | 3000 | 10000 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| CV top-1 | **66.4%** | 60.3% | 54.6% | 53.0% | 49.4% | 46.1% | 40.1% | 27.8% |

**单调下降，没有最优点。** 贝叶斯直觉里「小桶该向大桶借力」在这里失败，原因是**群体位置分布对个体几乎没有预测力**（群体 top-1 只有 10.1%，小桶上 0.1%）。位置偏好是个体特异的，群体均值不是可借的结构。

#### 真正的结论：决定命中率的是样本量，不是模型

| 桶样本量 `n_train` | 桶数 | 占比 | 直方图 top-1 | 混合 top-1 | 群体 top-1 |
|---|---:|---:|---:|---:|---:|
| **n ≥ 1000** | 14 | 45% | **73.4%** | 73.4% | 14.8% |
| 100 ≤ n < 1000 | 6 | 19% | 32.2% | 33.7% | 17.8% |
| **n < 100** | 11 | 35% | **34.4%** | 38.4% | 0.1% |

**大桶 73.4% vs 小桶 34.4%，差 2.1 倍；而在同一层内，混合与直方图几乎完全相同（73.4% vs 73.4%）。**

所以 `C/229` 的下一步不在模型结构，在**每个 (身份, 机位) 的样本量**。而 51.6% 这个数字里，**35% 的桶是小桶**，它们贡献的是 34.4%——这部分是「没数据」，不是「模型不行」。

**行动含义**：位置先验就用 12×8 直方图（不压缩、不收缩）；要提升它，唯一有效路径是**喂更多同身份同机位的素材**——这正是改用全量视频素材的直接依据。

### 7.7 仍然待验证的一件

`occ(τ|i,c)` 的可估性。当前 0/32 组可识别（§7.4a），要补每机位每天 ≥4 小时覆盖（含上午+下午）、≥5 天、每天 20–30 人的身份锚点。

在此之前，`occ` 只能用群体曲线 `occ(τ|c)`——这条已经能用，见 §7.4b 的 1.4×–3473×。
