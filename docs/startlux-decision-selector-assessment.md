# StartLux-Decision 能否重构身份选择器？——可行性评估（2026-10-17）

> 对象：https://github.com/StartLuxLabs/StartLux-Decision
> 对照：`tools/selector.py`（IdentitySelector v2，multi8 子原型 + per-cam 阈值 + margin 档）
> 结论口径：本机实测环境（AMD RX 5700 XT 8GB / 无 CUDA）、项目现有资产（125 簇 / 412 子原型 / 768d cradio 向量）

---

## 0. 结论（先行）

**1）不能替代身份选择器。** 两者的输入空间不相交：IdentitySelector 的输入是 768 维 ReID 向量，
StartLux 的输入是文本 / JSON / 图像，没有向量输入通道。所谓"用 StartLux 重构选择器"在接口层不成立。

**2）唯一有技术意义的接点是"第二级仲裁 / 开放集拒识"，不是第一级判别。**
StartLux 的 `none_probability`（"以上都不是"）与选择器的 `unknown` 语义同构，
`choice` 列表与"top-k 候选簇"同构——但这是**新增一层**，不是重构。

**3）不建议现在投入。** 三条硬约束同时成立：
   - 权重 **CC BY-NC 4.0**（仅非商用），代码 Apache-2.0；
   - 本机 **无 CUDA**（5700 XT），vLLM 后端不可用，只能走 llama.cpp + GGUF（Instant 还需非因果补丁）；
   - 无任何"人体外观同一性"基准证据——Decision Index 衡量的是决策/推理题，不是 ReID。

**4）可立即借鉴的不是模型，是它的**判定结构**：一次前向出概率 → 低置信才多想 → 显式 none 类。
   把这套"校准好的弃权"用轻量判别头（MLP on [sim, margin, cam, 质量]）实现，成本近似为零，
   比引入 0.8B–27B 语言模型更符合本项目的离线批处理+成本纪律。

## 1. 对象能力（事实）

| 项 | 内容 |
|---|---|
| 定位 | 开放"决策模型"家族：给状态（文本/JSON/图像）+ 若干带类型的问题，一次前向输出**每个选项的概率** |
| 问题类型 | `choice`（选项列表，≤26）、`noul`（是/否）、`score`（2–10 级量表） |
| 规格 | 0.8B / 2B / 4B / 9B / 27B（Instant 与 AutoThink 两版），v1 另有 35B-A3B MoE |
| 决策质量 | Decision Index 0.3：0.8B **53.75** / 2B 59.14 / 4B 67.88 / 9B 69.96 / 27B 72.83（AutoThink 73.37） |
| 延迟 | H200 + vLLM、单请求在飞：Instant 中位 **25–52 ms**；AutoThink 有把握时 38–59 ms，不确定时追加思考 |
| 接口 | `POST /v1/systemone`（兼容 System One），`/v1/decisions` 同构；OpenAI 客户端不适用 |
| 后端 | vLLM 0.31（需 CUDA）、llama.cpp（GGUF，视觉需 mmproj）、MLX（Apple）、transformers（参考实现） |
| 许可 | 代码 Apache-2.0；**权重 CC BY-NC 4.0，商用需单独授权** |
| 拒识 | `none_probability`：51,506 题实测，阈 0.2 时抓到 66.3% 的"无正确选项"题，误报 2.2%（AUROC 0.920） |

## 2. 为什么不匹配（逐条）

### 2.1 输入模态
```
现有：vec[768] ──► IdentitySelector ──► (cluster_id, sim)   # 1 ms 级，纯 numpy
设想：vec[768] ──► ???                # StartLux 无向量入口
```
StartLux 能读的是裁剪图（base64，≤8 张/请求，1024×1024 折 1024 token）。要喂它就必须先把向量"翻译"成图，
等于把已经算好的 ReID 证据丢掉，改让一个通用决策模型看图认人。

### 2.2 判别力没有证据支撑，且有理由怀疑
- 现有选择器在 test 348 轨上的实测：默认档 cov 0.391 / same 0.897 / coll 0.032 / 跨段保持 0.972；
  精确档 cov 0.230 / same 0.988 / 跨段 1.000。这是**任务内校准过的度量学习**结果。
- StartLux 的训练目标是决策/推理（棋类、游戏、视频事件判读），**没有人脸/人体同一性基准**。
  通用 VLM 在低分辨率监控裁剪上的同人判别通常显著弱于专用 ReID 嵌入——这是需要实测否证的假设，
  而不是可以先验接受的结论。

### 2.3 选项规模
125 个簇 > 26 选项上限，会触发 knock-out：5 组 × 25 + 1 轮决赛 = **6 次前向/轨**。
按 H200 的 25–52 ms 折算约 150–310 ms/轨；本机 5700 XT 走 llama.cpp Vulkan，量级预计秒级/次
（未实测，不作为结论）。348 轨离线尚可（十几分钟），但**实时门控不可行**。

### 2.4 本机硬件
- `nvidia-smi` 不存在；显卡为 **AMD Radeon RX 5700 XT（8GB）**。
- vLLM 需 CUDA/ROCm，gfx1010 不在 ROCm 官方支持内 → 实际路径只有 **llama.cpp + Vulkan + GGUF**。
- 8GB 显存：0.8B/2B/4B 的 Q4–Q8 可跑，9B/27B 不现实（27B 即使 Q4 也 ~15GB）。
- Instant 版 GGUF 依赖仓库自带 llama.cpp 补丁（`qwen35.attention.causal=false`），
  即"必须用他们 patch 过的二进制"，运维面比现在的 numpy 库大一个量级。

### 2.5 数据合规
官方提供 `bamboonode.dev` 免费 27B 端点（无需 GPU 即可试）。但本项目素材是**真实人员监控画面**，
把裁剪图外发第三方端点做 PoC 不可接受；PoC 必须本地自托管或使用去标识素材。

## 3. 三条可选路径

| 路径 | 内容 | 收益 | 代价 | 判断 |
|---|---|---|---|---|
| **A. 直接替换选择器** | 用图像 + choice 选簇 | 无 | 接口不成立、精度无证据、许可 NC、硬件不足 | ❌ 否决 |
| **B. 二级仲裁（shadow）** | 只在 `0.35 ≤ best < thr` 或 `margin < δ` 的疑难带，取 top-5 簇裁剪图 + 查询图，问 `choice` + `none_check` | 可能把"拒识带"里的一部分转成可用判定，抬高 cov 而不掉 same | 6→1 次前向（候选只有 5 个，1 次即可）；需新依赖、新许可、新运维 | 🟡 值得一次受控实验，不作为主线 |
| **C. 借鉴判定结构，不引入模型** | 在现有分数上训一个弃权头：`P(accept | sim, margin, cam, 轨迹质量, 嵌入一致性)`，用 `none` 类语义做校准 | 同覆盖率下提精度，或同精度下提覆盖；成本 ~0；可解释、可回归 | 需要标注的"该拒识"样本（现有 348 轨 + 跨段对可构造） | ✅ 推荐 |

### 关于 C 的具体形态
现在的弃权是**两个超参**（`thr_unknown_per_cam` + `margin_prec_per_cam`），靠分位校准，
本质是"一维阈值 + 一维间隔"的直角决策边界。StartLux 的做法给出两点启发：
1. **单次前向即出全选项分布** → 等价于把 `sims_all` 的 K 维分数直接送进一个小分类/校准器（逻辑回归或 2 层 MLP）；
2. **显式 none 类 + 可调的 gate** → 训练时把"unknown"作为一个真实类别，用保留率语义校准，而不是拍阈值。
这两点都不需要语言模型。

## 4. 若要跑 B，最小实验设计（先定门槛，再看结果）

**数据**：test 348 轨（跨时段），复用 `selector_v2.npz` 的 `sims_all` 取 top-5 候选；
每条轨取样 3 帧裁剪（已有 `output_crosscam` 检测资产），构造"查询图 + 5 候选图 + 簇描述"的 choice 题。

**对照（同覆盖率比较，这是唯一公平口径）**：
| 基线 | cov | same | coll |
|---|---|---|---|
| 默认档 | 0.391 | 0.897 | 0.032 |
| 覆盖档 | 0.621 | 0.880 | 0.034 |
| 精确档（margin=prec） | 0.230 | **0.988** | 0.039 |

**通过条件（三条全部满足才允许进入影子链路）**：
1. 在 cov ≈ 0.62 处 same ≥ 0.88 + 2pp，且 coll 不上升超过 0.5pp；
2. 在 cov ≈ 0.23 处不得低于 0.988（精确档是当前最强前沿，仲裁层不能把它拉低）；
3. 单轨端到端仲裁延迟 ≤ 300 ms（本地 llama.cpp，4B Q4；达不到则只能离线回填，不能进在线路径）。

**样本量**：疑难带实际样本有限（按 cov 差额估算约 100–150 轨），需 bootstrap 置信区间；
不足则扩到跨段 107 对做配对比较。**不得用 test 调 gate**（沿用项目既有纪律）。

**失败即弃**：若 same 增益 < 2pp 或仅在高 cov 段有效，说明"疑难带"的瓶颈是嵌入质量而非判别器容量，
结论应回到换嵌入（DINOv3 / C-RADIOv4 已在本机验证可用）而不是叠语言模型。

---

## 5. 一句话建议

**不要把 StartLux 当作选择器；把它当作一面镜子。** 它证明了"概率化拒识 + 不确定才多想"这条路线值钱，
但执行层用 20 行 numpy/ sklearn 就能在本项目落地（路径 C），而不必引入一个 8GB 显存吃不下的
非商用权重家族。若一定要试，只做路径 B 的影子实验，并预先写好"不达标就删"的判定线。
