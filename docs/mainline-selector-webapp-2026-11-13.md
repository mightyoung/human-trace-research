# 身份选择器接入控制台（2026-11-13）

> 结论先行：机制接上了、口径立住了、**但包内数字不支持「池有增益」**。那个结论的证据在 8 段
> （56.4 → 68.2 → 79.3），不在这个 10 分钟包。别把这里的数字当精度报。

## 1 接的是什么

| 层 | 之前 | 现在 |
|---|---|---|
| 算法 | `tools/pose_match.py` + `tmp/full/exp_selector_runtime.py`（离线脚本，8 段数据） | `webapp/backend/selector.py`（服务，10 min 包） |
| 入口 | 命令行 | `#/selector` 页签 + 8 个 `/api/selector/*` |
| 状态 | 无（每次重跑） | `data/reid/selector_pool.json`（池 + 参数同文件，便于复现） |

参数沿用已验证值，不引入新超参：**σ=0.6**（形态加权带宽）、**池 top-3**（不是池均值）、
**池容量 8（FIFO）**、**质量门框高 ≥60 px**、**τ=0.80**。

## 2 四条口径（缺一条数字就不可信）

1. **查询一律留一**。查询轨从模板与池里都剔除。不剔的话查询轨就在自己身份的模板里，
   top-1 恒等于自己 —— 这是最容易造出「100% 准确」的假象。
2. **候选只含还有其它模板的身份**。单轨实体留一后模板为空，它不进候选；
   否则「没有模板」会被读成「不是这个人」。本包 411 个实体里 **325 个是单轨**。
3. **库与池按机位分层**。跨机位外观在实测里是随机水平（6 种编码/对齐配置 AUC 0.450–0.622，
   区间全跨 0.5），`scope=all` 只作对照，不作默认。
4. **人脸触发源 = 人工确认过的人脸卡**（`faces_labels.json` 里 verdict 过的 `g####`），
   不是自动人脸识别。识别全对时的收益是 79.3% 那组数字；现实折损来自覆盖
   （本包 45 张卡 / 539 轨 = 8.4%）与误识别，**两者本页都不估**。

## 3 包内自评（可复现）

`GET /api/selector/eval?mode={real|oracle}&split={loo|half}`

| 口径 | n | 仅库 S0 | 库+池 S1 | 仅池 S2 |
|---|---:|---:|---:|---|
| 留一 · 真实池 | 216 | **56.0%** | 56.0% | 覆盖 0%（池空）→ 写 4 条后 **25.5% / 命中 38.2%** |
| 留一 · 池上限 | 216 | **56.0%** | 56.0% | 覆盖 96.8% / 命中 47.4% |
| 前后半 · 真实池 | 22 | 90.9% | 90.9% | 覆盖 0% |
| 前后半 · 池上限 | 22 | 90.9% | 90.9% | 覆盖 72.7% / 命中 81.2% |

（「写 4 条」= 手工把 318-E003 的 4 条轨锚进池，验证池链路通、且被 55 条查询看见。）

- 「池上限」= 每处理完一条轨就把它写进自己身份的池（触发全对的上限），严格按 `t0` 因果流式处理。
- **S1 在四种口径下都恒等于 S0**：池分从未超过库分。
- `half` 只有 22 条可评：实体极碎，后半段里「前半段出现过同实体」的轨本来就少，且这部分
  是「前后都被聚到一起」的轨 —— 有选择偏差，**不能当作乐观证据**。
- 实体来自聚类输出而不是人工真值 → **包内自证口径**，只做「有池 vs 无池」的相对比较。

## 4 为什么池在这里没有增益（三条，都可查）

1. **这个包是 10 分钟切片，没有跨时段**。8 段的增益来自「上午库 → 下午查询」，
   同一人在那两段之间换了天气/衣着/光照；10 分钟内同一个人基本是同一件衣服，
   池加进来的样本与历史库高度冗余。
2. **实体极碎**：539 轨 / 411 实体 / 325 个单轨实体。可评轨只有 216 条，
   每条查询的候选空间里能与之竞争的身份有很多只有 1 条模板。
3. **库分数本来就很高**（同机位不同人常落在 0.87–0.95），`S1 = max(库, 池)` 几乎轮不到池发言。
   界面上「与次名分差」一行就是给人看这个的：0.991 vs 0.945，分差 0.046。

## 5 四个实测坑（都改了）

| 坑 | 现象 | 处理 |
|---|---|---|
| **tid 不同源** | `/api/track/thumb?cam=305&tid=3` → 404「轨迹不存在」。ReID 库的 `tid` 来自 `2026-10-12` 那批跟踪，渲染用的 `tracks` 是另一版 | 页面**不取缩略图**，只显示文字标识。硬要取就是一堆破图 |
| **并列打分无 tie-break** | S0 在 real/oracle 之间抖 0.4pt（55.6 vs 56.0）—— 纯库打分不该受池影响。根因是候选集来自 `set()`，池一变迭代顺序就变 | `pick()` 与排序统一 `(-score, entity)`。修后两种口径 S0 **严格相等** |
| **池条目显示错实体** | 把 318-E033 的轨锚到 318-E003，界面上仍显示 `318-E033` → 错配被静默掩盖 | 池行区分 `entity`（槽位）与 `track_entity`（轨自身），不一致时黄色标出；`witness` 返回 `mismatch` |
| **小框污染模板** | 318#12 框高 24 px 也能写进池 | 质量门（≥60 px）先拦；要强写需 `force` |

## 6 复现

```bash
# 后端（本地 venv）
cd webapp/backend && python -m uvicorn main:app --host 127.0.0.1 --port 8010
# 前端（★ 必带 --emptyOutDir false，否则 dist/faces 被清空）
cd webapp/frontend && node node_modules/vite/bin/vite.js build --emptyOutDir false
# 自评
curl -s "http://127.0.0.1:8010/api/selector/eval?mode=oracle&split=loo"
```

页面：`http://127.0.0.1:8010/#/selector`。截图 `webapp/deploy/uicheck_selector/`。

## 7 没做 / 边界

- **自动人脸识别没有接**。要做就得在 1440p 原生上跑 SCRFD+ArcFace（代理片人脸中位 52 px，
  不够），且需要「人脸 → 轨」的实时绑定服务；当前用人工判定过的人脸卡顶替，接口已预留 `src` 字段。
- **没有与 long35 长卷（1202 轨 / 443 身份）联调**。控制台当前加载的 ReID 库是
  `data/reid/store_meta.json`（539 轨，key 前缀 `2026-10-12`，`cradio_gemma2_bridge_v4`），
  与 long35 那套不是同一批跟踪 —— 两者如何对应**未核**（正因为没核过，页面才不取缩略图）。
  要在长卷上验池增益，应回到 8 段脚本口径（`tmp/full/exp_selector_runtime.py`），
  不要在控制台上再造一遍实验。
- **对级 κ（153 条）仍缺**，与本页无关，但同一批审稿人会问。
