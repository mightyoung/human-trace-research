# 运行时选择器：人脸作可信触发器 + 实时全身特征池

**结论：机制成立，但「换衣」这个前提在本数据里没有被证实 —— 真正被证实的机制是「同一人在不同场景/框形态下外观不可比」。**

| τ | S0 仅历史库 覆盖/判对 | **S1 库+池 覆盖/判对** | 变化 |
|---|---|---|---|
| 0.75 | 78% / 80.9% | **88% / 87.4%** | 覆盖 +10，判对 +6.5 |
| **0.80** | **53% / 91.8%** | **73% / 94.0%** | **覆盖 +20，判对 +2.2** |

| 档 | n | S0 判对 | **S1 判对** | 池覆盖 |
|---|---|---|---|---|

## 2. 实验设计（因果）

```
上午段（*_train_*）→ 每「机位×身份」的**历史全身特征库**（轨均值）
下午段（*_test_*） → 按起始帧排序逐条作为**查询**
  对每条查询：
    S0 = cos(查询, 历史库)
    S1 = max(S0, cos(查询, 实时池))   ← 池内取 top-3 平均（多模板）
    S2 = 仅池
  ★ 打分完成后，若该轨**有可用人脸**，才把它的 body 特征写入该身份池（因果）
```

- 池容量 8 条 FIFO；多模板取最像的 3 条均值（不取池均值，否则换场景前的旧样本会稀释新样本）。
- 445 具名轨中 **141 条有可用脸（31.7%）** → 这是「能写入池」的现实上限。
- 查询轨 208 条；历史库 48 个「机位×身份」组。

**口径声明**：人脸「识别到谁」用 GT 代替 → 这是**上限**（假设人脸识别全对）。
「这条轨能不能写入池」用**真实可用脸** → 这部分是现实的。所以现实折损只来自覆盖，不来自误识别。

## 3. 机制核查：不是换衣，是框形态变了

低相似档 53 条里，我逐条查了机位与框高：

| 机位 | 上午库框高中位 | 下午查询框高中位 | 变化 |
|---|---|---|---|
| 305 | 196 px | 184 px | −6% |
| 318 | 160 px | 146 px | −9% |
| **320** | **191 px** | **101 px** | **−47%** |
| 323 | 196 px | 157 px | −20% |

**低相似档 24 条（有同机位库的）里 22 条在 320，全部是 female5。**

看图确认（`tmp/f5/f5b.jpg`）：320 的上午库轨是**站立全身**（走廊），下午查询是**坐姿头肩**（工位）。而同一个人在 318 机位的上午/下午（`tmp/f5/f5.jpg`）**穿的是同一套黑上衣+牛仔裤**，cos 0.91–0.95 —— 衣服没换。

所以：

- **「换衣」假设在本数据里没有证实**：没抓到一个换衣案例（8 段是同一天 09:28 与 14:30）。
- **真正被证实的是「形态/场景域偏移」**：同一个人、同一套衣服，因为**框从整身变成头肩 + 背景从走廊变成工位**，cos 掉到 0.48–0.55。
- 换衣只是这个机制的一个特例：**任何让外观特征漂移、而人脸不漂移的变化**（换衣、坐下/站起、换机位、光照）都会触发同一个需求，而这个需求**用同一套池就能解决**。

这个更正对落地有实际影响：

| 如果原因是换衣 | 如果原因是形态/场景 |
|---|---|
| 池要长期保留历史（换回来还能认） | 池要**按机位 + 框形态分层**，跨形态模板无用 |
| 全局池合理 | 全局池会被污染（实测 all 池比 cam 池差） |

实测支持后者：**cam 池优于 all 池**（见下节），说明模板的价值高度依赖场景一致。

## 6. 局限（写论文必须带）

1. **「人脸识别到谁」用 GT 代替** → 上表是上限。现实折损来自人脸误识别（本数据 31.7% 有可用脸，其中 fake/误检未计入）。
2. **只有 18 个身份可评**（需要「上午在该机位有库 + 下午有查询」），且增益集中在 female5 一人。
3. **8 段是同一天 09:28–14:30**，跨天未验证。换衣需要跨天才能自然出现，**本数据无法验证换衣场景**。
4. 池的写入触发只要求「有可用脸」，没有做「人脸是否真的属于该身份」的校验 → 现实中需要人脸比对的置信度门槛。
5. `320` 那 22 条低相似本质是检测框形态问题，**根因在检测/跟踪层**（整身↔头肩），池只是补救。

## 7. 落地建议

**AnchorPool 的最小实现**
```
key   = (身份, 机位)        # 不跨机位共享，实测 all 池不占优
value = 最近 N 条 body 特征（N=8，FIFO）+ 每条的质量标签
写入  = 人脸比对置信度 ≥ τ_face_accept（且 ≥ 2 帧一致）
查询  = max(历史库 cos, 池内 top-3 均值 cos)
ttl   = 2 h（与之前一致，不做长期记忆）
```

**三条纪律**
1. **绝不回写聚类库**（错样本会随窗口扩散）。
2. **写入要带质量门**（male10 的例子证明一条偏样本就能局部变差）。
3. **池按机位分层**，跨形态的旧模板不参与匹配。

**与聚类层的关系**：两者独立、可叠加。聚类层（+15.29 pt R）解决「离线完整度」，运行时池（+20 pt 覆盖）解决「在线可判率」。若只能先做一个，选聚类层（它的验收标准更硬、证据更全）；运行时池需要先补一个跨天数据来验证换衣。
